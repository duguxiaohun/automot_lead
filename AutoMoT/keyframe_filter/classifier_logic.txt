XML命名规则
AutoMoT/data/lead是lead_data对应的route XML根目录，查找时必须从lead_data/<Scenario>/<run_id>解析(Scenario,Town,route_key)，不能只取数字route。
Scenario取run父目录；run_id先剥末尾MM_DD_HH_MM_SS时间戳，再只在存在时剥尾部_route0；剩下就是route_key。Town12_route15里的route15是key本体，不能剥，也不能要求它带_route0。
XML文件名公式固定：route_key以route_开头时用<Town>_<route_key>.xml，否则用<Town>_route_<route_key>.xml。
例子：
Town03_Rep0_route_001783_route0_... -> data/lead/<Scenario>/Town03_route_001783.xml
Town12_Rep0_1054_0_route0_... -> data/lead/<Scenario>/Town12_route_1054_0.xml
Town06_Rep0_Town06_13_route0_... -> data/lead/<Scenario>/Town06_route_Town06_13.xml
Town12_Rep0_Town12_route15_... -> data/lead/<Scenario>/Town12_route_Town12_route15.xml

道路结构划分
R1. 常规道路/同向可行驶道路
核心行为是车道保持、跟车、同向变道、同向车道内绕障,自车始终不进入对向车道。这一类覆盖单向多车道、双向双车道、环岛、非结构化道路等多种物理形态,但行为函数统一。
包含的场景:ControlLoss、DynamicObjectCrossing、HardBreakRoute、noScenarios 属于纯跟车;Accident、ConstructionObstacle、ParkedObstacle 属于"同向车道内换道绕障再回归";HazardAtSideLane 暂归这一类,但前面提过它的"对向双车道"表述有歧义,建议你核实数据后再确认。
此外还有几个场景的部分片段属于 R1:StaticCutIn 里"自车起步时不在期望车道所以要变道"这一段;InterurbanActorFlow 里"先向左变道"这一段(InterurbanAdvancedActorFlow 是否也有这段前置变道,需要你核实原始数据,如果没有就不挂 R1)。
R2. 双向单车道/借对向车道道路
核心特征是自车方向只有一条车道,前方被占死后必须短暂借用对向车道通过,通过后返回原车道,如果对向车优先或遇红绿灯则停车等待。
包含的场景:AccidentTwoWays、ConstructionObstacleTwoWays、ParkedObstacleTwoWays、HazardAtSideLaneTwoWays、VehicleOpensDoorTwoWays。这五个是"自车主动借道"；VehicleOpensDoorTwoWays 不再挂独立停车道路结构，两侧停车/开门只是把有效可行驶通道压缩成 R2。
InvadingTurn 结构上也挂在 R2 下(同样是双向单车道),但行为方向相反——是对向车占用自车道,自车被动等待、不主动进入对向车道,需要单独标注为被动让行,不要和上面五个的主动借道行为混用。
R3. 高速/匝道/合流道路
核心特征是存在主路、匝道、合流、分流、驶出结构,自车需要根据侧后方车辆和目标车道找时机并线或驶出。
包含的场景:EnterActorFlow/EnterActorFlowV2(自车并入主路)、MergerIntoSlowTraffic/MergerIntoSlowTrafficV2(同类合流)、HighwayCutIn(他车切入自车道,自车减速跟车)、HighwayExit(自车找时机驶出)。
StaticCutIn 如果触发位置在匝道汇入口附近,也应该挂这一类;2026-07-06 全量逐帧 RGB 复核后,当前候选收紧为 R1/R3/R4/R5,不再保留独立停车道路结构。
R4. 信号灯路口
核心特征是红灯停、绿灯行,同时仍需观察冲突车辆、行人、自行车或异常交通行为。
确定包含:RedLightWithoutLeadVehicle、SignalizedJunctionLeftTurn/SignalizedJunctionLeftTurnEnterFlow、SignalizedJunctionRightTurn、OppositeVehicleRunningRedLight。
条件性包含(取决于该路口是否有信号灯,需核实):T_Junction、CrossingBicycleFlow、PedestrianCrossing、VehicleTurningRoute、VehicleTurningRoutePedestrian、InterurbanActorFlow 和 InterurbanAdvancedActorFlow 的路口转弯片段、BlockedIntersection 的路口片段。
R5. 无信号灯路口
核心特征是没有明确灯控,自车需要根据路权、横向车流、对向车流、行人或自行车判断通行时机。
确定包含:NonSignalizedJunctionLeftTurn/NonSignalizedJunctionLeftTurnEnterFlow、NonSignalizedJunctionRightTurn、OppositeVehicleTakingPriority、PriorityAtJunction(原文未写明是否有信号灯,建议核实)、CrossJunctionDefectTrafficLight(按你确认,信号灯失效后按无信号灯路口逻辑处理,但建议保留"信号灯故障"这个独立事件子标记,因为四向都可能来车的不确定性比普通无信号灯路口更高)。
条件性包含:T_Junction、PedestrianCrossing、VehicleTurningRoute、VehicleTurningRoutePedestrian、InterurbanActorFlow/InterurbanAdvancedActorFlow 的路口片段、BlockedIntersection 的路口片段——这些和 R4 是互斥的同一批场景,具体挂哪边取决于该路口实际有没有信号灯。
停车/开门/遮挡并入口径
不再设置独立停车道路结构。看起来是双车道但其中一条被路边停车完全占据时,如果有效通行空间接近对向单车道,归 R2；否则普通行驶仍归 R1。
停车车辆突然启动、开车门、遮挡视线或自车从停车区域并入主路,统一由 R-E2/U-E2/U-E3/U-E4 表达事件。
ParkingExit、ParkingCrossingPedestrian、ParkingCutIn、StaticCutIn 都不再额外生成停车道路结构；VehicleOpensDoorTwoWays 用 R2 表达有效可行驶对向单车道。



事件分类
R-E1. 跟车 / 车道保持
这是最基础的常规事件。
核心含义：
自车沿当前车道或可行驶区域前进，并根据前车状态保持安全距离。
包括：
●  普通车道保持；
●  普通跟车；
●  环岛内沿可行驶路径行驶；
●  非结构化道路中的正常前进；
●  路口、合流、障碍事件前后的背景驾驶状态。
对应行为：
KEEP_LANE
FOLLOW_LEAD_VEHICLE
MAINTAIN_SAFE_DISTANCE
适用场景片段包括：
●  ControlLoss；
●  noScenarios；
●  Accident / ConstructionObstacle / ParkedObstacle 中未遇到障碍之前和绕行结束之后；
●  HardBreakRoute 中前车急刹之前和恢复之后；
●  DynamicObjectCrossing 中大部分正常行驶片段。

R-E2. 目标导向型变道
核心含义：
当前车道通常仍然可行，但自车为了完成路线目标，需要主动换到目标车道。
触发原因是自车路线或导航目标，而不是外部障碍。
包括：
●  为了高速出口提前变到右侧车道；
●  为了左转提前变到左侧车道；
●  自车初始不在期望车道，需要修正到目标车道；
●  从停车位或停车侧汇入主行驶车道；
●  根据目的地选择目标车道。
对应行为：
ROUTE_REQUIRED_LANE_CHANGE
SELECT_TARGET_LANE
CHANGE_LANE_WHEN_SAFE
典型场景片段：
●  HighwayExit；
●  ParkingExit；
●  InterurbanActorFlow；
●  StaticCutIn 开头“自车不在期望车道”的片段。
这里一定要和“被迫变道”区分开。

R-E3. 常规匝道合流 / 并线 / 驶出
核心含义：
道路结构本身要求自车完成合流、并线、汇入或驶出，这是正常驾驶任务。
它虽然需要判断侧后方车流，但不是突发事件。
包括：
●  自车从匝道并入主路；
●  自车进入慢速车流；
●  自车在高速或匝道结构中完成合流；
●  自车驶出高速。
对应行为：
MERGE_WHEN_SAFE
MATCH_TRAFFIC_SPEED
CHECK_SIDE_REAR_GAP
YIELD_IF_NEEDED
EXIT_WHEN_SAFE
典型场景片段：
●  EnterActorFlow / EnterActorFlowV2；
●  MergerIntoSlowTraffic / MergerIntoSlowTrafficV2；
●  HighwayExit。
注意：
HighwayCutIn 不是自车主动合流，而是他车切入自车道，所以更适合归为突发事件。

R-E4. 信号灯路口通行
核心含义：
自车根据正常信号灯规则完成停车、等待、直行、左转或右转。
包括：
●  红灯停车；
●  绿灯直行；
●  绿灯左转；
●  绿灯右转；
●  有信号灯 T 字路口通行；
●  有信号灯路口的正常等待和启动。
对应行为：
STOP_AT_RED_LIGHT
GO_AT_GREEN_LIGHT
TURN_LEFT_AT_SIGNAL
TURN_RIGHT_AT_SIGNAL
GO_STRAIGHT_AT_SIGNAL
典型场景片段：
●  RedLightWithoutLeadVehicle；
●  SignalizedJunctionLeftTurn；
●  SignalizedJunctionLeftTurnEnterFlow；
●  SignalizedJunctionRightTurn；
●  T_Junction，如果是信号灯控制；
●  BlockedIntersection 中“看灯”本身属于常规部分。
注意：
如果绿灯时出现对向车闯红灯，常规信号灯通行会被突发事件打断。

R-E5. 无信号灯路口通行
核心含义：
没有红绿灯，自车根据正常路权关系和安全间隙完成直行、左转或右转。
包括：
●  无信号灯左转；
●  无信号灯右转；
●  无信号灯直行；
●  等待横向车流；
●  等待对向优先车；
●  路权允许时通过。
对应行为：
NEGOTIATE_PRIORITY
WAIT_FOR_SAFE_GAP
PASS_WHEN_SAFE
TURN_LEFT_WHEN_SAFE
TURN_RIGHT_WHEN_SAFE
GO_STRAIGHT_WHEN_SAFE
典型场景片段：
●  NonSignalizedJunctionLeftTurn；
●  NonSignalizedJunctionLeftTurnEnterFlow；
●  NonSignalizedJunctionRightTurn；
●  OppositeVehicleTakingPriority；
●  PriorityAtJunction；
●  PedestrianCrossing 中如果只是正常路口让行，也可以作为背景事件。
这里需要注意：
正常路权判断本身不是突发事件。只有出现额外异常对象时，才切换到突发事件。

三、完善后的突发事件分类
突发事件建议保留为 8 类基本单元。

U-E1. 前车急刹 / 突然减速
核心含义：
前车突然急刹或快速减速，自车原本的常规跟车被打断，必须紧急减速以避免追尾。
触发来源：
●  前车突然刹车；
●  前车速度快速下降；
●  TTC 快速变小。
对应响应：
EMERGENCY_DECELERATION
KEEP_TTC_SAFE
AVOID_REAR_END_COLLISION
典型场景：
●  HardBreakRoute。
事件片段：
常规跟车 → 前车急刹 → 自车紧急减速 → 恢复跟车

U-E2. 静态障碍物占道
核心含义：
自车当前行驶路径被静态障碍物阻挡，原本的车道保持或跟车任务被打断。
障碍物包括：
●  事故车辆；
●  施工障碍；
●  停放车辆；
●  静止车辆；
●  路侧危险物；
●  开门车辆造成的占道风险。
对应响应：
STOP_AND_WAIT
FORCED_SAME_DIRECTION_LANE_CHANGE
FORCED_OPPOSITE_LANE_INVASION
RETURN_TO_ORIGINAL_LANE
这里要重点强调：
由静态障碍物触发的变道是被迫变道，不是目标导向型变道。
事件片段：
常规跟车 / 车道保持
→ 静态障碍物占道
→ 判断是否可绕行
→ 被迫变道或停车等待
→ 绕过障碍
→ 回归车道保持
同向绕行场景：
●  Accident；
●  ConstructionObstacle；
●  ParkedObstacle。
借对向车道绕行场景：
●  AccidentTwoWays；
●  ConstructionObstacleTwoWays；
●  ParkedObstacleTwoWays；
●  HazardAtSideLaneTwoWays；
●  VehicleOpensDoorTwoWays。
HazardAtSideLane 需要稍微注意：
如果是同向多车道内避让，则是同向被迫变道；
如果是 TwoWays，则是借对向车道绕行。

U-E3. 动态车辆切入 / 动态占道
核心含义：
其他车辆突然进入或即将进入自车未来路径，自车原本的常规行为被动中断。
包括：
●  侧方车辆切入自车道；
●  匝道车辆切入主路自车道；
●  路边停车车辆突然启动；
●  停止车辆突然进入当前车道；
●  静止车辆变成动态障碍并侵入自车路径。
对应响应：
SLOW_DOWN
YIELD_TO_CUT_IN_VEHICLE
STOP_IF_NEEDED
FOLLOW_AFTER_CUT_IN
典型场景：
●  HighwayCutIn；
●  ParkingCutIn；
●  StaticCutIn 后半段；
●  DynamicObjectCrossing 中存在动态对象干扰的片段。
需要区分：
常规合流：
自车主动并入车流。

动态切入：
他车突然进入自车路径，自车被动避让。

U-E4. 行人 / 自行车横穿
核心含义：
行人或自行车突然进入自车预期路径，自车必须让行或停车。
它可以发生在：
●  普通直道；
●  路口；
●  转弯后；
●  停车车辆遮挡区域；
●  有信号灯路口；
●  无信号灯路口。
对应响应：
YIELD_TO_PEDESTRIAN_OR_BICYCLE
SLOW_DOWN
STOP_AND_WAIT
PROCEED_AFTER_CLEAR
典型场景：
●  CrossingBicycleFlow；
●  PedestrianCrossing；
●  ParkingCrossingPedestrian；
●  VehicleTurningRoute；
●  VehicleTurningRoutePedestrian。
事件片段：
常规路口通行 / 常规跟车
→ 行人或自行车横穿
→ 自车减速或停车让行
→ 横穿对象离开路径
→ 恢复常规通行

U-E5. 对向车辆异常侵占自车道
核心含义：
对向车辆因为障碍物或异常行为侵入自车车道，自车被迫等待或减速。
这和 TwoWays 借对向车道不同：
TwoWays 绕行：
自车主动借用对向车道。

对向车侵占：
对方车辆占用了自车道，自车被动让行。
对应响应：
YIELD_TO_INVADING_ONCOMING_VEHICLE
STOP_AND_WAIT
RESUME_LANE_KEEPING
典型场景：
●  InvadingTurn。
事件片段：
常规车道保持
→ 对向车侵入自车道
→ 自车停车等待
→ 对向车离开
→ 恢复车道保持

U-E6. 违规车辆冲突
核心含义：
自车本来按照规则可以通行，但其他车辆违反规则，导致自车必须避让。
典型情况：
●  自车绿灯左转或通行；
●  对向车闯红灯；
●  对方不按路权通过；
●  规则上自车可走，但实际路径被违规车辆占用。
对应响应：
STOP_DESPITE_PRIORITY
YIELD_TO_RULE_VIOLATING_VEHICLE
PASS_AFTER_CONFLICT_CLEARS
典型场景：
●  OppositeVehicleRunningRedLight。
事件片段：
绿灯正常通行
→ 对向车闯红灯
→ 自车减速或停车避让
→ 冲突解除
→ 继续完成路口通行
这类可以看作“异常路口冲突”的一个子类，但建议单独保留，因为它和信号灯故障不同：
信号灯没坏，是对方违规。

U-E7. 信号灯故障 / 路口规则失效
核心含义：
路口的正常灯控规则失效，自车不能再按照“红灯停绿灯行”的常规逻辑通过，而必须全程观察四个方向的车辆。
典型场景：
●  CrossJunctionDefectTrafficLight。
它和其他突发事件不同：
其他突发事件：
常规事件中间插入一小段异常。

信号灯故障：
整个路口通行阶段的规则基础都失效。
所以它不太适合写成：
常规通行 → 突发插入 → 恢复常规通行
更适合写成：
异常路口通行阶段：
信号灯规则不可用 → 全程判断四向车流 → 找安全间隙通过
对应响应：
IGNORE_DEFECTIVE_SIGNAL_AS_PRIMARY_RULE
CHECK_ALL_DIRECTIONS
PASS_WHEN_CONFLICT_FREE
它属于突发事件大类，但片段形态是“整段路口异常”，不是短插入。

U-E8. 前方道路暂时阻塞 / 阻塞解除
核心含义：
自车原本可以继续行驶或通过路口，但前方道路暂时没有可通行空间，需要停止等待；之后阻塞突然解除，自车继续前进。
典型场景：
●  BlockedIntersection。
它也比较特殊。它不是典型绕行，也不是简单让行，而是：
常规跟车 / 看灯
→ 前方无路可走
→ 长时间停车等待
→ 前方车辆或障碍突然消失
→ 恢复车道保持
对应响应：
STOP_BECAUSE_PATH_BLOCKED
WAIT_UNTIL_PATH_CLEAR
RESUME_AFTER_BLOCKAGE_DISAPPEARS
建议单独保留，不要混入静态障碍占道，因为 BlockedIntersection 的重点不是“绕障能力”，而是：
能否在长时间等待后重新判断道路已恢复可通行。
