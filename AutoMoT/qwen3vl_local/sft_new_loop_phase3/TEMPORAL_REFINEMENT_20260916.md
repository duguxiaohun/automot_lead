## 1. 标定函数内部固定窗口

旧 `label_actions` 要求至少九个速度采样，但随后遍历整段传入序列。
标准 `RouteTrajectory.signals` 通常只提供九个采样，所以不能据这个缺口声称旧数据普遍错标。
问题在于其它调用方传入更长审计轨迹时，2 秒之后的下降/增速/回落也可能影响标签。

现在[trajectory_action.py](trajectory_action.py)通过共用 `longitudinal_decision` 固定使用
当前至 +2s 的九个速度采样。额外尾部只记录数量，不参与判定；窗内缺值/缺帧仍拒绝标定。
例如 `[5]*9 + [0, 0]` 保持 NONE，窗外停车不能改成 DECEL；窗内持续增速后 +2.25s 回落也不再隔离窗内 RESUME。

仍保持原合同：

- STOP：≤0.5m/s 的两个连续采样都在 [0,1.5s]，包含当前帧。
- DECEL：相对当前速度首次下降达到 `max(1.2m/s, 20% × 当前速度)`，单次达到即可。
- RESUME：相对当前速度连续两次增速达到同一门槛，确认不晚于 +2s。
- 当前已确认等待优先于随后起步；原有先增速再明显回落的混合窗继续隔离，不写成 NONE。
- 横向仍由原车道身份/RGB 不确定性守卫处理；本次未改变车道方向、稳定确认或 road/section 规则。

## 2. 标定依据可追查

`action_evidence.longitudinal_decision` 记录：是否可标定、动作、原因、基准速度、门槛、首次下降、
增速开始/确认、近停开始/确认、混合窗回落时刻、使用/忽略采样数。
缺帧、非法速度、混合阶段不再都归入同一个笼统原因。

[audit_temporal_slices.py](audit_temporal_slices.py)复用同一函数，避免诊断与标定各维护一套时间判定。
新增 `isolated_gain_present`、`gain_unconfirmed_at_2s_boundary` 两个诊断切片；
最后一帧未确认只表示窗内证据不足，不宣称下一帧一定确认。
所有判定轨迹只进入离线证据，**不渲染到模型输入，也不增加 teacher 动作解释或答案暗示**。

## 3. 提示词改动范围

[prompts.py](prompts.py)明确最新帧为 t=0、截止时刻包含端点、相对当前速度计算变化、
RESUME 双采样确认都在 2 秒内；横向规则提取为 binary/choice 共用常量，补齐 choice 原先省略的
“车道内经过、道路连接不等于跨线”等排除条件。

输出合同不变：binary 仍逐行 YES/NO，choice 仍为所属三/五个动作中的唯一词组，不加入 NONE/INVALID/联合动作选项。
同输入切换答案或 invalid 真值不会改变提示词；模型仍只看到历史 RGB、当前速度、导航和场景前提。

默认无额外 history detail 的十情境样例，system+user 英文词数：

| 模式 | 最少—最多 |
| --- | --- |
| binary 4RGB | 287—398 |
| binary 2RGB | 284—395 |
| choice 4RGB | 278—397 |
| choice 2RGB | 275—394 |

这是词数，不是 tokenizer token 数；额外 context detail 会增加长度。
[本地完整提示词样例](probe_output/temporal_contract_20260916/prompt_examples.json)可直接检查四种组合。
