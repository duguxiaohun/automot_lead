## 1. [P2] 漏记从明确无约束对象到出现约束对象的变化

位置：`action_review.py:106–111`，特别是 `limiter is not None` 条件。

`_known_limiter()` 正确把显式 `None` 视为已知的“无对象”，与缺字段区分。
但随后只有 anchor 已存在对象 ID 才进入变化检测，导致 `None → ID` 的首次约束出现被永久跳过。
这与文档中 `logged_limiter_change` 记录“连续、已知记录中约束对象首次改变”的定义不一致。

真实复现：`StaticCutIn/Town12_Rep0_1117_0_route0_01_10_22_43_12`，UE3 f69。

| frame | speed_reduced_by_obj_id | target_speed |
| --- | --- | --- |
| 69 | null（字段存在） | 6.75 |
| 70 | null（字段存在） | 6.75 |
| 71 | null（字段存在） | 6.75 |
| 72 | 3739 | 6.012149886163494 |
| 73 | 3739 | 6.192203880700742 |

应能记录 `{"at_s": 0.75, "from_id": null, "to_id": 3739}`，
当前 `build_action_review()` 和已生成 candidate 的 `logged_limiter_change` 均为 null。
该例在已使用的审计窗口内且此前记录连续完整，不涉及推断未知字段。
这里只证明日志的对象约束出现，不把该 ID 的出现等同于唯一驾驶原因或事件起点。

对局部 1148 条候选逐路线回读，查到 **257 条上下文题 / 257 个物理 anchor** 有同类遗漏。
这些 anchor 有时间相关性；这是审查字段缺项数，不是动作错标数或独立风险事件数。
完整身份与预期/实际值保存在本地
`probe_output/v19_independent_review_20260920/missed_limiter_acquisition.json`。

建议让显式无对象也参与首次变化比较，并继续在缺字段/非法值时终止连续证据链。
回归需包含 `None→ID`、`ID→None`、`ID→另一ID` 和中途未知四类。
若字段只打算描述原有对象的解除/替换，则需相应收窄字段名称和文档；当前说明不能声称覆盖所有首次约束变化。

影响限于离线工作流证据。`review_only` 不进入模型输入或动作标签，因此本问题不要求修改 STOP/KEEP 或原始速度规则。
构建器和审计器共用同一函数，二者结果一致不能发现这种共同遗漏；本次是独立比较原始对象记录后发现的。

## 2. 提示词与标定的完成程度

v19 确实补上了上一轮的一项语义缺口：十类 KEEP 不再要求风险已清空，
共享说明允许当前阶段内短暂制动，choice/binary 使用相同释义。
制动命令与实际速度阶段分开，零目标速度没有被直接改成 STOP，缺失值也未补成 false/0。

UE2 的避碰、观察邻车及来车、等待可用间隙的目的仍在动作段，scene_context 仍保留 RS、事件和历史事实。
RE5 未停车时的持续增速、持续等待为 STOP、已完成跨线后继续通过可为 KEEP 等语义保留。
未发现本轮所查渲染路径把新增 controller、对象 ID、未来节点或数值窗口放入模型提示词。

标定算法仍为 v8，主要动作仍为 STOP > 首次跨线 > 速度，未升级为完整阶段序列。
与 v18 修复后的局部产物逐项比较，1148 条候选和 384 行索引只有
`action_review`、`mapping_contract_hash` 两项改变；标签、原始速度证据和采样顺序均一致。

运动边界仍为 220 个主要 KEEP 中 67 个命中诊断；新增响应桶为 40 个制动请求、其中 12 个车辆零目标速度请求。
这些桶重叠，不是错标率。新字段让问题可查，新文案避免误解，但尚不能证明四帧 RGB 下这些标签都容易区分。
动作因果仍是条件性目的解释；对象日志提供可核验的约束事实，不能证明观察、判断空隙等认知过程。

## 3. Action 侧衔接

检查 `run_full_pipeline.sh`、`scene_policy.py`、`action_input.py` 和实际 prompt 渲染：

- 动作开关独立使用，原 planning 开关拒绝；干净 dataset + action 条件才自动补独立特殊 RE。
- 只有通过上游门控且支持所选动作的上下文用于选择描述；并发时按 taxonomy 固定顺序选择一句。
- 十类共 38 个变化动作组合，prefill、摘要、复核和 fallback 四条渲染路径均使用完全相同的 Phase3 描述。
  本轮执行 152 次渲染断言，并检查 3 类空状态不添加动作句。
- `NONE/no_action` 不合成 KEEP，沿用原协议；因此不能直接把新版 Phase3 KEEP 文本当作 Action 外部预测输入。
  这是当前明确约定，未作为新增缺陷。
- 条件身份绑定 `choice_semantics.py` 源码哈希，旧训练条件不能静默套用新文案。

并发上下文按 taxonomy 选描述是确定性的模板策略，仍不能证明被选中的事件是该帧动作的唯一实际原因。
本次只审查动作条件的衔接，没有把 Action 优化器、训练恢复和 GPU 执行一并宣称审计通过。
