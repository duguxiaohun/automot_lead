# 2026-09-14：20260911_174046 binary / choice 与历史版本指标比较

本次 binary 总体 exact 与上一版基本持平，左右变道 P/R 明显上升，但减速仍是主要短板。choice 在同一批单动作题上确有优势，主要改善减速与恢复增速；它没有评估无动作、错误前提和联合动作，不能替代完整 binary 合同。

## 证据与可比性

- 新包：[binary](../../checkpoints/sft_new_loop_phase3_20260911_174046_4rgb_binary_audit_bundle/lora_production/metrics.json)、[choice](../../checkpoints/sft_new_loop_phase3_20260911_174046_4rgb_choice_audit_bundle/lora_production/metrics.json)。
- 历史数字来自 [20260911 审计摘要](AUDIT_SUMMARY_20260911.md) 与 [20260910 审计摘要](AUDIT_SUMMARY_20260910.md)。本地此次只有两个新包，没有重新读取历史包逐题结果。
- 两个新包都是 4RGB、语言 LoRA、视觉 LoRA 关闭，prompt v7，动作规则 current_wait_first_crossing_v7_rgb_guard，mapping hash 一致。两份 dataset manifest 仅 frame_index 路径不同；split seed=20260911，索引 train/val/test=13524/396/552。训练记录的 47 个源码 SHA256 全部与本地对应文件一致，训练 Git commit 为空，打包 commit 不能当训练 commit。
- 上一版是 v6 prompt 与旧 holdout；旧 765 题所属物理路线已进入开发/train-only 集合。这次是新 holdout，因此跨历史版本只比较表现趋势，不能将差值解释为压短 prompt 的单独因果收益。
- 新版 binary/choice 的 306 个共有题已逐题核验：身份、GT、四图 SHA256、导航、场景前提、当前速度与未来速度证据一致（当前速度另由 prompt_spec 核验）。两者 prompt/输出合同和训练数据筛选、选中保存步不同，因此是两个已训练系统在同题上的比较，不是等预算、只改输出格式的消融。
- 指标为离线动作问答，非 CARLA 闭环成功率，也不是串联真实 Phase1/2 预测后的端到端分数。本表使用修改前的原始包成绩；后续已完成的 RGB 逐帧审计与修订见 [EVAL_REVIEW_20260914.md](EVAL_REVIEW_20260914.md)，没有新模型成绩。

- binary：训练选中的best通过val guard，但最终test `production_ready=false`；唯一失败项DECELERATE recall=47.06%<50%。run_root选择状态里的true只是验证选优状态，不能覆盖test结果。
- choice：test `production_ready=true`，通过的是choice单动作任务自己的guard；没有NONE/INVALID/组合动作考核，不能将这个标志解释为完整驾驶任务或闭环已就绪。
- 同RS错事件仍只有2题、2条独立路线，1题答对。invalid总体高分主要来自90题错道路前提。

## 判断与后续优先级

1. 若保留完整Phase3合同，binary的横向识别已有明显进步；应优先审查DECEL漏报及其与STOP/RESUME的阶段混淆，其次是NONE误触发与联合动作。
2. 若任务已保证前提有效且恰好一个动作，choice更有依据：同题净增38题。但其横向召回、恢复增速误报和路口规则冲突退化需要保留观察。
3. 这次新test已经用于比较与诊断；后续根据其错例修改prompt或规则时应按项目开发路线隔离约定管理，最终提升应在未参与修改的holdout报告。
4. 本报告保留原始结果与CPU逐题校验，不回写原始审计包。后续代码、提示词、标签修订单独记录在 RGB 审计报告；不能把修订后数据上的统计冒充这两个 adapter 的新成绩。
