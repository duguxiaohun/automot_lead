## 实现与数据来源

- `keyframe_filter/evidence_guards.py` 被 collector 和 Phase3 适配共同调用；`annotation_repair.py` 保留源 RS/EVENT、修复原因及修复后的字段。
- `annotation_repairs_20260910.json` 只包含已看过的精确帧段；`lateral_rgb_uncertainties_v1.jsonl` 保存横向反证。它们都进入映射指纹，修改决定不能静默复用旧索引。
- 旧 `collection_output/*_result.json`、原 RGB/meta、旧 checkpoint 与审计包不覆盖。新索引从正式 collection 全量读取并应用修复，不将旧 review cache 冒充全量数据；原始 meta 重新读取生成动作。
- 本次 54 条已用于规则开发的物理路线加入 `development_route_groups_20260910.json`。与此前 258 条合计 312 个开发路线组，只进入 train；新 val/test 不包含这些路线。同一物理 route 的 Rep/重复采集仍不跨 split。
- 最终完整构建 14,400 条（train 12,888 / val 504 / test 1,008）；312 个开发路线组与 val/test 无交叉。最终验证状态保存在本地 `checkpoints/phase3_repair_20260910/repair_status.json`。首轮与最终数量相同，因为按最小 context 容量平衡；候选池与抽样内容已改变。
- 自动门控命中数是待核验候选量，不是人工确认错标数。未来动作一致性检查也不等于 RGB 语义正确率。

## 验证和配对评测

最终 14,400 条索引已回读 3,301 个采集 run 的原始 meta（3,300 个物理路线组），速度和被问动作差异均为 0，物理路线跨 split 数为 0。当前 99 项 CPU 回归测试通过，shell 语法与 diff 检查通过；没有运行真实 GPU 训练。

`audit_rebuilt_index.py` 检查全索引合同、RGB 文件和完整精度标签；新增 `audit_raw_index.py` 从原始 meta 再读速度和车道身份，防止索引只凭自己保存的轨迹自证。`audit_temporal_slices.py` 单列启动历史重复、接近阈值、窗口末端减速和静止 anchor 随后起步；这些是诊断切片，不删难例，也不调整分类阈值。

新增 `paired_eval.py` 按 scenario/run/frame/context/RS/问序精确配对，拒绝缺样本、重复样本、不同真值、导航或 RGB 身份，保留严格 parser 的格式失败。新 eval 保存实际输入 RGB SHA256，并要求两侧指纹一致；历史包缺指纹只报告路径身份验证。`eval.sh` 在 base 与 LoRA 的 production 生成完成后自动输出 `paired_base_lora.json`。报告分别保存有效/invalid、context、动作组合和时间诊断切片的两侧准确率及改对/改错计数，切片允许重叠；不是只报总体平均。

对旧包的配对工具回归：767 条，base 207/767，旧 LoRA 470/767；两者都对 151、base 对/LoRA 错 56、base 错/LoRA 对 319、两者都错 241。这只是旧成绩重现，不是本轮修复收益。

修复后的新模型应在同一新测试索引上完成 base/LoRA 配对。若要进一步与旧训练方法比较，应另做同预算、同物理分割的训练对照，并在固定真值上评测；旧 61.28% 与新标签、新测试集的分数不能直接相减。prompt 校验不应为迁就旧 adapter 而关闭。仅有 base/新 LoRA 的结果也不能单独证明“标注修复”或“提示词修复”的独立贡献。

最终独立追溯扫描覆盖 7,241 条有效 run、914,466 个源标注帧，共记录 2,639 个发生修复的帧。1,582 帧命中 hazard-only R4；13 帧 HighwayCutIn 视觉决定中有 9 帧同时命中该门控，最终 1,573 帧 RS 保守隔离为 UNKNOWN。13 帧均使用视觉确认的 R3 并清除不适用的 R-E4；1,053 帧移除普通 trigger-only R-E3。不同修复原因可以重叠，不能直接相加作为独立帧数。横向过滤另计候选窗口：非相邻 lane-id 跳变 758 个、精确 RGB 冲突 15 个，可能包含同一帧的不同 context，不能称为 773 个独立错标帧。新增 section 变化分支此次未命中，不能把它当成原始数据已提供完整 lane-section 拓扑的证明。

最终 test 的 1,008 条中，17 条含启动重复历史、20 条静止 anchor 随后 RESUME、35 条直到 1.5s 后才跨过减速阈值；42 条速度接近停车阈值、80 条接近速度变化阈值。切片可重叠，统计来自精确 meta，不证明 RGB 一定不可判别，也不据此调整标签或删除样本。

## GitHub 同步与远端执行入口

从 `AutoMoT/` 运行，在用户的训练机上，完整本地模型具备后：

```bash
DATA_DIR=checkpoints/sft_new_loop_phase3_data_v7 \
BUILD_WORKERS=3 \
MODEL_DIR=checkpoints/Qwen3-VL-4B-Instruct \
bash qwen3vl_local/sft_new_loop_phase3/run_full_pipeline.sh
```

默认沿用四卡训练，输出写入带时间戳的新 pipeline 目录。需要单卡时显式设置 `TRAIN_MODE=single`。所有模型调用继续离线，不下载。

用户明确使用 GitHub 正常同步。代码、轻量审计规则、测试和说明均在现有白名单；`checkpoints/` 内索引、训练输出与本地审计产物不入库，也不需要专用迁移包。远端拉取后运行上述 pipeline，默认从训练机上的正式 collection 和原始 LEAD 数据重新构建 v7 索引。`MODEL_DIR` / `DATA_ROOT` / `COLLECTION_DIR` 按远端实际路径覆盖。索引构建后自动执行两层数据核验、时间诊断、训练、base/LoRA 评测与审计包生成。

仍待完成：完整 Qwen 权重可用后的真实训练与新模型配对评测；同 RS 负例的未见路线覆盖仍很少；可信 lane-section/successor 拓扑与更长历史/近端导航消融尚未实现。不能把这些问题写成已解决。


远端不得从旧训练 checkpoint 直接 resume 到新合同。本地通过代码/数据检查不表示真实 GPU 训练已通过。

`audit_annotation_repairs.py` 单独扫描正式 collection，保存所有发生修复的逐帧记录，包括未进入索引的 UNKNOWN 帧；每条包含原始 RS/EVENT、修改原因和人工确认标记。远端 pipeline 自动执行，产物放在本轮 pipeline 的 `annotation_repair_audit/`，不入库。
