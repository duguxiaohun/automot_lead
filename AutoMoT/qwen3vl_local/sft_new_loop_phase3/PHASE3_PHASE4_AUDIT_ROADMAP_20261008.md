# Phase3 / Phase4 统一证据、独立语义与计算优化方案

日期：2026-10-08。状态：**设计与审计指导；G0 本机审计工具已开始实施，其余实验尚未执行**。首批代码、真实本机结果和服务器待办见 [G0 实施说明](../audit_joint/README.md)。下文原讨论与历史数字不因新增工具升级为复现结果。

本文综合本轮讨论、已读取的工作区源码和 Qwen3.5 官方实现。本次文档操作未写入既有源码、标签、采样、运行入口或模型，也未启动全量建库、人工盲标、GPU 训练或 CARLA。文中的历史数字来自已有产物，不能当作本轮新实验。

**基线决策已确定：** Phase4 后续开发使用 v42/老师 v10 的完整冻结快照，Phase3 使用明确 prompt variant 的 v23，模型保持本地 Transformers 5.3.0 vendor。G0 负责实际冻结和复现；本次仅完成版本选择，未生成快照。v41 只作历史参照，只有找回匹配的原始源码、数据和模型资产后才复现；不能用 v42 源码替跑。v42 的代码变更和验证不属于本次文档实施成果。

阅读顺序：本文定义共同原则与验收流程，再读 [Phase3 落实指南](IMPROVEMENT_GUIDE_20261008.md) 和 [Phase4 落实指南](../sft_new_loop_phase4/IMPROVEMENT_GUIDE_20261008.md)。本文不替代既有运行手册，也不新增可直接调用的命令。下文产物名称、字段和实验编号均为建议设计，除明确链接的现有文件外，不表示已经实现。

## 1. 总体决策

保留 Phase3 对采集车行为的预测、Phase4 对当前转移条件的判断，建立共同证据时间线。先诊断标签、输入与任务的关系，再分别进行语义实验和计算优化。暂不把两个任务合成一个标签体系，也不以共同前缀为理由强制合并 LoRA。

| 主线 | 要回答的问题 | 不能用来替代的证据 |
| --- | --- | --- |
| 证据与标签审计 | 标签说的事实是什么，学生是否能判断，来源是否可靠？ | 单元测试数量、规则回放数量 |
| 任务与输入实验 | 改标签、问题域或输入后，部署所需能力是否改善？ | 合并类别后的表面准确率、老师一致率 |
| 计算优化 | 同一训练目标能否更快、更省显存地计算？ | token 数估计、推理缓存可用、仅后缀梯度非零 |
| 序列与下游验收 | 条件判断能否驱动正确状态进展，并保留必要限制？ | 单帧答对率、固定录制视频回放 |

## 2. 对已修订路线的进一步完善

1. **逐锚点标签与物理动作起止分开。** `trajectory_action.py` 重算的是从某个锚点出发、按阈值和窗口判定的标签及决策轨迹；它不是现成的全路线物理动作分段器。时间线应分别保存这些结果与另行定义、审核的物理起止，不能把标签翻转冒充实际动作发生。
2. **最终 test 只用于冻结方案的确认。** 单因素实验在开发验证集比较；若每次改法都查看新的“独立 test”并据其选优，后续它就承担了验证集的作用。保留开发训练、开发验证、规则独立审核、最终测试的角色区别。
3. **盲标任务按 Phase 区分。** Phase4 标当前条件 YES/NO/UNKNOWN；Phase3 标各行为命题的可判断性及可接受预测集合。不能把“当前可以走”当作“采集车随后确实会走”的人工真值。
4. **删除问题不用三个条件的机械合取。** 可由部署时已知条件可靠计算的冗余问题，即使可见也可省去模型问答；下游需要而学生不可判断的问题，应补输入、改问法或外部计算。不能因为无法判断就强留强制二分类。
5. **S2 拆分输出协议与集合监督。** 先核对原动作名在真实模板下的 tokenization，保留完整动作名是默认选择；确需编码时才单独验证新协议。多 token 答案也能做完整序列概率的集合目标，不必为集合监督强改字母输出。
6. **S4 分开跨度与图数。** 保留 Phase4 原跨度/图数实验，另加两 Phase 的 `[-2,0]` 短跨度臂。共同锚点、精确输入审核及 coverage 分别报告，不因统一 batch 或缓存就统一历史偏移。
7. **边界未知不等于动作等价。** 不清楚采集车会做什么，不自动意味着多个答案都“正确”。S2 必须有预先定义的预测容忍语义和人工证据；不可识别样本可选择不监督，而不是一律扩大答案集合。
8. **条件重新变 NO 是正常行为。** 延迟指标按连续条件成立片段计算；新冲突、实例更换或采样断档会中断片段，不能把首次 YES 后所有旧状态都计为偏晚。

### 3.2 已有结果不能扩大的范围

已有 Phase3 20261008 四图 choice 候选审计包有 380 题、108 错、严格准确率 71.58%，记录的提示词分支为 `v23_rgb_stage_candidate_20261006`，不是任意 v23 模型的共同结果。其 `production_ready` 与质量门状态为 false。

其中 DECELERATE→STOP 为 16 题，6 题记录停车起点为 1.5/1.75 秒，另 10 题在已有 2 秒窗口内无停车起点；DECELERATE/STOP→KEEP 共 27 题，RESUME→STOP/KEEP 共 18 题。这些计数用于安排审核，不预估“放宽后能吸收多少错误”。

Phase4 v41 已有验证为 34 条开发训练路线、3601 帧程序回放；两图/四图各 3071 训练题，其中 443 人工、2628 弱题；人工 val 273/test 186，待审 539。人工评估仍只覆盖四事件，严格 registry 为空；34 路线无 return 监督，自动 no-return/in-lane-pass/cyclist-bypass 分支仍缺。没有本轮新增的全量 v41、独立审核或 GPU/CARLA 效果结论。

1067 项专项通过证明已覆盖的程序合同，不证明老师标签或驾驶行为正确。历史审计包的明细在本地 checkpoints；可追踪的事实摘要见 [v41 验证记录](../sft_new_loop_phase4/ten_event_teacher_v41_verification_20261008.json)。

## 4. 不变项与待实验项

不变项：未来轨迹不能进入学生当前输入；来源与图像 SHA 不能绕过；物理路线身份不因 Rep、采集时间、软链接或目录搬迁而改变；人工标签不能被弱老师静默覆盖；UNKNOWN 不伪装为 NO、KEEP 或 INVALID；Phase4 双轴状态、横向执行许可及执行回执保留。

Phase3 的未来轨迹可作为行为预测的离线目标证据；这不等于未来泄漏到输入。Phase4 判断当前条件时，不能用未来动作证明当前许可。时间戳在当前的规划字段也需要审计部署来源：它可能来自采集专家的机动选择，不能仅凭“当前字段”就认定线上可得。

下列变化均属新实验：输入跨度或字段、标签阈值、可接受集合、候选动作域、输出 token 协议、loss 归一化、附带题、邻帧采样、dropout 分布、模型版本与联合 LoRA。它们不能和纯计算重排一起声称“语义不变”。

## 5. 阶段 G0：冻结基线与全链路数据隔离

### 5.1 基线清单

建议生成 `baseline_manifest.json`，记录：源码提交与未提交差异摘要、逐文件 SHA、模型全部资产身份、processor/tokenizer/chat template、非思考格式、LoRA 配置、torch/Transformers/PEFT/FLA/causal-conv1d/CUDA 版本、设备、精度、kernel、数据 manifest、图像合同、训练/评估提示词、采样历史、loss 分母、world size、梯度累积和 checkpoint 选择规则。

固定环境复现至少包括合同核验、同 checkpoint 的完整目标评测、固定训练小批次的数值与性能基线。旧 checkpoint 仅用其匹配源码和资产复现。当前工作区已有修改时，不能只用 Git HEAD 代表源码，也不能替旧 manifest 重写 hash。

快速内核预检不能止于包版本：四个 rank 分别记录 `fla`、`causal_conv1d` 的导入文件、版本/提交、CUDA/编译兼容性，以及实际绑定的 chunk/recurrent/conv 函数；在目标 GPU 上以真实 BF16 输入验证前向、反向和生成路径，并由 profiler 确认调用。普通注意力的实际后端另查，不能把 SDPA 配置等同于已调用 FlashAttention。本地 vendor 缺依赖时有 `warning_once` 并回退，不是硬失败，也不完全静默；日志可能只出现一次。[官方用法说明](https://huggingface.co/docs/transformers/main/en/model_doc/qwen3_5) 同样提示缺少这些可选依赖会走慢路径。G0 可以登记慢路径基线，但 H20 性能选档必须在已核实的同一后端下比较；E4c 多段打包则要求边界功能实际可用，不能带着不支持边界的回退运行。

### 5.2 角色分离

| 数据角色 | 允许用途 | 失去独立性的触发 |
| --- | --- | --- |
| 开发训练与试标路线 | 调规则、诊断、设计输入与容忍语义 | 本来就不是独立效果证据 |
| 开发验证集 | 选超参、阈值、输入方案、checkpoint | 不作为最终独立 test |
| 规则独立审核集 | 按冻结规则审核老师；保留原预约 | 看过结果后改规则，后续同样本审核需标明重复使用 |
| 最终留出测试 | 冻结候选后的确认 | 看错误并据此改方案后，后续不能再称未参与设计 |
| 历史回归集 | 对照旧指标和已知失败 | 已有曝光不靠改文件名、重抽帧或重切分消除 |

划分以物理组为最小单位。建立 Phase3/Phase4/Action 使用数据、老师开发路线和人工曝光组的交叉矩阵；重点检查任一训练来源与另一任务 val/test 的交集。别名和软链接按稳定逻辑身份、文件/像素内容核对，不能只比路径。

发现交叉冲突先登记其来源和受影响实验。旧实验不改历史 split；新联合实验建立新的联合准入清单。最终留出不足时报告缺额或补采独立路线，不把已曝光组改回 test。

建议产物：`split_cross_audit.json`、`exposure_ledger.jsonl`、`baseline_manifest.json`。通过条件：训练与该实验最终留出无物理组交集；每个结果能还原其实际数据、源码和模型。

### 5.3 补齐六事件开发验证集

现有 Phase4 人工 val 只覆盖四事件。先按实际 manifest 列出另外六事件及其缺失边，从未进入训练、且未用于该规则开发的物理组预约新的开发验证路线；与最终 test、规则独立批准池分别隔离。开发验证一旦用于选优就记录曝光，不再回收为最终 test。旧 val 保留为历史子集。

预约前先完成跨 Phase 交集过滤：即使候选来自 Phase4 既有 val 路线，也要排除 Phase3 训练池、Action 训练池、Phase4 训练池、规则开发/人工曝光组及已登记独立批准池、最终 test 的物理组；不以“尚未被 sampler 抽到”豁免训练池成员。保存候选→排除原因→实际预约的路线清单；过滤后不足则补采或缩小实验声明，不能先审核再发现泄漏。

新开发验证按事件×主要边×YES/NO×静止/运动列支持，至少纳入目标实验影响的格子，并按 §7.3 的精度预算扩样。没有覆盖的事件不得据四事件宏平均选出“十事件更好”的候选；相应 S 实验先限定声明范围或等待补标。弱老师一致率不能填补人工验证缺额。

## 6. 阶段 G1：统一证据时间线，只读诊断

### 6.1 最小记录单元

建议单位是“物理路线 × 事件实例 × 锚点 × 任务 × 输入配置 × 问题”。同一帧允许多个实例、多个转移边，不能用 `(frame,event)` 强行去重。

| 字段组 | 建议内容 |
| --- | --- |
| 身份 | physical_group、route、instance_id、actor identities、event、branch、segment、return policy、split |
| 学生输入 | 有序图像帧号、文件/像素 SHA、完整实际文字、模板/tokenizer/processor 身份、图像 grid、输入合同、必要时 token IDs hash |
| 因果来源 | observed_until、来源文件 SHA、可部署字段来源、上下文/状态是预测还是 oracle、证据缺口 |
| Phase3 | 每锚点原始动作位、eligible/reason、纵向 decision trace、首跨证据、主要动作、KEEP scope、规则及 prompt variant |
| 物理事件 | 单独标定的 onset/confirmation/completion，使用的判定定义、审核区间、左右删失；缺失则 null |
| Phase4 | 事件轴/纵向轴状态、适用边、各 criterion 三态值、raw rule target、入库 target、readiness/catchup、visible scope、执行许可与回执身份 |
| 审计结果 | 事件存在性分歧及原五类原因、主要原因/附加原因、严重度、审核者和证据 ID、处理决定及版本 |

raw rule target、经准入后的监督 target、人工有限输入判断分开保存。不要从已入库 JSONL 反推被弃答和被过滤的全量分母。

**生成分母为所选开发路线的逐帧记录，不是两个抽样训练索引的交集。** Phase3 对每个有效锚点重新运行固定版标定器，并按原 Phase1/2 答案映射及常规事件 gate 恢复 context；Phase4 从所需因果历史起点连续运行固定版老师回放，导出每帧实例及条件。不得每个锚点孤立重启状态机，或用后来实例填补早先检测。帧末未来窗口不足、缺图、无 context、无实例、UNKNOWN 与不适用分别留记录，不用训练配额过滤账本。原题库 ID/是否入库/是否抽中仅作附加字段。

以同一次录制的共同帧轴做全外连接，记录两侧有数据的覆盖、事件存在性覆盖、可比命题覆盖和最终监督覆盖四个分母；帧差仍为 0。缺文件/未回放属于数据缺失，不解释成“无事件”。全量路线可只导出紧凑逐帧字段，精确问题和人工匹配仍限制在已审开发窗口，不因此扩成人工全量审核。

### 6.2 匹配规则

Phase3 当前只有路线、帧与 context，不自带 Phase4 的实例 ID。G1 开始前冻结 `matching_protocol`，先从已有 RGB 审核的开发路线及错例窗口试运行；历史 test 错例仍只作回归，不转入训练。全量路线仅流式生成自动字段和候选索引，不人工展开百万帧上的笛卡尔积。

匹配操作顺序固定如下：

1. 以 `physical_group` 做泄漏隔离，以同一次实际录制的 `scenario/route_id`、源身份与时间基准做逐帧连接。不同 Rep 的同物理组不能按相同 frame_id 当作同一观察。
2. 同时刻事实比较只连接同一锚点（帧差为 0），分别记录两任务图像 offsets；不假定输入相同。Phase3 context 通过冻结映射筛出事件/分支，再核对参与者、行驶方向、目标车道/走廊、实例有效区间及问题适用性。
3. 把 Phase4 instance_id 作为审核关联字段附在 Phase3 记录上，保留关联证据与置信等级，不能伪装成 Phase3 原有真值。参与者不能从 Phase3 证据识别时，不凭场景名补齐。
4. 并发实例逐个保留候选；唯一证据才能确认匹配。关系类型先冻结，再比较答案；先后关系另用连续片段分析，不用最近时间点替换同帧连接。

context→event 的执行依据是 [taxonomy.py](../sft_new_loop_phase4/taxonomy.py) 的 `CONTEXT_TO_EVENT`，同时核对 [Phase3 context 定义](context_taxonomy.py) 的 source_event；分支模板取 `template_for`，实际边集合取 [route_context.py](../sft_new_loop_phase4/route_context.py) 的 `episode_edges`，单边取 `episode_edge`，再检查适用性。冻结这些源码的 SHA，并核对映射一致性。下表是当前常量和边定义的阅读快照，不是另一个手工维护的执行规则；代码变化时重导/检查快照，不依文档表覆盖代码。

| Phase3 context | Phase4 event | 事件边及分支约束 |
| --- | --- | --- |
| LEAD_BRAKE | U-E1 | proceed / complete / re_yield |
| STATIC_BLOCKAGE | U-E2 | default：depart / pass / return / complete；no-return 不含 return；in_lane_pass 改用 proceed / complete / re_yield |
| DYNAMIC_CUTIN | U-E3 | proceed / complete / re_yield |
| VULNERABLE_CROSSING | U-E4 | default 与 cyclist_follow 使用 proceed / complete / re_yield；cyclist_bypass 使用 bypass 边，另核 return policy |
| ONCOMING_INVASION | U-E5 | proceed / complete / re_yield |
| JUNCTION_RULE_CONFLICT | U-E6 | proceed / complete / re_yield；按实际实例检索及条件范围审核 |
| SIGNAL_FAILURE | U-E7 | proceed / complete / re_yield；故障身份不能由普通红灯反推 |
| POST_BYPASS_RETURN | R-E2 | enter / complete；兼容 context 名不能证明曾发生绕障 |
| RAMP_MERGE_EXIT | R-E3 | enter / complete；连接道路不一定有真实跨线 |
| UNSIGNALIZED_PRIORITY | R-E5 | proceed / complete / re_yield；STOP 义务保留，导航/环岛完成边界按实际 route context 另核 |

所有实例另保留适用的共同纵向边 restrict / settle / hold / release / stable / renewed_restriction；recover_follow 及路线相关变体按 [episode_edge](../sft_new_loop_phase4/route_context.py) 的真实定义补入。下表给出边与行为的预期关系，不是动作翻译表；未能落实其适用条件的记录不进入自动矛盾统计。

| Phase4 命题 | Phase3 相关证据 | 预期关系与时序 | 可进入错标审核的证据 |
| --- | --- | --- | --- |
| restrict / hold | STOP、DECELERATE、KEEP 和原纵向 trace | 当前约束与未来采集行为可并存；采集车也可能未遵守约束 | 某一任务自己的定义与同源可靠事实冲突，而非动作未服从许可 |
| proceed / release 类条件 | RESUME、KEEP 或其他实际速度动作 | 条件成立可以先于执行；已经运动也可能保持 KEEP | 持续 YES 下无执行先记延迟/无响应；不能仅因等待过久认定 YES 错 |
| depart / enter / return | 原始首次跨线、方向与目标；主要 choice 可能被 STOP 遮蔽 | 条件→许可→执行分别计时；跨线不一定存在于所有 enter 分支 | 目标/方向与可见事实矛盾，或可靠执行记录与 Phase3 首跨定义冲突 |
| pass / complete | 独立物理阶段完成、旧跨线与速度 trace | bypass 的 pass 是已进入绕行走廊并稳定横移，不是已经越过整个障碍；complete 按分支含义审核 | 不能要求完成帧仍输出 LANE_CHANGE，也不能把 pass 错配为障碍全部通过 |
| recover_follow / stable 类条件 | 连续跟随证据、当前及未来速度 | 稳定跟随仍可小幅变速；不与 KEEP 一一等价 | 检查跟随判据及来源，而非仅比较动作名 |
| catchup | 已确认后继几何/执行事实，仍滞后的控制器状态 | 针对已发生后继事实补问；保留当前相关冲突与纵向限制 | 后继不可见、来源异常或当前命题不成立，不能用未来补证 |

无可靠匹配时记 `unmatched`，多个可能匹配记 `ambiguous_match`，禁止找最近时间点强行配对。差异统计同时列出匹配覆盖率，否则只看容易匹配的题会高估一致性。

新增独立诊断项 `event_presence_mismatch`：Phase3 上游答案映射/gate 与 Phase4 规则实例检测，对同帧是否存在某事件不一致。匹配实例之前，先对共同帧轴统计“两侧均存在、仅 Phase3、仅 Phase4、两侧明确不存在、任一侧未知”；无记录不自动等于不存在。同时保存两侧来源、有效区间、参与者和 gate 原因，防止只统计已匹配交集而漏掉事件召回问题。两侧都有同类事件但对象不同，另记实例身份分歧，不强算存在性一致的可靠匹配。

原五类原因保留：任务定义不同、标签错误、有限输入不可判断、边界不确定、源异常。新增项先独立计数，可与原原因共存；它是上游分歧现象，不预断谁错。审核后再追溯检测漏报/误报、gate 范围、实例生命周期或源异常。真正的标定错误也可能只存在于一个任务中，不要求另一个任务给出相反标签才纠正。S3 应使用该诊断得到的真实事件缺失/错误输入分布，与合成扰动分报。

### 6.3 时间与因果边界

逐锚点重算 Phase3，保留相对当前速度阈值、两点确认、STOP 优先和首次跨线。物理起止另以明确规则/人工证据记录，不用 `T_a-H` 生成标签。

Phase4 保存 YES/NO/UNKNOWN 的完整区间和实例终止原因。参考帧类型必须保留。46 条旧 band 的 `before_frames` 不生成事件级容忍表，也不再把已成立的 YES 往前扩。

连续视频和未来轨迹可以解释物理事实，但不能回填成早先有限输入“已经可见”的凭据。右删失不当作未发生；参与者消失不自动当作走廊释放；图间隔内源异常仍纳入因果包络检查。

时差合同：同时刻连接容差固定为 0 帧；执行等待的观察范围限同一连续明确 YES、实例仍适用的区间，新 NO/UNKNOWN/断档/终止即结束或删失。没有证据支持通用“超过 N 帧即错标”。先在开发训练连续片段校准每类 `lag_alert_frames`，冻结后用于排序审核；未校准填 null，只报告完整延迟分布，不自动分类为标签错。若系统另有响应截止，则单列 SLA 违例。阈值不能利用最终 test 决定，也不能反过来改变条件成立时间。

建议产物：`timeline.jsonl`、`timeline_summary.json`、`discrepancy_queue.jsonl`。通过条件：身份、输入与来源可回溯；抽查每类差异能解释为什么可比或不可比；此阶段不改训练目标。

## 7. 阶段 G2：有限输入与完整证据的分阶段审核

### 7.1 抽样与盲法

先在开发训练路线试标，每个待审事件/转移格以 8 实例、5 物理路线作为发现问题的起点。按 YES/NO/UNKNOWN、静止/运动、分支、距边界、昼夜及源风险分层，加入随机正常题；不能只审模型错题或老师 YES。

第一阶段只展示精确学生输入，隐藏老师标签、模型预测、文件名中的场景答案及未来证据。状态文字若原本就是学生输入则保留，并标注其来源用于事后审计。默认省人力流程为同一审核者“两图→锁定答案及集合→四图→锁定答案及集合→第二阶段完整证据”。两图均为对应四图的子集；Phase4 的 `[-4,0]` 虽非四图首尾，也满足子集条件。换输入合同后重新验证包含关系。

这个顺序可防止额外画面倒灌两图判断，但四图回答可能受两图答案锚定，不能视为独立标注。建议约 20% 的分层子集双人独立审核，两人均走同一流程且互不可见；关键稀缺格设最低双审数量，高分歧格扩审。需估计无顺序影响的四图水平时，另留只看四图的独立子集。试标、作者自审、独立审核分别报告；20% 是预算起点，不是统计充分性保证。

Phase4 第一阶段输出 YES/NO/UNKNOWN、决定性证据、缺失信息。Phase3 输出原行为命题的判断/不确定性；S2b 的集合只能由第一阶段有限输入审核给出，并按两图/四图分别锁定。不能把安全动作建议当作采集行为标签。

第二阶段查看连续视频、相关元数据与异常证据；建立物理事实及其可靠度。元数据与 RGB 冲突时保留争议，不规定元数据永远正确。第二阶段不得利用未来扩大或挑选首轮可接受集合；若发现源异常或任务定义冲突，记录剔除/争议，必要时新版本重新盲审，保留原记录。

### 7.2 统计与处理

| 量 | 定义与限制 |
| --- | --- |
| 有限输入人工不可判定率 | 第一阶段 UNKNOWN / 全部抽审题；是操作性人工指标，不是已证明的模型信息论上限 |
| 人工分歧率 | 独立第一阶段审核者不一致 / 双审题；UNKNOWN 保留为独立类别 |
| 标签争议率 | 原标签与第二阶段可靠事实不一致；不确定物理事实另外计数 |
| 额外证据依赖率 | 第二阶段可确定而第一阶段不可确定的比例；给出分母和所需字段 |
| 完全相同输入冲突 | 相同有序像素、文字及处理合同对应不同 target；核查遗漏输入、身份或标注问题 |
| 近似输入差异 | 用于检索复核，不因图像相似直接认定不可学习 |

Phase3 行为未来本来可能具有随机性。相似输入对应不同未来动作并不自动说明预测任务无效；它提示应评估不确定性和概率。不能承诺只要补数据就一定得到确定答案，也不能仅凭一次人工 UNKNOWN 断言模型绝不可能学习。

| 诊断 | 建议动作 |
| --- | --- |
| 学生需要部署可得的历史 | 单独实验更长历史/过去速度/可验证状态凭据，审计延迟与缺失 |
| 仅特权字段能判断 | 改成有限可见范围命题、外部模块判断，或不提供强监督 |
| 明确错标 | 修对应标定/审核链路，重建新版本，列出逐题变化；不放宽评分掩盖错误 |
| 边界无法判定 | 保留 UNKNOWN；监督排除与评测 coverage 单列，不填半权重 YES |
| 人工确认多个预测均可接受 | 仅进入明确版本的 choice 集合目标；原单目标保留用于历史指标 |
| 源异常 | 按精确因果范围隔离；不扩大成整路线的未经核实删除 |

建议产物：`limited_input_review.jsonl`、`full_evidence_review.jsonl`、`review_adjudication.jsonl`、`learnability_report.json`。本地保存图像与证据；不因本方案上传原始数据或审计包。

### 7.3 人工预算、批准优先级与精度

严格门槛唯一来源是 [teacher_approval.py](../sft_new_loop_phase4/teacher_approval.py)。当前 rule_class 还区分 readiness/catchup，不能只按十事件乘两图数估计工作量；先清点实际待批准类别 C。

| 每个规则类别、每种输入配置 | 当前政策或理想下限 |
| --- | --- |
| 总判断数 | 政策 ≥100；若 YES/NO 全判对，实际至少 73+35=108 |
| 老师 YES 的正确性 | 95% Wilson 下界 ≥.95；全对至少 73 题 |
| 老师 NO 的正确性 | 95% Wilson 下界 ≥.90；全对至少 35 题 |
| 物理路线 | 总体 ≥20，YES 与 NO 各自 ≥20；两组路线可重叠，不等于强制 40 条 |
| 转移附近判断 | ≥30，可包含于上述题数，不另加 30 |
| 人工 UNKNOWN | 保留在正确性分母中，不能删除以通过批准 |

108C 是无错误且满足全部路线/转移条件的理想判断下限，不是包通过预算；例如 C=10 已需至少 1080 个按类别/图数独立计数的判断，实际 C 以清点为准。两图/四图可以共享取图与连续视频复核劳动，但不能互相继承批准；去重规则仍须满足现有审核器。错误、不可判定与稀缺路线都会增加预算，邻帧复制不能补路线缺额。

| 优先级 | 拟定范围 | 预算和去向 |
| --- | --- | --- |
| A，先争取严格批准 | UE1 proceed、UE4 横穿 proceed 的已有可靠分支，先做容量与有限输入可观察性筛选 | 每个实际类别/图数至少按 108 题理想下限预约；缺 20 条 YES/NO 路线则保持弱监督，不承诺本轮通过 |
| B，开发验证优先 | 当前缺人工 val 的六事件，以及待做 S 实验的主要边 | 单列开发验证预算；先补可选优参考，再决定哪些类别追加独立严格批准 |
| C，暂保持弱监督或 UNKNOWN | return、缺分支、稀少 YES、依赖未给学生的权限/历史凭据的类别 | 定向收集真实支持；只让满足既有弱准入的题留在弱训练，不能为凑批准强标 |

“每格 8 实例/5 路线”仅用于发现问题，不足以据不可判定率决定删题、补输入或推广规则。用于决策的格子先登记目标区间半宽 h、预期比例和路线内相关性。独立二项的最保守近似 `n≈1.96²×0.25/h²`，h=.10 约97、h=.05 约385；这只是规划起点，正式按路线聚类、设计效应和实际路线数扩样，不能用同一路线大量帧替代。

预算账本分别列：开发试标、六事件开发验证、冻结规则的独立批准、最终 test、双审及裁决；记录题数、独立路线、两图/四图判断次数与审核时间。开发参考不得重复记作独立批准或最终测试的新增证据。先预审可行性再大规模发卡，避免发出上千张实际无法达到路线门槛的卡。

## 8. 阶段 E：先做容易验收的计算优化

### 8.1 E0：性能基线

记录端到端有效题/秒、有效监督 token/秒、optimizer step/秒、不同锚点与路线数、显存峰值、CPU/RAM、GPU 利用率，以及读取/校验/解码、processor、视觉塔、语言前向、LM head/loss、反向和同步耗时。

已核源码的优先诊断点：Phase4 `train.py` 在每题前向前同步执行 `encode`；`model.py` 内还包括源 SHA/像素身份核验、JPEG 解码、processor 和同步 `.to(device)`，没有后台数据预取链路。分别计时文件读取/核验、解码、processor、等待数据、H2D，不能统称“视觉塔慢”。Phase4 每轮 val 和 Phase3 生成式 val 都由 rank0 串行执行，其余 rank 等待；Phase3 的 teacher-forced loss 验证已经分片/汇总，不应重复改造。报告训练有效时段与含验证/保存的整轮墙钟：生成验证期间三卡等待代表该阶段约 75% 卡时空闲，不代表整轮 75%。E5 处理输入供给，E6 处理生成式验证分片，优先级由端到端占比决定。

CPU 用墙钟、GPU 用 event/profiler 对齐；逐算子同步计时只用于诊断，正常吞吐测量保持重叠。检查每题 `float(loss)`/日志引入的设备同步，任何减少同步的候选仍保持统计与报错检查语义。内核预检、ragged 路径计数和四卡 I/O 争用先于把性能问题归因于 b 太小。

计时分为训练、老师回放/建库、评估生成、运行时多边问答四条路径，分别报告墙钟和调用量。老师回放主要是规则/数据处理，不把其耗时归为模型 generate。当前 Phase4 [评估生成](../sft_new_loop_phase4/model.py) 与 [runtime](../sft_new_loop_phase4/runtime.py) 均使用 `generate(max_new_tokens=8, do_sample=False, use_cache=True)`；记录实际生成 token 数、prefill/decode、读图/processor、解析、控制器提交和完整评估耗时。运行时额外报每帧边数、每题/整帧 p50/p95 延迟及截止错过；E3 在同一问题集合和生成配置上比较，不能只用训练吞吐判断价值。

GPU 异步计时用正确的 event/synchronize 边界；重叠阶段耗时不能直接相加当墙钟。预热、冷/热缓存、输入长度、batch/accum/world、dtype/kernel 均固定。SHA 核验的成本单列，不能以删除身份校验换提速。

在冻结的实际采样题序上，以每个 rank 分别统计同一 optimizer 更新内、同一轮内和跨轮的图像身份复用、复用距离、唯一帧数、缓存命中曲线；全 rank 理论并集另报，不能冒充单卡可用命中率。两 Phase 当前均逐样本前向，`phase3_balanced` 可能把同一步的题分散到多条路线；同一步高复用尚未成立。v40 七轮记录的最大单题曝光 49 次只说明跨步复用值得测，不是 v42 当前重复率，也不是每轮都重复 49 次。

增加 E4 的 B=1/2/3/4 等可行批大小剖析：固定原更新题集，报告有效/补齐 token 数、batch 利用率、各阶段耗时和峰值显存。原更新题数不足以四卡同时增大 B 时，容量探针与 P5 新更新预算分别登记（§8.7）。批处理本身不会自动去重图像，也不会减少每题语言层的有效 token 工作量；四张 432-token 图像仍为 1728 视觉 token 加文字，padding 还可能增加计算。E4 单独测利用率，E2 单独测冻结视觉复用，再测组合；不要把二者收益混在一项里。

以实际缓存命中得到视觉编码比 r、视觉耗时占比 f，忽略其他变化及缓存开销时，单纯视觉优化的理想总加速为 `1/((1-f)+f/r)`。例如 f=.20、r=16/7 时只有约 1.13 倍；这是规划估算，实测还包括 gather/传输及缓存维护。动态图像尺寸用实际像素/grid 和耗时加权，不只数图像张数。P2 改采样后另测，不能拿人为连续锚点的理想比值替代 P0 真实命中率。

#### 8.1.1 FLOPs 只作量级核对，不作为训练时长承诺

冻结线性基座仍需向前传播及向更早的 LoRA 传播激活梯度，稠密投影主项可粗写为 `4 P_mat T`（前向约 2PT、输入梯度约 2PT），不是只算 32.46M LoRA 参数。P_mat 应取在这些 token 上实际执行的投影权重；4B 总参数包含 embedding/视觉等，E1 又只在答案位置执行 LM head，因此直接用 P=4e9 是简化代理。另计视觉塔、注意力/DeltaNet、LoRA、归一化、内核重算及优化器，不能把该代理当严格 FLOPs 下界。

按 [官方 4B 配置](https://huggingface.co/Qwen/Qwen3.5-4B/raw/main/config.json) 与本地投影定义，可将这部分代理细化为下表；它计入门控 q 和 DeltaNet 的 a/b 投影，不含 bias/norm/卷积、LoRA 增量或可选 MTP 分支。

| 每 token 执行的语言投影 | 计算式 | 参数量 |
| --- | --- | --- |
| 32 层 MLP | 32×3×2560×9216 | 2,264,924,160 |
| 24 层 DeltaNet | 24×[2560×8192 + 2560×4096 + 4096×2560 + 2×2560×32] | 1,010,565,120 |
| 8 层普通注意力 | 8×[2560×8192 + 2×2560×1024 + 4096×2560] | 293,601,280 |
| P_mat 合计 | 上述三项之和 | **3,569,090,560（约 3.569B）** |

embedding 权重 248320×2560=635,699,200 不计入逐 token 稠密投影；共享该权重的 LM head 按实际 E1 位置另外计费，视觉塔也另算。4e9 比上述 P_mat 高约 12.07%；换用精细代理时，原 4PT 数字降低约 10.77%，两个百分比的分母不同。它只说明这部分矩阵计算代理的偏差，不说明完整训练 FLOPs 被高估同样比例。

以 P=4e9、T=2000 和用户提出的 148 TFLOPS 峰值作情景计算：4PT=3.2e13 FLOP，峰值相除约 0.216 秒/题；假设有效算力为峰值的 40%，约 0.541 秒/题，每卡 2560 题约 23.1 分钟。148 也见 [MegaScale-Infer 表 3](https://arxiv.org/html/2504.02263v1#S4.T3)，但这不是本次对目标 H20 实际时钟/功率/精度路径的测量。40% 不是实测 MFU，更不是理论下限；模型 FLOPs 利用率与包含重算的硬件 FLOPs 利用率应分开定义，避免把重算重复计入时间。

在上述 4PT 代理上，若完整重算一次前向约增加 2PT，即 6PT/4PT=1.5，按同一有效算力假设约 34.6 分钟/卡/轮；不能直接套全参数训练 6PT→8PT 的约三分之一增幅。非重入 checkpoint 的提前停止、实际检查点范围和 kernel 内重算使真实增幅不同。以上时间均不含数据等待、验证、保存和通信，不能用“约 30 分钟”作为完整 Phase4 一轮的验收上限。

后续估算优先用 P_mat=3.569B：T=2000 时 4P_matT≈2.8553e13 FLOP，峰值相除约 0.193 秒，40% 有效算力情景约 0.482 秒/题、20.6 分钟/卡/2560 题；完整重算代理约 30.9 分钟。前面的 4e9 数字保留作旧估算对照，不能把两组代理当作快/慢后端的实测结果。

B=1、T≈2000 的大投影已经有较多矩阵行，批处理收益可能小；但这不证明小投影、循环/卷积内核或整个训练已达到高利用率。若实测较慢，先核对计算代理、真实长度/grid、后端、checkpoint 和带宽，再通过 E0 判断 I/O、Python、ragged、通信、验证各自贡献，不预先认定原因。

### 8.2 E1：只投影有监督位置

保持完整隐藏状态前向。若目标 token 在位置 j，则用 j-1 的隐藏状态计算完整词表 logits。覆盖全部受监督答案 token、EOS 及原有权重，维持原来的 token/样本/累积归一化。不得重复 causal shift。

本地 5.3.0 vendor 已支持整数或位置下标张量形式的 `logits_to_keep`，E1 不要求升级 Transformers。两 Phase 当前每次前向 B=1，直接抽取该样本全部有效 target 的前一位置即可。E4 一旦启用 B>1，混长行的监督位置映射就是必须同时解决的条件，不能留作后续问题。

本地实现是 `hidden_states[:, slice_indices, :]`，位置张量为整批共用的一维下标，不接受每行独立位置表。可选两条路径：（A）求各行预测位置的并集 U，模型投影得到 `[B,|U|,V]`，再按行位置映射只保留本行监督；其他行的并集位置一律不计 loss，不要把压缩后的相邻位置再 causal shift。（B）取得正确多模态前向后的最终隐藏状态，按 `(row,j-1)` gather 成有效位置列表，再通过同一个 LM head；保留 autograd、PEFT/DDP/checkpointing 的真实路径，不以 `output_hidden_states=True` 连带保留所有层作为必需实现。A 不需改 forward 接口但可能多算，B 需要受控训练适配及验收；两者分别记录投影位置数/显存。均按原样本分母还原损失，不能对展开的所有 token 直接取全局均值。

Phase4 当前只监督答案及 `<|im_end|>`，其训练使用模型内置 loss；E1 应显式计算已对齐交叉熵，复现原 FP32 loss 和样本内有效 token 均值，再沿用现有样本/累积归一化。不能向稀疏 logits 继续传原全长 labels，也不能改成整个更新的全局 token 均值。Phase3 继续保持自己的有效权重分母和精度路径，不借此统一两 Phase 的目标。两个入口的具体落点见各指南。

B=1、L=2000、V=248320 时，BF16 logits 理论存储为 `B*L*V*2/2^30≈0.925 GiB`；不是整体显存或确定可回收量。FP32 loss、中间张量和 kernel 行为另测。

Phase3 还有全位置 argmax 统计，E1 同时改为仅统计原有有效监督位置及各 component。当前 `[:, :-1, :].contiguous()` 在 B=1、原 logits 连续时可能直接返回视图，不能断言必有第二份完整副本；记录实际 stride、分配和峰值。避免全词表投影及其他中间量的综合收益以 E0/E1 实测为准。

保留全词表 softmax 分母；只对候选词表归一化是另一个目标。全 ignored 样本显式跳过有效监督，不能只留 EOS，也不能把 NaN 换成看似正常的样本 loss。

### 8.3 E2：冻结视觉去重与缓存

首版只缓存所有依赖都冻结、确定性的图像编码。确认视觉塔和被缓存的 merger 均无可训练参数或随机增强；若 merger 可训练，只能考虑缓存其之前的冻结结果。不得因模型外层 `.train()` 悄悄启用视觉随机性。

缓存键绑定像素内容、处理器参数、grid、视觉权重/源码、dtype 和缓存层级。图像顺序、placeholder 数量、`image_grid_thw`、multimodal token types、语言侧 M-RoPE 每条序列独立正确构造。不能缓存经过语言层上下文融合的“图像 token”供不同窗口直接复用。

不要求统一两个 Phase 的 system。E0 决定缓存层级：步内命中不足时可直接试冻结特征的跨步/跨轮有界缓存，不必改采样凑连续锚点；这与参数更新后失效的语言前缀不同。GPU LRU、CPU/pinned memory、磁盘分别测容量、传输、命中与端到端收益，纳入失效、损坏恢复与重新核验。重排跨更新题序以提高命中属于 P 实验。任何冻结范围或像素处理变化都使对应缓存失效。

以 merger 后每帧 432 token×2560 维×BF16 计算，单帧 2,211,840 字节，约 2.11 MiB（2.21 MB），1000 帧约 2.06 GiB（2.21 GB），尚不含索引、传输副本和 allocator 开销。动态分辨率/切图须按实际 token 数计费。磁盘读取可能慢于重算视觉塔；只有墙钟净收益成立才采用，不把容量估算当速度证明。

对 K 个、同路线、无缺帧、无风险排除、处理身份一致的锚点，以下为可完全缓存时的理想复用参考（该固定题序的调用量收益上界）。锚点步长与每题内部图像 offsets 是两个参数：

| 输入 | 锚点步长 | 唯一图像数 | 编码次数比，K=4 / 8 / 16 |
| --- | --- | --- | --- |
| Phase3 四图 `[-3,-2,-1,0]` | 1 帧 | K+3 | 2.29 / 2.91 / 3.37 |
| Phase4 四图 `[-6,-4,-2,0]` | 1 帧 | K≥2 时 K+6；K=1 时 4 | 1.60 / 2.29 / 2.91 |
| Phase4 四图 `[-6,-4,-2,0]` | 2 帧 | K+3 | 2.29 / 2.91 / 3.37 |

Phase4 相邻一帧的两个窗口无共同图，但四个连续锚点包含相差两帧的配对，因此整批为 16/10=1.60 倍，并非无复用；取 t、t+2、t+4、t+6 才为 16/7≈2.29 倍。任意采样或排除后用实际图像身份集合求并集，不能套用密集连续公式或当作普遍上界。仅合并 batch 而未接 E2 时仍会重复编码，不能直接获得表中收益。

线上连续滑窗若缓存完整必要历史、视觉编码确定且权重不变，热缓存后可每个新锚点仅编码一张新图。Phase3 相邻窗口直接共享三图；Phase4 逐帧滑动需要保留两组奇偶帧历史（至少覆盖所需的最近 7 帧），只保存上一个四图窗口则不能做到。跳帧、冷启动、掉帧和缓存逐出另计。语言侧每个锚点仍重新处理本题四图，不复用滑出图像已污染的 DeltaNet/KV 末态。

### 8.4 E3：推理公共前缀共享

以同一模型/adapter、同一观察和完全相同 token 前缀为单位；task/edge/state 不同的文字放在各分支，并验证完整模板拼接一致。保留 8 层 K/V、24 层卷积/循环状态、mask、位置和 RoPE 信息。

每个分支有独立可写缓存，分支 A 不影响 B；先冻结一帧问题集合，再整体提交控制器状态，不能问完一题就改变其他题的条件。测试多实例、多目标、不同后缀长度、分支重排和空后缀。

首轮保持原 `generate` 与 parser。将生成改成候选 logits 分类另列实验，否则无法区分缓存收益和解码协议变化。不同 LoRA 不共享语言前缀状态，除非另外证明被共享部分完全没有参数差异。

### 8.5 数值通过标准

先做确定性 FP32 小模型对照，再做实际 bf16/GPU/kernel 对照。对比有效位置 logits、loss 分子/分母、每类可训练参数梯度与一次 optimizer 更新；不能只证明 loss 有限或某个梯度非零。

容差在看候选结果前，结合基线同路径重复运行的数值误差预先冻结。记录最大绝对误差、相对范数误差、梯度方向及参数更新差异；近零梯度单列。逻辑错位、跨分支污染、漏梯度不属于可接受浮点误差。没有目标 GPU 证据时标“CPU 通过、GPU 待验”，不宣称全面等价。

性能在相同题目/权重/更新预算下比较，另报告固定墙钟的能力，不能只提高 batch 就把两个不同训练预算称作等价。

### 8.6 E4：同一参数更新内的独立序列批处理

E4a 保持原 rank 分配，只把原 sampler 已选中、属于同一 optimizer 更新的题组合成 B>1；用户要求的四卡负载均衡另设 E4b（§8.7），允许在原全局更新内重新分配 rank，但不改变全局题集/权重。每行仍是一条完整且独立的“本题图像＋文字＋答案”序列。Qwen3.5 的语言注意力与 DeltaNet 状态保留 batch 维度，无须把多题拼成一条长序列或改模型架构。四图模式每行只装该题四图；同批其他行的较晚图像不属于该行输入。processor 的展平图片列表、grid、placeholder 与行归属必须逐项对齐，不能把唯一图片集合当作每行共有视觉上下文。

| batch 行 | Phase3 连续锚点：该行的四图 | Phase4 间隔两帧锚点：该行的四图 |
| --- | --- | --- |
| 1 | t−3, t−2, t−1, t | t−6, t−4, t−2, t |
| 2 | t−2, t−1, t, t+1 | t−4, t−2, t, t+2 |
| 3 | t−1, t, t+1, t+2 | t−2, t, t+2, t+4 |
| 4 | t, t+1, t+2, t+3 | t, t+2, t+4, t+6 |

两列分别有 7 张唯一图像；每行仍只获取其列出的 4 张特征及自己的问题。此表只是行隔离和复用示例，能否作为 E4 要看这些题是否原本属于同一次更新；不满足则是 P2 的选题设计。

**E4 与 E2/P2 的边界：** E4 本身不减少语言层计算，也不自动去重视觉编码；E2 才把冻结视觉特征按映射复用到各行。即使 batch 内恰好有连续锚点，只要原全局更新题集/权重不变仍可进入 E4；新增邻帧或跨更新调题进入 P2，扩大有效更新 batch 则进入 P5。每 rank 原更新只有一个样本、全局只有四题时，没有四卡每卡 B>1 的等价合并空间；E4b 跨 rank 平衡也不能凭空增加题数。

损失先恢复每行原 `ell_i`，再按旧更新系数求和。Phase3 保留逐样本加权 token 分母及外层 `1/grad_accum`，包含原尾步、超长跳过和 DDP 补齐处理；Phase4 保留逐样本有效 token 均值及当前 `1/accumulation_size`。不要把“batch 均值再除旧 accumulation”当通用公式：一个组有 b 行、原更新 n 行时，Phase4 应贡献 `sum(ell_i)/n`，即 batch 均值乘 b/n。Phase3 当前尾步仍按配置 grad_accum 缩放，E4 不顺手修成实际尾部行数。optimizer/scheduler/裁剪只在原更新边界执行，跨 rank 的同步次数与 collectives 必须一致；按长度分桶只在原更新内部，不改选题或跨更新顺序。

padding 分为正确性基线与速度试验，不能笼统写“左 padding 必然错误、右 padding 只屏蔽 loss 就一定正确”：

| 路径 | 条件与验收 |
| --- | --- |
| 保留真实 padding mask | 本地默认左 padding；补丁会逐行压紧有效 token 后计算 DeltaNet，因此被 mask 的 pad 不推进状态。左/右都可作为正确性参考，但 ragged 路径会逐行执行，吞吐待测 |
| 训练专用右 padding | 每行先形成完整 prompt+答案+结束符，再在末端 pad；不能先 pad prompt 再追加答案。该 collator 局部配置，不改生成入口的全局 tokenizer 默认 |
| 右 padding 的无 linear mask 试验 | 所有有效 token 连续在前，监督均在 pad 前，`use_cache=False`、无旧状态、pad 后不续写，且各行有效位置/M-RoPE 与 B=1 一致。因果卷积/循环的后缀 pad 不反馈到前面的有效输出，才可考虑让线性层处理整批并丢弃末态 |
| 禁止直接迁移 | 左 pad/中间 pad、含 padding 末态的 generate/缓存续写、跨窗口语言状态复用均不适用上述省 mask 条件 |

本地只有一个上层 `attention_mask`，会同时影响 M-RoPE、普通因果注意力和 `_update_linear_attn_mask`，没有独立公开的 linear-mask 开关。若保留普通注意力的真实 mask、仅绕过线性分支，需要局部受控适配，不能声称只改一个现有公开参数即可。另一候选是在纯右 pad、无续写训练下省去上层 padding mask，仍保留模型的因果注意力构造并显式核验有效位置、模态类型与数值；它是待证明的整条前向快路径，不是“只在 loss 屏蔽就足够”的默认保证。等长组可先避免 ragged 开销。首版 E4 的标准 masked batch 可直接使用现有模型入口，快路径和视觉去重分别验收。

E4 验收包括：逐行有效 logits、每行 loss 分子/分母、各可训练参数梯度和一次 optimizer 更新；混合长度、两图/四图、binary 多 span、尾部不满组、超长/全 ignored 处理、图像顺序与 M-RoPE、实际 GPU/FLA。对一行更换其他行的图像/文本、改变行排列、单独执行同一行时结果应一致（在确定性容差内），用来检查跨行污染。padding 统计与有效题/秒并报，不以 padded token/秒虚增吞吐。

默认 LoRA dropout=.05 时，B=1 与 B>1 即使同 seed 也未必为同一题生成相同掩码。先在 dropout=0 做确定性等价；若要验证训练态逐步相等，需按样本/层对齐或重放随机掩码。保留原独立 dropout 分布的普通 batch 可仍是同目标工程优化，但不能把不同随机实现的梯度差异归成浮点误差，也不能承诺完整训练轨迹逐位相同；恢复 .05 后做配对多 seed 回归。不得为了通过测试把实际训练 dropout 默默改成 0；这与 R1 跨分支共用掩码的相关性变化不同。

#### 8.6.1 E4c：变长打包的工程研究候选

本地 ragged 判断只要整批 mask 含 0，就逐行压紧并递归执行 DeltaNet，包括该层投影、卷积和循环核；24 层的这条路径失去跨行 batch 并行，并有索引与同步开销。因而标准 masked E4 首先是正确性基线，不能预期它在这些层有通常的 B 倍吞吐；全 1 mask/等长批仍走批路径。层数占 3/4 不等于耗时固定占 3/4，收益由 E0 逐层测量。

具体同步范围：上层 `_update_linear_attn_mask` 每次前向检查一次全 1 mask 并返回 None，此时后续各 DeltaNet 层不重复做该 mask 判断。不能把 ragged 的逐层/逐行开销套到无 padding 的 B=1 基线。

新增 E4c：把多个独立样本的 token 展平为一个存储流，但保持完整边界。它不共享语言前缀、不减少每题有效 token 计算；与 R0 训练前缀树分开。官方 [padding-free 指南](https://huggingface.co/docs/transformers/main/en/padding_free) 要求线性注意力和卷积显式传边界，不能仅重置 position_ids。边界显式化便于审计，但涉及整条多模态前向，不能预先说它比右 padding 快路径更容易证明正确。

| 通路 | 必须实现并验收的边界 |
| --- | --- |
| DeltaNet | 将累计长度 `cu_seqlens` 传入实际支持的 FLA 前向/反向；每段从独立零状态起步，禁止沿前一题末态继续 |
| 因果卷积 | `seq_idx` 覆盖全部有效 token，段界前的卷积历史不得流入下一题；短于卷积核的题也要验证 |
| 普通注意力 | 变长因果 kernel 使用同一组分段长度/max_seqlen，禁止全流下三角 mask 造成跨题可见 |
| 多模态位置/图像 | 每题独立计算 M-RoPE 与图像 placeholder/grid，再按原顺序打包；不能从视觉网格的 cu_seqlens 推断语言样本边界 |
| loss/E1 | 保存段号与原位置映射；j-1 必须在同一段内，段首无合法前驱时不监督，末题 token 不预测下题；保留每题 loss 分母/全局权重 |

本地 5.3.0 vendor 的语言 DeltaNet 没有传 `cu_seqlens`，卷积显式传 `seq_idx=None`；现有视觉塔的同名参数不是语言打包入口。实施要改 collator、vendor 参数传递及普通注意力适配，或另评明确固定版本升级，不能只换 collator 就宣称生效。[FLA 源码](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/chunk.py) 与 [卷积接口](https://github.com/Dao-AILab/causal-conv1d/blob/main/causal_conv1d/causal_conv1d_interface.py) 展示了相应能力，锁定版本仍须实测。任何通路忽略边界必须拒绝 packed 模式或整体退回已验收的独立行计算，不能静默沿用展平流。

先与独立 B=1 对齐 logits/loss/全部可训练梯度/一次更新，覆盖换序、替换其他题、单独重放、混长/短段、两图/四图、图像归属、checkpoint 重算和真实 GPU；去掉任一边界参数时应被检查拒绝。dropout 按 §8.6 处理。总 packed token 数设单独容量上限，每题输入上限仍保留。该项在 E0 确认 ragged 瓶颈后进入，不能阻塞更便宜的 E5/E6；尚未修改 vendor。

进入 E4c 前还有两项内核硬门，按锁定版本逐项验收，而非只确认参数名存在：

- FLA 当前主分支要求变长输入的物理 batch 维 B=1，逻辑题数由 `cu_seqlens` 定义；q/k/v 维序、累计长度的 dtype/device/单调性、首值 0、末值总 token 数，以及初始状态的段数都要核对。卷积的 [C++ 检查](https://github.com/Dao-AILab/causal-conv1d/blob/main/csrc/causal_conv1d.cpp) 当前要求 `seq_idx` 为连续 CUDA int32，x 为 channel-last 内存布局（逻辑形状仍为 B×C×T），并有通道/stride 的 8 倍数约束；一般 `.contiguous()` 不保证得到所需布局。记录布局转换的拷贝成本，反向路径也验收，不将 FLA 与卷积的边界张量 dtype 强行统一。
- 8 层普通注意力实际 head_dim=256、query heads=16、KV heads=4，需在目标 H20 上验证 BF16、GQA、因果变长、真实长度和 checkpoint 重算下的前反向。不能将“256 维反向只能在特定数据中心卡运行”写成永久规则：[FlashAttention 官方说明](https://github.com/Dao-AILab/flash-attention#nvidia-cuda-support) 已说明 2.5.5 起无 attention dropout 时消费卡也支持。attention dropout 与 LoRA dropout=.05 是不同参数。Hopper 架构兼容性是候选依据，不代替 H20 实测；后端不支持时可能报错或回退，必须记录实际调用，并只允许保留段隔离的回退。

### 8.7 四张 H20：连续锚点段、每卡容量与 E4b 调度

**用户已明确：两 Phase 的目标训练机固定四张 H20，每卡报告显存 97871 MB；sequence 指可配置长度的连续锚点段，每题仍独立两图/四图。** 本会话 `nvidia-smi` 实际仅见一张 RTX 4070 Ti SUPER 16376 MiB，未连接目标 H20，以下为预算与实施决策，不是 H20 实测。若 97871 来自 nvidia-smi 的 MiB 列，每卡约 95.58 GiB；若是十进制 MB，则约 91.15 GiB。上线预检读取实际单位、空闲容量、驱动及四卡拓扑，不把四卡显存相加当作单卡可用量。普通 DDP 每卡保留一份模型。

#### 8.7.1 段长、题数、token 长度与更新预算必须分开

| 名称（建议配置字段，尚未实现） | 含义 |
| --- | --- |
| `sequence_anchors=K`、`anchor_stride=s` | 取数段含 K 个锚点，锚点间隔 s 帧；Phase3 s=1、Phase4 可比较 s=1/2，改变选题属于 P2 |
| `sequence_questions=Q` | 该段实际选中且合格的题数；Q=Σ各锚点选中题数，Phase4 同帧多边/实例时 Q 不等于 K |
| `tokens_i=L_i` | 第 i 题真实 processor 展开后的 token 数，含该题独立图像/文字/答案；max_length=8192 是上限，不是实际长度 |
| `per_device_microbatch=b`、`global_microbatch=4b` | 每张卡一次前向的题数；全局 batch=8/12/16 分别表示每卡 2/3/4 题，不是每卡再启动多个 DDP 进程 |
| `global_update_questions=N` | 一次 optimizer 更新实际包含的题数；满组同权时 N=4b×累积次数，非满组显式保存每波题数/权重 |

段长 K 决定取数/局部缓存/邻帧相关性，不把 K 个题拼成语言长序列，也不默认同时保留 K 题计算图。每个 microbatch 前向后立即反向，释放该图，只累积梯度；可跨波保留的是符合 E2 条件的冻结视觉缓存。若希望一次处理更多段，可在取数队列里交错多路线；段数也不能与一次前向 b 混用。

推荐示例：一次更新从四条不同路线各取一个本地连续的 8 锚点小块，假设每锚点恰好选中一题，合计 Q=N=32，每卡分配一块。各路线 K=32 的较长段作为跨更新的取数队列，不让一个单路线段默认占满整个更新。多边或过滤后按实际 Q 分配，不能继续假定每卡 8 题。四卡采用相同波次表：

| 每卡容量 b | 每张卡的前向波次 | 对应各波全局 batch | 该例一次更新总题数 |
| --- | --- | --- | --- |
| 2 | 2+2+2+2 | 8、8、8、8 | 32 |
| 3 | 3+3+2 | 12、12、8 | 32 |
| 4 | 4+4 | 16、16 | 32 |

三种排法保留同一全局 32 题/权重，可以作 E4 对照。若原 P0 未选这四块题，选择它们仍是 P2，不能冒称恢复原 balance；四路线结构是 P2c 的设计示例，不强制改写 E4 的原更新题集。Phase3 候选 N=16 时可用四路线各四题；实际按 Q 与配额调整。K=32 可作为首个取数队列探针，K=16/32/64 是后续 P2 段长候选，均不是本轮改成的默认采样。

K/s 只控制取数段，不能绕过 N 的更新边界：例如 Q=64、N=32 的段要分两次更新，不为保留整段计算图推迟 step。段可跨更新排队，冻结视觉特征可按 E2 保留，语言状态和训练图不可跨更新沿用。Phase4 s=2 表示同一路线按两帧步长取锚点，不代表改变每题四图 offsets；若要求逐帧覆盖，则保留 s=1 或将两组奇偶子段都纳入明确的选题账本。

#### 8.7.2 E4b：均分题数，再平衡实际计算量

在四个 rank 都处理相同数量真实题的前提下，调度原全局更新题集。记录每题长度 L、图数/grid、预计新编码图像数、读图位置和原损失系数；优先将长度相近的题组成 microbatch，再以每卡预计总耗时分配组。初版成本可用 `a×b×Lmax + c×b×Lmax² + d×未命中视觉工作量 + I/O` 排序，系数由 E0 拟合；全注意力与 DeltaNet 的成本不同，不能仅按 sum(L) 保证等时。相邻小块尽量保持在同卡，但若缓存亲和与负载平衡冲突，以整步最大耗时最小为目标，记录额外编码量。

保留全局题集、原更新边界、每题权重和 optimizer/scheduler 计划；只调整 rank 归属与同更新内顺序。每张卡的 loss 系数应还原原全局目标：若目标为 `Σ c_i ell_i`，DDP 默认梯度平均时，本 rank 反传 `4×Σ_local c_i ell_i`；等量同权才简化为各 rank 的局部均值。Phase3 尾步等旧缩放也包含在 c_i 中，不顺手归一化成另一目标。对应 DDP 梯度平均与同步机制见 [PyTorch 官方说明](https://docs.pytorch.org/docs/2.14/notes/ddp.html)；实际环境版本仍由 G0 固定。

所有卡提前拿到相同的波次大小表，最后同步 backward、optimizer step、评估及保存边界一致；`no_sync` 同时包住前向与反向。预先处理超长/坏图/无监督题，保留基线既有处理；不能某卡临时跳过一次 backward，或单卡 OOM 后自行减 b 继续。尾段/不足四等份的组先按冻结策略排好，E4 不新增有正权重的复制题凑满。任何必要的零贡献占位必须明确标记、计入调度而不计为真实曝光，并通过 DDP 图/同步验收。

动态 b 应由四卡共同计划选取，按本轮最重分组满足显存与同步约束；不让 GPU0 自选 2、GPU1 自选 4 后失去共同波次。等题数仅是基础，CPU 解码、磁盘、通信拓扑与 kernel 也可能制造拖尾，因此均分不能保证完全无等待。

续训以冻结的全局更新题集→rank→波次确定性映射为准，绑定调度算法版本、成本模型快照、seed、题身份及稳定的平局处理。已计划部分直接重放保存的分配表，或按保存输入重算并校验 hash；不得按恢复时的 GPU 负载/缓存状态重新分配。源码细节也需纠正：Phase4 `plan(..., world_size=world)` 产出全局题序与全局题 ID 曝光历史，训练再取 `indices[rank::world]`，不是四份独立的 rank 采样历史；world 参与合同和配额约束。E4b 保留采样历史，新增调度记录，不把 rank 迁移算新增曝光。当前训练保存的是 epoch 边界状态，不冒称已支持任意步恢复；中途恢复需另存完整更新游标、优化器/RNG/采样状态，预取但未消费的题不得算已训练。

#### 8.7.3 容量预算与首轮选择

预算基线为 Qwen3.5-4B、BF16 冻结基座、语言 LoRA r=16、视觉 LoRA off、E1 稀疏投影、训练 use_cache=False。Phase4 当前 gradient checkpointing 默认开；Phase3 默认关，必须分开预算。改变 checkpointing 的性能/数值单独验收，不默认为两 Phase 已相同。

以下为可计算的组成项，不是完整峰值预测：

| 组成 | 每卡预算依据 |
| --- | --- |
| 基座权重 | 按实际参数量 P×2 字节；名义 4×10⁹ 参数约 7.45 GiB，名称“4B”不是精确参数数。初步为基座权重预留 10 GiB，再由实际加载校准 |
| 语言 LoRA 参数/梯度/Adam | 按官方 4B 维度和当前 12 类目标投影估算约 32.46M 参数；若参数、梯度及两个 Adam 状态均 FP32，约 0.484 GiB；独立梯度桶还可能约 0.121 GiB，实际 dtype/bucket 复用另核 |
| 32 层边界隐藏张量 | 仅 `32×b×L×2560×2` 字节；L=2000、b=2/3/4 时约 0.61/0.92/1.22 GiB。只是 checkpoint 边界量级，不含层内激活与重算峰值，Phase3 未开 checkpoint 时不可拿它当总激活 |
| 若仍计算完整 BF16 logits | L=2000、b=2/3/4 约 1.85/2.78/3.70 GiB；L=8192 时约 7.58/11.37/15.16 GiB，内置 FP32 loss 另有开销。E1 后按实际投影位置重新计算 |
| DeltaNet、普通注意力、反向与临时工作区 | 不从 48 MiB 循环末态估计训练激活；按实际 FLA/SDPA/其他内核、L 与 checkpointing 测峰值 |
| 冻结图像缓存 | 每帧约 2.11 MiB；K=32、Phase3 s=1 或 Phase4 s=2 的单路线段图像并集 35 张，约 74 MiB。拆成四块合计 44 张是分卡边界重复；推荐的四路线各 8 锚点示例也为每卡 11 张约 23 MiB、合计 44 张，但不是同路线重复，不应用 35 张作它的去重分母 |

**初步选择：两 Phase 都以每卡 b=4、全局 microbatch=16 作为主性能候选，b=2 起做正确性/容量探针，b=3 作中间对照；不因显存大就把 K 题全部同时前向。** 这是基于上述权重/输出量级与约 91–96 GiB 容量的工程起点，不是已证明的最大 batch。两图/四图、Phase3 binary/choice、Phase4 分别测；不能凭一个分支通过替其他分支定容量。

Phase3 checkpointing off 可另列激活压力情景，但不采用 `34 L b h` 作为 Qwen3.5 预测公式。该系数来源于特定标准 Transformer 的激活记账（见 [重计算论文](https://arxiv.org/abs/2205.05198)），门控 MLP、GQA、24 层 DeltaNet、冻结基座以及 fused 算子保存张量均与其假设不同；冻结参数也不意味着无需保存 LoRA 输入。机械代入 32 层、h=2560、b=4 时，L=2400/4096/8192 分别为 26.74/45.63/91.27 GB，即 24.90/42.50/85.00 GiB。数字仅说明长尾容量压力，不是上界或下界，不能再与表内边界隐藏张量重复相加。E0 分别测 checkpoint off/on 的已分配/保留峰值及耗时，决定是否用重算换更大的 b；不把该选择隐含到 P5 的 LR 扫描里。

| 实际最长有效 token 长度 | 初始容量探针 | 后续决策 |
| --- | --- | --- |
| L≤4096 | b=2 验证后优先比较 4，保留 3 对照 | 以 b=4 为候选；若仍有余量且吞吐改善，可继续试 6/8，受原更新题数约束 |
| 4096<L≤8192 | 从 b=2 起，逐档 3/4 | 特别检查 Phase3 checkpointing off 与长尾激活；不能按短题结果直接放行 |
| 更长输入或更大图像 grid | 单独预算/输入合同 | 不静默截断或沿用这张表 |

初始工作峰值预算取实际每卡容量约 85%（若为 95.58 GiB 则约 81.2 GiB），余量覆盖长尾、通信和临时分配；还须扣除其他进程占用。记录 PyTorch allocated/reserved 与驱动空闲，不重复相加；allocator 缓存不等于有效计算。该预算是调优起点，可据完整长尾测量调整；目标是四卡有效题/秒最高，不是显存填满或用 padding 把 nvidia-smi 利用率做高。

Phase4 默认四卡、每卡累计 8 题时 N=32，上表 2+2+2+2、3+3+2、4+4 可保留原更新。Phase3 默认 grad_accum=1 时原 N=4；若改成每卡 4 题并希望每更新 N=16/32，必须登记 P5 有效 batch 实验，重算更新次数与选优预算，不能标 E4 等价。两 Phase 的运行容量可以相同，但不强行采用相同优化器更新合同。

#### 8.7.4 H20 上的自动选档验收

在目标四卡上固定真实题与长度分位数，覆盖典型、p95、最长、冷/热缓存，分别测 b=2/3/4；每档先预热及完整 optimizer 步骤（含 Adam 状态首次分配），再采集多个完整更新。拟合实测内存/时长随 b、L 的变化，用于下一档预测；长序列/内核可能有非线性，拟合不能代替最长输入实测。比较不同档位时固定全局更新题集和 N；需要扩大 N 才能试更大档时另标 P5。

选择满足原数值门、全部四卡显存预算且全局有效题/秒最佳的档位；差异落在计时噪声内选更稳的较小档。吞吐不升时先定位 ragged padding 回退、FLA/attention 内核、单线程解码、H2D、磁盘和同步，而不是继续增大 K。预取、读图缓存、pinned memory/异步拷贝按实际瓶颈分别试，不能把任何一项收益预先算入。

报告每卡前向/反向结束时间分布、最慢卡决定的整步墙钟、GPU 活跃率、显存峰值、通信及有效题/token 吞吐。`(max(T_rank)-min(T_rank))/max(T_rank)` 可作计算完成时间离散度，不能冒充已测 NCCL 等待比例；通信重叠用 profiler 另看。不保证 GPU 利用率恒为 100%，以减少空等且提升真实吞吐为目标。保存题→段→rank→波次分配及原权重，可从 checkpoint 复现；OOM 调档须全 rank 共同回到完整更新边界重放，不能重复计梯度或曝光。本轮未执行以上 H20 测量。

### 8.8 E5：有界预取与 CPU/GPU 输入流水线

先拆 CPU 编码与设备搬运：后台 worker 只读图、核验身份、解码、processor 和构建 labels/位置，返回 CPU 张量；每个 rank 的主进程负责 pin/H2D 与模型调用。现有 Phase4 `encode` 在函数末尾搬到设备，不能把原函数直接塞进多进程 worker。worker 使用独立 processor/受控线程数，不在 fork 子进程初始化 CUDA；同时检查四 rank×worker 数对 CPU、内存和磁盘的总压力。

题序由冻结 sampler/调度表给出，结果按任务序号消费，不按 worker 完成先后消费；图像 SHA、模板、labels、随机预处理及异常处理与原路径一致。预取队列按 CPU 字节和批次数设上限，pin 的是将搬运的 CPU tensor，`non_blocking` 配合预取流/event 与正确张量生命周期才可能与计算重叠，单独加标志不保证加速。冷缓存、热缓存和失败/尾段分别测；不借此减少核验或改变有效曝光。验收同题输入张量/身份/消费顺序、loss/梯度/更新与恢复一致，再报告数据等待、H2D 重叠和整轮吞吐。E5 首版可在 B=1 上做，不必先实施 E4c。

#### 8.8.1 E5 可选子项：processor 之后预转视觉 BF16

本地 [vendor](../qwen35/vendor/modeling_qwen3_5.py) 的 `get_image_features` 先执行 `pixel_values.type(self.visual.dtype)`，patch embedding 又在卷积前转为 `self.proj.weight.dtype`。因此在两处实际 dtype 均为 BF16、且标准 processor 已完成 resize/归一化/patch 展开的前提下，可以测试 worker 只将 `pixel_values` 预转 BF16，再 pin/H2D；不提前降低 processor 算术精度，不转换 input_ids/grid/labels，也不改源 RGB/像素 SHA。dtype 从实际模型冻结配置传给 worker，不因模型名字含 BF16 就硬编码；若视觉模块实际为 FP32 或链路含其他转换，则保持原输入。

以 processor 输出恰为四张 1152×384 图的情景计算：每图 1728 个未合并 patch，temporal_patch_size=2 时每 patch 为 3×2×16×16=1536 维；四图合计 10,616,832 个元素。FP32 为 42,467,328 字节（42.47 MB/40.5 MiB），BF16 为 21,233,664 字节（21.23 MB/20.25 MiB）。这是每题视觉输入，不是 merger 后特征；实际按 `pixel_values.numel()*element_size()` 记账。pin 在转换后进行，及时释放 FP32 中间结果；worker/进程传递中的双份副本、队列深度和四卡总量另计，不声称整机 RAM 或总 H2D 都减半。

先比较同一 processor FP32 张量经“CPU 转 BF16 后搬运”与“搬运后由模型转 BF16”的视觉入口值，覆盖实际输入值/舍入边界；再比视觉特征、有效 logits/loss、LoRA 梯度和更新。数值门通过才归为 E5 等价优化，CPU 转换耗时及墙钟收益另测。仅看到 `.type()` 不能代替目标 CPU/GPU 转换一致性证据。

#### 8.8.2 身份校验策略候选：默认关闭，单列合同变化

只有 E0 证明重复文件/像素 SHA 校验占比显著时，才评估一次 run 内的校验结果缓存。`inode/size/mtime` 即使加上 device、ctime_ns、解析后的路径，也不是内容身份：原地改写、元数据粒度或保留时间戳、软链接换目标和读写竞争都可能绕过元数据判断。该方案会弱化现有逐次内容核验，不能计入“同合同 E5”收益。

候选须显式开关（建议字段 `identity_verification_policy`，尚未实现）、默认逐次内容核验，manifest 记录策略、键、有效期/失效规则和文件系统假设。命中数与节省耗时单报；元数据变化、软链接目标变化或身份不符立即失效并重新核验，恢复 run 默认清空。验证文件替换、同大小改写、保留 mtime、链接改指等反例，明确哪些无法保证被发现；追加元数据检查不能冒称恢复了原内容保证。

优先比较另一条路径：在有界内存缓存中复用已经核验的精确字节/RGB/processor 结果，键绑定预期 SHA 和处理版本，记录已核验内容的复用。它避免“仅凭 stat 跳过校验却重新读取新字节”，但失效、损坏、源文件变化可见性仍按 E2/输入合同明确，不把缓存视为自动通过。此次只登记策略候选，未启用开关或修改核验代码。

### 8.9 E6：四卡分片生成式验证

先生成与单卡完全相同的验证清单，再按稳定 ID/原顺序分片，不使用会为整除补重复题的 DistributedSampler 默认行为。Phase3 先在全局执行原 `unique_cases`/配额/封顶，随后分片；Phase4 保留全部 val 及原 reference_kind/paired_identity。首版各卡仍逐题 B=1、同一 greedy 解码参数，只改变题的执行卡；各 rank 用本地 unwrap 模型独立生成，不在题数不等的循环里经 DDP wrapper 触发隐式 collective。

生成结束汇总逐题原始文本、解析结果、身份及充分计数，恢复原顺序并检查无缺题/重题，然后在 rank0 调原指标函数。不能平均四卡的 accuracy/macro/比例，也不能每卡各自去重后合并当作全局去重。格式错误、空切片、老师一致率/人工准确率、Phase3 action guards 和 checkpoint 选优规则全部保留；指标之外的 elapsed_seconds/吞吐当然会变化。生成题集、输出 token/文本、解析和整数计数要求与原 B=1 基线一致；loss 等浮点统计用预登记容差。若近似内核造成 greedy 翻转须定位，不能只看宏平均接近就宣称等价。

所有 rank 保存/恢复各自训练模式和必要 RNG 状态；只让 rank0 写报告/保存 checkpoint，并广播一致的选优结果与继续训练状态。空分片也参加最终汇总，错误不能吞掉后以少题指标选优。验收包含周期与 final generation、不可整除题数、少于四题、重复来源、恢复后首个更新；逐题条件独立才可任意分片，未来若有递推状态的序列验证应按完整路线分片。四卡验证理想加速上限约 4，实际受长度不均、I/O、汇总影响；整轮收益按验证占比计算，不承诺训练步骤本身变快。

优先在哪个 Phase 实施由 E0 决定：历史审计包的生成 val 清单为 Phase3 binary 384 题、choice 320 题；Phase4 当前人工 val 273 题、每题 max_new_tokens=8。题数差距本身不足以证明收益，另报实际输入长度、生成 token 数、每轮验证次数（含 final）及总验证墙钟。Phase3 binary 多行输出、验证触发频率可能放大开销，但不能推广成每个 Phase3 分支提示词必然更长。记录 `f_val=验证耗时/整轮耗时`，结合 E6 实测加速估计整轮收益后排优先级。

Phase3 入口当前默认 `DDP_TIMEOUT_SECONDS=3600`，rank0 生成时其他 rank 在 barrier 等待是已确认的代码路径。E6 有望减少这段等待，但仍有最后汇总/保存及最慢分片；不宣称消除了所有 NCCL 超时，首轮不顺便降低 timeout。记录各卡完成/等待分布、错误退出与恢复行为。

所有实验先用开发验证集；最终方案冻结后再做最终留出确认。缺额、排除率和新旧共同题都必须报告。

| 编号 | 唯一主要变化 | 必须保留或额外验收 |

| S0 | Phase3 语义明确的边界标记子集排除监督，是否运行先过诊断门 | 撤回五标记并集默认；先查训练池/曝光分布，配事件×动作等量随机排除对照，原标签及评估分母不改 |

S2 的候选码概率应明确是完整词表概率还是候选集合内归一化概率。首版建议保持完整词表分母，与单目标 CE 对照；若另做候选内归一化则单独命名。集合非空且只含当前合法候选，只有一个元素时退化为单目标。

集合型 loss 允许 `-log Σ p(a|x)`；对多 token 答案需计算完整答案序列的概率，不能只比较首 token。原始真值、人工集合和模型输出分别保存。集合可能使模型总选旧动作，故需要独立报告转换时机，不能靠集合准确率宣称无偏晚。

S1 排除监督会改变训练分布和分母；不是纯计算优化。若 Phase3 多行 binary 某行缺证据，仅将该行 loss mask 掉仍可能通过 teacher forcing 让后续行读取它的虚构答案，必须另行审查目标串；本阶段不随意改其自回归结构。

S0 的证据与三臂设计集中在 Phase3 指南 §6.0：已复核旧审计包五标记并集在错例/正确例分别为 40/108、102/272；带标记与不带标记错误率约 28.17%/28.57%，没有显示边际错误富集。这不证明标记在所有事件内独立于错误，更不支持按旧 test 选子集。S0 先统计全训练池、实际 sampler 曝光及权重，再用开发证据确认语义子集；训练排除量不能照搬旧 test 的 142/380。若不具备机制证据或导致关键支持流失，允许不运行 S0，继续 E/G 工作。

S4 不预设“短跨度更干净”或“四张连续图必然冗余”。运动位移随跨度改变，但视角、自车运动、遮挡和噪声共同影响可观察性；相邻帧也可能提供确认顺序。源画面跳变与真实运动差异分开处理，缩短图像跨度不取消老师仍依赖的历史风险包络。旧 [两图/四图路线 bootstrap](../../checkpoints/phase3_audit_20261008/extended.json) 中 binary/choice 的区间均跨 0，只说明当时未明确分辨差异，不是等价证明，更没测过新 `[-2,0]`。

S4c/d 的共同锚点按最长臂历史及原未来目标窗口的完整性选定，所有臂单独报告来源风险、可观察性和不可判定率，并保留非共同支持的覆盖差异。新 `[-2,0]` 是两套原四图的子集，可继续对该臂采用“两图锁定→四图锁定”；但 `[-2,0]` 与 `[-3,0]`/`[-4,0]` 等不同两图臂互不包含，同一审核者依次看它们会获得输入外历史。各两图臂需独立审核分配或不同实例，不能把“都是四图子集”误当多臂间也无泄漏。Phase3 若追加更长两图臂，还须重新判断是否为原四图子集，必要时单独盲审。

### 9.1 “鼓励早转移”的条件路径

先在独立于设计错例的开发连续片段测量系统性偏晚，区分 Phase3 行为预测、Phase4 条件回答、执行许可及真实执行。预登记延迟主要终点和假放行不得恶化的范围，结合路线聚类区间判断；没有偏晚证据则保持基线，不为体现诉求预先扩 YES。

确认偏晚后依次考虑：（1）相关 Phase 的边缘监督排除，Phase3 的 S0 还须通过训练分布/语义诊断并设置随机排除对照，Phase4 为确有增量的 S1；（2）若迟滞来自已发生后继状态但控制器未同步，单独做已审核 catchup 题权重实验 P4；（3）若 Phase3 choice 仍在人工多解边界偏晚，先验收输出协议，再做 S2b；原语义动作名可沿用，无须先改成代码。每步仅在其诊断前提成立时执行，失败回退或跳过不适用项，不把三项一次叠加。

catchup 加权只能改善后继事实已确认时的状态追赶，不能代替静止 readiness 正例，更不能教模型在条件未成立时 YES。若 readiness 因输入不足或正例缺失偏晚，回 G2/S6 或补可靠正例；若是许可/执行模块迟滞，则修对应链路。Phase3 集合监督不迁移成 Phase4“安全放行集合”。始终保留明确 NO、新冲突否决和双轴约束。

## 10. 如何决定省去哪一道问题

| 情况 | 决策 |
| --- | --- |
| 答案可由部署时已知、可靠且因果的输入唯一确定 | 可由确定性模块计算；不必要求“学生看不出”才省问；检查外部条件错误时的回退 |
| 下游需要该区别，且学生可判断 | 保留或改成更清楚的提问 |
| 下游需要该区别，但有限输入不足 | 补输入/改有限范围命题/外部计算/显式未知，不能强制猜测 |
| 下游不需要，且不影响训练或错误恢复能力 | 可做删题消融；保留原始证据和范围记录 |
| 仅少量测试样本未出现该动作 | 不能推出该事件动作不可能；先审训练总体与分支覆盖 |
| 只有依赖另一道模型预测才能推出 | 不是可靠冗余；需要传播误差评估，不能用真值替代部署预测 |

不要用“可确定、不需要、看不出”三个条件全满足作为唯一删题标准。特别是 STOP/DECELERATE 和汇入加速，即便选择题表面上可折叠，下游仍可能需要其独立含义。

## 11. 阶段 R：训练前缀树研究

当前 [缓存复制](../engine.py) 为推理设计；[后缀梯度测试](../qwen35/tests/test_backend.py) 的相关前缀在 `no_grad` 下计算，尚未证明整图梯度等价。Phase4 默认 LoRA dropout=.05、checkpointing 开启，训练前缀树不能直接套现有推理缓存。

R0 使用同一 adapter、dropout=0、无随机增强，前缀保留 autograd，分支张量以保梯度方式复制，禁止 detach/no_grad 或共享可写存储污染。训练前缀状态在 optimizer 更新后失效，不能跨参数版本复用。

验收覆盖前缀/后缀 logits、loss、前缀及后缀参数梯度、各 LoRA target 的梯度、一次更新、重复迭代、保存恢复；LoRA 初始零权重导致部分梯度天然为零时，要使用能检出断图的非退化测试配置。之后逐项加入 checkpointing、梯度累积、DDP、实际 FLA/causal-conv1d 内核。

R1 才研究 dropout>0。共享掩码改变分支梯度相关性；在适当条件下单分支边缘分布可能保持，但不能声称每步相同，也不能预断影响很小。以多 seed 曲线与开发效果评价。

第一版只组织原同一 optimizer 更新内已选问题，题目、损失权重、归一化和更新次数不变。不增加“免费题”、不重排跨更新顺序、不强制把两个独立 LoRA 合并。

右侧 padding 忽略 mask 仅限有效 token 连续在前、监督在 padding 前、且 padded 末态永不续用；问题先 pad 再追加答案是中间 padding，不满足条件。普通注意力仍须正确处理真实前缀长度、位置和 mask，不能把一层适用的结论推广到整个模型。

按官方 4B 配置，24×32×128×128×4 字节约为 48 MiB 循环状态/样本，另有卷积、普通 KV 与反向激活；分支显存必须实测。token 工作量比例不是吞吐承诺。先记录实际抽样后每锚点问题数，再决定前缀树是否值得实施。

## 12. 阶段 P：采样分布与更新预算实验

P0 在 Phase4 是 v42 实际入口的 `phase3_balanced` 对照，Phase3 则以其冻结 run 的实际采样合同为准。P1 附带题、P2 邻近锚点、P3 桶归一化、P4 已审核 catchup 权重、P5 有效 batch/更新预算分别测试；组合在单因素结果之后。P4 指实验编号，此处不代表 Phase4 的简称。P5 改变训练更新方式，不必改变标签语义；将它列于 P 是为了与同更新等价重排的 E4 区分。附带题必须先通过原来的身份、风险、监督来源和准入检查，不因“已计算图像”就有可靠答案。

P2 由配额选中的主锚点出发，候选方案让每个主锚点最多带 1–3 个邻锚点，整次更新仍覆盖多路线；数量是待登记参数，不是当前默认。Phase4 保持 `[-6,-4,-2,0]`，可研究 t±2、t±4 等同奇偶锚点提高复用；不能为得到连续窗口擅改 offsets。邻帧同样逐题检查实例/输入风险/标签资格，越过边界换实例时不继承上一题标签。

增加邻帧并不必然破坏事件等额配额：可在原事件曝光预算内为邻帧分配名额，或明确扩大预算并做等量对照；不计入配额的“免费附带题”才会静默改变呈现权重。即使事件总量保持，事件内动作/YES/NO、readiness/catchup、路线集中度及每次更新的梯度相关性仍会变，不能称原 balance 已完全保留。P3 桶归一化也不能恢复损失掉的路线多样性或独立信息量。

建议先做固定偏移的 P2a 对 P0，再做仅改变邻帧选择的 P2b（开发证据定义的边界优先）；保留稳定段对照，不因稳定段少见翻转就当成无价值。边界识别不能读取开发验证/最终 test 的模型错误来抽训练题。P2 与 P3 各自验收后才组合，避免同时改邻帧与 loss 分母。每次更新报告不同路线/事件/主锚点数量、各桶有效权重与出现概率、邻帧相关度代理、最大重复及全局累计曝光，配对开发指标按路线聚类。

用户指定的可配置连续段另列 P2c，候选 K=16/32/64，首个调度探针 K=32，s 的定义见 §8.7。每段先展开合格题 Q，再在事件曝光配额内分配；一段有多个事件/多条边时逐题记账，不把整段都记入首锚点事件。短路线、缺帧、无资格题及段尾按登记规则保留短段/过滤，不能复制最后一题凑长段。优先多路线段交错，评估 K 增大带来的每步路线集中度和梯度相关性；不得把均分四卡当作恢复统计独立性。首轮 P2c 固定 N，避免同时改变 P5。

P5 首先解决 Phase3 默认四卡 grad_accum=1、N=4 时不能每卡并行 2/3/4 题的问题。主候选 N=16、每卡 b=4，一波更新；N=32 为后续候选。为了单独比较同一 N=16 下 b 的工程性能，b=2 使用每卡 2+2，b=3 使用 3+1，b=4 使用 4；不能直接拿 b=2/N=8 与 b=4/N=16 的训练效果归因于批处理。Phase4 首轮保持 N=32 的三档调度，不需要 P5 才能采用 b=4。

P5 拆成受控比较与实用调参两层。P5a 保持 LR=1e-5、原曝光题序/总次数/标签/题权重，比较 N=4 与 N=16；这回答固定 LR 下 batch 的影响，仍是有效对照，不能因 LR 未调就称其必然混杂。只是该结果不能代表各 batch 调优后的最佳效果。P5b 才用小型 `N×LR` 网格，Phase3 binary/choice 分开：N∈{4,16}、LR∈{1e-5,2e-5,4e-5}。2e-5 对 N=16 是平方根缩放候选，4e-5 是线性缩放候选，均不保证最优。保留每个 N 的 1e-5 锚点，对照两侧给予同等选优预算；资源不足时报告不完整网格，不将“调优新 batch”与“未调优旧 batch”当成纯 batch 收益。

scheduler 总更新数按实际 N、尾步及每轮题序重算，warmup/衰减以预登记的累计曝光比例或归一化训练进度定义，再映射到 optimizer step。本地 Phase3 实际为 warmup+cosine，默认 warmup_steps=2000；更新数降为四分之一后照搬 2000，会改变 warmup 占比，甚至让全程停在 warmup，必须报告并校正这一设计变化。各臂固定 Adam 其他参数、clip、checkpointing 和输入后端，记录累计 LR/weight decay 差异。Phase4 当前直接 AdamW、未建 scheduler，保持该基线，不顺便增加调度器。N 扩大后更新次数下降是 batch 改动的一部分，不能靠增加训练轮次悄悄抵消。

具体压力情景取 [10/08 历史审计统计](../../checkpoints/phase3_audit_20261008/stats.json)：三轮 binary global_step=9216、choice=7680，train_work_global 分别为每轮 12288/10240。以四卡、原 grad_accum=1、无额外跳过/尾部差异为前提，global_step 才可对应这里的 optimizer 更新数；不是任何 run 都能直接换算。下表是固定曝光、仍用默认 warmup=2000 的反事实，不是新 N 已训练的结果。

| N | binary 总更新数 | 固定 2000 的占比 | choice 总更新数 | 固定 2000 的占比 |
| --- | --- | --- | --- | --- |
| 4 | 9216 | 21.70% | 7680 | 26.04% |
| 16 | 2304 | 86.81% | 1920 | 104.17%，全程未走完 warmup |
| 32 | 1152 | 173.61%，全程未走完 warmup | 960 | 208.33%，全程未走完 warmup |

P5 默认保留各自基线的进度比例：`warmup_new=round(total_updates_new×warmup_base/total_updates_base)`，非整除情形预登记取整规则。这个历史例子中 N=4/16/32 对应 warmup=2000/500/250，binary 保持 21.70%，choice 保持 26.04%；不能把 binary 的比例一律套给 choice。实际 G0 run 的比例若不同则从其自身合同重算，LR 网格各臂使用同一进度规则。若要统一两任务 warmup 比例，另列超参变化。

等曝光、等 optimizer 更新数、等墙钟是三种不同预算：主要比较先用等曝光，其余另报，不能声称三者同时固定。调参只用开发验证集，报告多 seed、收敛曲线、实际更新/曝光/用时及搜索成本。Phase4 首轮仍 N=32、LR=2e-5，不因 Phase3 的 LR 扫描同步改它。新的 N/schedule/采样计划写入新 run，不兼容恢复旧 checkpoint 时另起实验。

定义每题损失 `ell_i` 后，一个可选目标为 `L=Σ_b W_b/N_b * Σ_(i∈b) ell_i`，其中 `N_b` 是整个 optimizer 更新、全部 rank 的有效题数。若还有题权重，分母改成明确的权重和，而不是混用题数。不存在的桶如何处理、是否重归一化剩余 `W_b`，预先定义并记录。

DDP 若梯度默认按 world size 取平均，本地加权和需要相应 world-size 补偿；不能又按局部 microbatch/accum 平均一次。没有某桶的 rank 仍参加同一 collective，尾部更新用实际全局计数。先验证单卡与多卡的同一全局题集更新一致。

桶总权重固定不能消除桶出现概率、桶内抽样概率、路线集中和邻帧相关性的改变。报告实际曝光、有效权重、不同题/锚点/路线、每更新桶出现概率、最大重复、置信来源、readiness/catchup 和静止/运动分布。加权曝光不取代原始曝光账本。

## 13. 指标、时序审计与最终准入

| 层级 | 必报项目 |
| --- | --- |
| 数据 | 完整候选→UNKNOWN/风险过滤→入库→抽样呈现的分母；事件×边×分支×答案×输入配置×来源覆盖 |
| Phase3 | 原标签严格准确率、各动作 P/R、KEEP/INVALID、人工集合准确率与集合覆盖；转换提前/偏晚仅在有对应定义的连续片段计算 |
| Phase4 | 人工参考准确率、事件/边指标、YES precision、NO→YES、readiness recall、catchup recall、UNKNOWN/格式错误及覆盖；老师一致率另报 |
| 序列 | 首次有效回答延迟、执行延迟、漏响应、条件撤销后仍放行、抖动、错误实例恢复、状态停滞、删失及安全许可拒绝原因 |
| 下游 | Action 接口语义及 oracle token 变化审计→固定 Action 的离线 ADE/FDE→预测 token/上下文链路→CARLA 真实闭环；必要制动信息及端到端延迟各层均检查 |

Phase4 `NO→YES / 全部 NO` 是假放行率，`正确 YES / 预测 YES` 是 YES precision，二者分母不同。UNKNOWN 不偷放到 NO 中美化指标；需要保守拒绝时单列系统行为与模型事实判断。

延迟在连续明确 YES 区间内从首个成立时刻开始计。新 NO 结束窗口，后续 YES 新开窗口；UNKNOWN/断档按预定规则删失，不桥接成持续成立。问题已经不适用、实例终止或缺执行回执不能记成“成功零延迟”。分别测模型回答、许可提交和执行确认。

离线预测状态序列仍使用录制图像，不是模型行动改变世界的闭环。先前帧用 oracle 状态/事件/导航的评估应标为条件上界；另测预测上下文与错误事件下的实际链路。

置信区间按物理路线聚类，比较两方案时用同路线配对重采样；帧多不等于独立样本多。低支持格不报虚假的精确百分比，空格为 N/A。开发阶段可重复实验，最终测试前冻结主要终点、退化允许量、错误预算、样本计划与选优规则；不在看结果后补门槛。

严格批准政策与预算集中在 §7.3；路线聚类区间作为补充，不能静默替换批准规则。

### 13.1 Action 的低成本前置验证

当前 [action_token.py](../action_prior/action_token.py) 的动作 token 路径从原始 Phase3 candidate/full map 经稳定 release 投影，明确记录 `source_kind=phase3_oracle`，不是读取 Phase3 模型预测；是否启用还须核对具体 run 合同，不能推广成所有 Action 配置都使用该路径。[稳定 release](../action_prior/phase3_release.py) 不随实验文档自动更新。

先导出旧/新规则或投影在同一离线数据上的 token 差异表，再用固定 Action checkpoint、相同 RGB/其他先验、相同轨迹参考比较 ADE/FDE、停止/恢复分层表现。若 token 词表或语义不兼容旧 Action，先报告接口不兼容，再单列等预算重训 Action 的迁移实验，不强行比较不合法输入。Action 训练与评估也遵守联合物理组隔离。

S0 只排除 loss，S2b 只增加集合目标且保留原单一标签时，oracle token 可以完全不变；不能宣称“任何 Phase3 训练语义变化都会改变 token”。先做差异核验：不变时 oracle 对照只是负控制，无法衡量预测模型改善；还需接入有来源合同的预测 token 评估。不得把集合任意挑一个动作写入 oracle。真实规则/投影变动才需要新 oracle token 下游结果，并显式迁移 release/映射合同。预测 token 的接口验收和闭环是后续独立工作，不冒称已接通。

## 14. 依赖顺序与交付物

核对日期为 2026-10-08。以下 main 链接会变化，实施升级前必须记录选定 release/commit 与源码 SHA，不能把检索到的主分支当作本地已经具有的能力。

- [Qwen3.5-4B 模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)：模型与标准用法；结构化任务仍保持本地验证的非思考模板，不能混入思考输出。
- [4B 官方配置](https://huggingface.co/Qwen/Qwen3.5-4B/raw/main/config.json)：32 层、3:1 混合注意力、卷积长度 4、32 个 value heads、128 维线性状态、词表 248320。本文的状态与 logits 内存数字是按这些维度计算的理论值。

- [5.3.0 官方损失实现](https://github.com/huggingface/transformers/blob/v5.3.0/src/transformers/loss/loss_utils.py)：`ForCausalLMLoss` 对 logits 转 FP32、做 causal 对齐；未传总 item 数时按有效 token 平均。Phase4 E1 显式 CE 对齐该路径，并保留外层样本累积方式；Phase3 自定义权重目标单独复现。
- [当前官方模型源码](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py)：可见预编码视觉特征与 DeltaNet 分段参数传递。分段打包仍须卷积、循环状态、普通注意力、位置和 loss 全链路隔离；不等于重叠窗口共享。
- [固定 5.3.0 上游目录](https://github.com/huggingface/transformers/tree/v5.3.0/src/transformers/models/qwen3_5)：仅是本地 vendor 的上游起点，实际行为还取决于 [本地补丁说明](../qwen35/README.md) 和 [模型副本](../qwen35/vendor/modeling_qwen3_5.py)。

- [Transformers 缓存说明](https://huggingface.co/docs/transformers/main/en/cache_explanation)：通用缓存面向推理；不能据推理缓存可用就推断训练梯度可靠。
