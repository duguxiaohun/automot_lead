# RGB 审计候选四组完整训练

本轮把 `v23_rgb_stage_candidate_20261006` 接入训练、loss 验证、生成验证、final 验证、独立推理及审计包。它修订当前阶段与历史趋势、短暂近零与持续停车、先减速后恢复、持续加速与孤立峰值、正常跟车恢复等措辞。动作阈值、标签定义、STOP/首次跨线的主要动作优先级、原采样与选优规则保持 v23。原版提示词仍是旧入口的默认值；新四组入口显式选择候选。Action 冻结发布和 Phase4 未修改。

这是一组新的完整训练实验，不是已经证明有效的版本晋升。无需先训练旧 adapter；训练后用新 adapter 回放旧题。真实 4B/GPU 效果尚未验收。

## 一条命令启动

在训练机已有完整 Qwen3.5-4B、本地数据和四个原审计包，且已激活 Qwen3.5 运行环境后，从 AutoMoT 目录运行：

```bash
bash qwen3vl_local/sft_new_loop_phase3/run_four_full_trainings.sh \
  --model-dir /absolute/path/to/Qwen3.5-4B \
  --gpus 0,1,2,3
```

依次训练：4rgb binary、2rgb_endpoints binary、4rgb choice、2rgb_endpoints choice。四组复用指定 GPU，顺序执行；每组四卡 DDP，而非四组争用同四张卡。单卡用 `--gpus 0`；并未完成本机 16GB 显存可行性或吞吐验收。

保持原训练预算：3 epochs、focus_balance_count=1024、lr=1e-5、seed=20260904，max_steps/max_frames 均为 0（不限截断）。这是原采样策略下的完整训练，不承诺所有候选题每轮都被采到。实际每组采样容量、过滤数、不同题数写入 sampling 日志。可用 `NUM_EPOCHS=... LEARNING_RATE=...` 等显式环境设置覆盖，最终配置保存于 suite.json；同一套四组使用同一配置。

先查看计划或只做检查：

```bash
python qwen3vl_local/sft_new_loop_phase3/four_runs.py plan
python qwen3vl_local/sft_new_loop_phase3/four_runs.py prepare
python qwen3vl_local/sft_new_loop_phase3/four_runs.py check --model-dir /absolute/path/to/Qwen3.5-4B --gpus 0,1,2,3
```

`prepare` 不加载模型，原始 meta 核验按独立路线并行（`--workers`，默认 8；0 为串行），构建索引、核对原始轨迹/RGB 路径和四组实际采样；`check` 还要求完整本地模型、固定运行依赖、GPU 及旧审计题实际 RGB SHA 检查通过；`run` 自动执行这些检查，再开始训练。无需手工先跑 prepare。依赖以 `qwen3vl_local/qwen35/requirements.txt` 为准；本机测试环境有 torch，但缺 transformers 和完整权重，不能据 CPU 测试声称模型就绪。

默认数据位置：`checkpoints/sft_new_loop_phase3_data_rgb_stage_20261006_isolated/frame_index.jsonl`。缺失时自动全源构建；已有时核验后复用，不静默覆盖。可用 `--index` 指向同合同的已构建索引。源数据/collection 用 `--data-root`、`--collection-dir` 指定；原审计包所在目录用 `--audit-root` 指定。回放原包的相对 `lead_data/...` 路径以 `--automot-root`（默认代码所在 AutoMoT）解析，迁移机器须保持该布局或指定相应根目录。

## 曝光隔离与数据变化

四个原审计包的 **118 个物理路线组**已用于开发审计，但原 v23 构建器的 1,779 组登记未包含它们。本轮将 118 组写入独立资产 `development_route_groups_rgb_stage_20261006.json`，只在新实验的构建入口通过 `--development-groups-extra` 显式接入，强制 train-only；所有重复采集及 Rep 同组隔离。训练准入要求这一资产的完整指纹，加载预检再次检查所有行。

首次按原 v23 构建器重建的诊断索引 `sft_new_loop_phase3_data_rgb_stage_20261006` 有 12,360 行，test 与旧包重合 104 组，**不得用于候选训练**。它保留作诊断，不伪装为独立留出；其 prepare 在发现泄漏后主动终止。最终入口仅使用带 `_isolated` 后缀的新构建：train 11,100 / val 420 / test 768，共 12,288 行；本轮曝光组与 val/test 重合均为 0。

当前源数据重建规模本就与旧训练机产物不同，新增曝光隔离又会改变划分和均衡采样池。四组共用同一新索引，不宣称它与旧训练完全同数据。suite.json 记录旧／新计数与划分摘要差异；同题旧模型／新模型比较可衡量结果变化，不能单独归因为提示词。

候选数据保留原动作标定语义，不因为模型错题改变真值。逐帧发现的三处异常登记于 `rgb_stage_risks_20261006.json`，用于回归分组及排除“仅修复异常题”的晋升结论；不会凭异常记录自动改标签。未知控制输入依赖仍是已知局限，见 [RGB 审计报告](RGB_AUDIT_20261006.md)。

## 每组自动产物

默认套件输出 `checkpoints/phase3_four_runs/<timestamp>/`，也可 `--output /new/directory`。已有套件目录拒绝覆盖。保存代码快照与 SHA、数据 SHA、四组完整配置和状态；每组有独立 train、eval、旧题 replay 和 regression_gate.json。

每组训练后：

1. 在新 test 上运行 base／LoRA 同提示词评估及错误审计包；best 仅由 val 选择。
2. 使用选中的新 adapter 回放对应原包全部题目，共四组 2,022 题。无需旧 adapter 权重，旧模型预测读取原包。
3. 重新解析输出，逐项核对题目、真值和因果 RGB 身份，保护全部 1,440 条原成功题及错误题中原正确的答案位；异常重叠单列。
4. 回退或没有非异常题收益，gate 不通过。结果保留，继续下一组独立实验；不会自动替换 v23 或 Action。gate 通过也只代表已观察开发题结果，不能保证未见场景不回退。

原包是已曝光开发回归集，不参与 val checkpoint 选优，不再称盲测。新 val/test 的同道路结构错误事件负例（same-RS）支持仍为 0，沿用原版“支持不足则不纳入该子组 guard”的规则，不宣称这一子组已独立验收。新留出集未进行本轮逐帧人工审阅，指标仍是对原规则标签的准确率。CPU 单测与程序读取不能算新增 RGB 目视审计。

如果某组因运行错误中断，原目录不覆盖，也没有 optimizer resume 功能。查看日志解决后，用新 `--output` 和 `--groups 4rgb_choice 2rgb_endpoints_choice` 等指定待跑组；已完成组保留。单纯 gate 不通过不需要重跑。
