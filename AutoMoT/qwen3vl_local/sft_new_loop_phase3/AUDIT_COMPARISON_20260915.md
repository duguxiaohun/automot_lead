binary 验证371题，choice验证219题。四图 binary val loss 0.1736→0.1249→0.11975→0.11952，生成 exact 末段仍上涨，没有明显持续退化。两图 binary loss 在6000最低0.12005，8000回升0.12271，但生成 exact仍上涨。choice 两组 loss 在4000最低（0.28782/0.28236），6000回升（0.30042/0.30763），生成 exact 同时继续上升；只能说 loss 与生成指标开始分离，当前曲线不足以宣称严重过拟合。

两组 binary 都评 final step9216；两组 choice 都评 best_generation step6000。训练每轮全rank呈现 binary12288、choice10240，均3epoch；step按rank本地处理样本计数，不等于 optimizer 更新。上轮 world_size=2，这轮4，因此本轮 step 数约减半不能直接解释为训练呈现预算减半。binary/choice 最终用于测试的选中保存点及数据筛选不同。

**binary 验证覆盖使 best 无法通过：** 两组每次 generation val 只有1条同RS错事件独立路线，而guard要求至少2条；两组 fallback step8000 的该组 exact=0，还分别有 invalid/横向召回或NONE指标失败。没有best时pipeline按现有规则评final，不是拿到了通过全部guard的best。

20260915预算修复确实生效：binary loss-eval 的每类请求16自动扩至26，实际312题，generation每类32未扩容、呈现384、去重371。它修复的是负例分配预算，不会增加真实独立路线。

最终 test 的同RS错事件在原索引中就是0题；95%=76/80完全来自 wrong_road_structure，不能评价同道路错误事件拒绝能力。四图test还因NONE45.95%<50%失败；两图还因DECEL recall48.11%<50%失败。choice通过的是自己的单动作guard。

## 8. 建议优先级

1. 完整 binary 任务先处理验证/测试同RS错事件独立路线覆盖，再审查 NONE 误触发、DECEL/STOP/RESUME 的阶段混淆与联合动作；不能靠放宽guard把覆盖缺口变成模型能力。
2. 若应用确实保证前提有效且恰好单动作，两图 choice 可作为当前节省输入的候选；总分持平、验证更快，但右变道召回与合流/出口弱项需在独立样本上继续验证。
3. 未来重新测试显式 CASES_PER_BIN=0，并在 manifest 中核对实际独立题覆盖。跨版本严格比较要冻结独立测试协议；旧测试已经用于规则开发，不能重新当未暴露holdout。
4. 本报告只读已有指标、元数据与逐题结果，不改模型、prompt、规则或原始审计包；未启动训练/仿真，也未执行新的逐帧RGB人工审计。若进一步根据本轮错例修改规则，按项目约定管理开发路线隔离。
