## 1. 任务定义与当前边界

Phase3 预测录制车辆在当前锚点之后的速度动作和首次车道边界跨越。它不直接回答“当前是否允许执行”。离线未来轨迹可提供预测目标；学生输入仍只能使用当前和过去的可部署信息。

当前纵向判定有 2 秒窗口、1.5 秒停车确认窗口、连续采样确认、相对当前速度阈值和起步例外；横向检测未来 3 秒内首次真实跨线。choice 投影沿用 STOP > 首跨 > 速度变化 > KEEP；binary 保留原始纵向/横向命题，允许不同轴同时 YES。KEEP 是证据完整时的正向保持，不是 UNKNOWN 的替代。[标定器](trajectory_action.py)、[原始投影](primary_action.py)、[choice/binary 语义](choice_semantics.py)

保持 `INVALID_ACTION_CONTEXT` 表示前提被可见证据反驳；夜间、遮挡、不知道动作和没有阶段转换不是 INVALID。当前 choice 的无效上下文不进入普通动作选择训练，不能因此只报告正确事件输入时的上线能力。

历史基线四图 `[-3,-2,-1,0]`、两图 `[-3,0]`，跨度均为0.75秒；新增显式短两图 `[-2,0]` 为0.5秒，不覆盖旧模式。图像配置切换须沿用同一组锚点和数据身份。[输入合同](history_rgb.py)

## 4. P3-G1：时间线与错例归因

### 4.1 必须保留的两种时间

`anchor_decision` 保存标定器在各锚点的输出：速度基线、阈值、first_drop、gain_start/gain_confirmed、stop_start/stop_confirmed、current_wait/pullaway、mixed_phase、lane_crossing 和 eligible/reason。

`physical_episode` 单独保存审核确认的动作起止、确认点、定义及删失。相邻锚点的相对速度基线变化可能使标签翻转，但不对应新的物理动作；不从 label run-length 直接生成物理分段。

在选定开发路线上逐帧运行标定器并恢复原 context 来源，不能只读配额抽中的训练索引。Phase4 同时连续回放老师，再按总方案 §6.1/§6.2 的共同帧轴全外连接，帧差为 0；不足窗口、无 context、未知和缺数据留记录。不得为获得可比标签，把仅 Phase4 检出的事件强塞入 Phase3 作为其原始事件。

Phase3 没有原生实例 ID，先用同一次录制/锚点及 `taxonomy.CONTEXT_TO_EVENT` 映射，再核对分支、目标和参与者，把关联 ID 与证据单独保存。并发实例无法唯一确认时保留 unmatched/ambiguous。先独立统计 `event_presence_mismatch`，再对可比命题做原五类归因；该上游分歧为 S3 提供真实事件缺失/错误输入测试。首轮人工仅覆盖已审开发路线和错例窗口，全量仅生成自动字段。

### 4.2 审计优先队列

| 现象 | 检查顺序 | 禁止的快捷修法 |
| --- | --- | --- |
| DECELERATE 被预测 STOP | 核对停车确认是否跨 1.5 秒、其余速度轨迹、当前视觉与 prompt | 把所有早停车都判对，或扩大窗口吸收错例 |
| STOP 被预测 RESUME | 当前是否已确认等待、控制释放与两点增速证据、未来起步与当前状态区别 | 因后面起步就把当前等待改为 RESUME |
| RESUME 被预测 KEEP | 明显增速证据、当前速度、汇入阶段、未来行为是否有限输入可判断 | 为提高准确率直接 RESUME→KEEP |
| LANE_CHANGE 被预测 STOP/DECELERATE | STOP 优先是否适用、是否真实首跨、原始复合证据、绕出/返回区别 | 把所有横向事件都改成变道 |
| KEEP 被预测动作 | KEEP 所在题域、证据是否完整、阈值附近变化、并存实例 | 用“事件尚未结束”否决 KEEP |
| 事件正确但动作不在候选域 | 分支缺失、候选规则错误、事件多义性 | 删除样本而不报告覆盖损失 |

旧 16 个 DECELERATE→STOP 中只有 6 个在已有窗口记录停车起点；另 10 个只能进入进一步证据检查。现有记录不能支持固定“可修回题数”。旧错误集中于少数路线时，要按物理组报告，不把邻帧数量当独立证据。

产出建议：`phase3_timeline.jsonl`、`phase3_discrepancy_queue.jsonl`、`phase3_relabel_proposals.jsonl`。最后一份只能记录提议、旧新依据和状态，不自动写回目标。

## 5. P3-G2：可学性与边界标注

第一轮只给真实模型输入，包括图像、当前速度、目标点、场景文字和原问题域；它们必须与对应 run 渲染一致。审核者回答原任务，不回答安全建议。无法判断未来行为时标预测不确定，不强制选其认为“更安全”的动作。

按总方案 §7.1 先两图锁定、再四图锁定，之后第二轮才开放未来轨迹/连续视频检查采集事实；约 20% 分层独立双审用于估计分歧，稀缺格按预算扩审。S2b 集合也必须在各自第一轮锁定，第二轮不得用未来修改“可接受”。速度变化、跨线真值与学生可观察性分别裁决，不用四图证据给两图定确定答案。

对集合标注区分：

- **目标事实不确定**：源证据不足，不能确定采集车发生了什么；原则上不作确定监督。
- **有限输入预测不确定**：物理目标明确，但给定图像无法确定未来；可研究概率预测或排除强监督，不自动宣称多个事实均为真。
- **预测任务允许多解**：经预定义容忍口径与人工证据确认，多种回答在该精确输入上可接受；才进入 S2b 的集合标签。

第三类是明确的任务扩展。它和严格录制行为标签并存，不能用集合结果替换原严格指标。若没有足够可信集合标注，S2b 保持暂缓，不为实验凑非单元素集合。

## 6. Phase3 语义实验设计

### 6.0 S0：先诊断，再决定边界排除实验

**撤回“五个 flag 任一为真即排除”的默认设计。** 本轮从 [20261008 四图 choice 审计目录](../../checkpoints/sft_new_loop_phase3_20261008_095809_951587_4_4rgb_choice_audit_bundle/audit_bundle/lora_production) 的四份 `cases_rank*.jsonl` 只读重算完整 380 题；case_index 全部唯一，五字段无缺失，正确/错误按原 `all_ok` 划分：

| 标记 | 错例 108 题 | 正确例 272 题 |
| --- | --- | --- |
| 五项并集 | 40（37.04%） | 102（37.50%） |
| subthreshold_drop_present | 23（21.30%） | 75（27.57%） |
| isolated_near_stop_in_1_5s | 13（12.04%） | 16（5.88%） |
| stop_pair_crosses_1_5s_boundary | 5（4.63%） | 6（2.21%） |
| first_drop_single_sample | 5（4.63%） | 5（1.84%） |
| gain_unconfirmed_at_2s_boundary | 2（1.85%） | 12（4.41%） |

带标记错误率为 40/142=28.17%，不带标记为 68/238=28.57%，相差约 -0.40 个百分点。正确例中比例相同，五标记并集在这份历史样本里不预示更高错误率。它既不是“预计可修回 40 题”，也不证明各事件内部或其他数据中绝无关联。历史 test 已参与设计，仅可提出假设；不能据单个标记约两倍的历史比例选择排除名单。全题标记率 142/380=37.37% 也不是训练池的排除率。

先按 [trajectory_action.py](trajectory_action.py) 的实际布尔定义区分语义，不按错例排名：

| 标记 | 实际含义与 S0 地位 |
| --- | --- |
| stop_pair_crosses_1_5s_boundary | 两点停车确认跨过 1.5 秒边界，且窗口内无完整确认；优先做窗口边界候选诊断 |
| gain_unconfirmed_at_2s_boundary | 窗尾增速达阈值、前一点未达；属于增速确认的窗口边界候选，不能因历史错误少就剔出诊断 |
| isolated_near_stop_in_1_5s | 窗口内（含当前点）有近停点，但无两点停车确认；是确认不足，未必紧贴时间边界，单列开发审核 |
| first_drop_single_sample | 首次降速达阈值，下一点未维持；是瞬态证据，未必贴近阈值，不自动当不可靠标签 |
| subthreshold_drop_present | 任意大于零且未达阈值的降速，不要求“接近阈值”；不纳入首版边界排除候选，仅保留诊断统计 |

前置产物建议为 `phase3_boundary_distribution.json` 与开发诊断记录。固定源码/训练 manifest 后，同时统计原候选池、准入训练池和实际采样呈现三层：每个 flag、交集/并集、字段缺失，以及按事件×原主要动作分层的题数、比例、原始监督权重、有效 token、锚点和物理路线数。并列候选排除前后各类别占比、稀缺格支持和重复曝光变化；缺失 flags 记 unknown，不能当 False。按实际 sampler 的完整计划/历史计算有效权重，不只数去重题目。

由代码语义和开发训练路线的有限输入审核确认一个较窄子集，冻结其逻辑、纳入理由及开发验证主要终点后才登记 S0；必要时不同机制分开实验。标记代表规则敏感性，不等于真值错误；若机制证据不足、候选范围过宽或关键动作/路线支持大量流失，就不启动。任何比例/支持阈值在查看候选效果前登记，不从旧 test 倒推。

训练至少有三臂：A 原监督，B 已冻结语义子集排除，C 按事件×原主要动作匹配 B 的排除数量、随机挑题排除。C 从同一准入池按预登记 seed 抽样，允许与 B 自然重叠并报告重叠率，不用模型错误挑 C。B/C 都按题身份作用于其所有重复曝光；同时核对实际曝光权重、有效监督 token、路线集中度和优化步数。匹配容量不足或曝光不等时显式记录，不能只称“题数一样所以全部等价”。可行时预登记路线分块匹配以减少路线混杂；多组随机排除 seed 与训练 seed 配对比较，避免偶然抽样决定结论。

B 对 A 衡量总效果，B 对 C 检验是否优于同类别等量减数据；都在固定完整开发验证集上比较，按路线聚类报告区间。如果 B 仅胜 A 而未稳定胜 C，不能归因于去掉边界噪声。没有收益或退化超预登记范围则回退；不把已排除题从评测分母删除。

首版只在单目标 choice 上排除整题监督，包含答案和结束符；原始标签、候选库、阈值与 oracle 投影保持。binary 的多行 mask/teacher forcing 另审。三臂固定起始 checkpoint、底层计划题序、种子和归一化约定，报告每步有效题数及实际更新；默认不补抽。全空更新按预登记合同处理并报告，不能宣称有效预算天然相同。若另试补抽或等有效监督量训练，单列预算对照，不混入首版结论。

### 6.1 S2a：保留语义输出优先，编码须单独论证

当前 [prompts.py](prompts.py) 明确要求输出完整列出的动作名，`choice_options` 稳定随机打乱候选顺序；字母答案不满足现有 parser/监督合同。原约定避免把语义学习变成位置字母选择。新代码协议是对此约定的显式修改，动机只能是经验证的计分/计算便利或效果收益，不能声称集合监督必须使用 A/B/C。

按以下顺序评估协议：

1. 在真实 assistant 边界、空白/换行和实际 tokenizer 下检查所有合法语义动作名是否单 token；若全部满足，直接保留。只部分满足时不能对全部动作统一用首 token 打分。原动作名多 token 仍可计算完整答案序列概率，作为保留原协议的基线。
2. 确需简化时，另试“动作→固定非字母代码”的全局映射；映射不随题或候选顺序变化，候选显示继续按原策略打乱。验证代码确为单 token、互不混淆、EOS/解析及动作还原一致；任意代码也有 token 先验偏差，非字母不保证无偏。默认不扩 tokenizer 词表；若新增 token/训练 embedding，须另记模型参数与预算变化。
3. 随题打乱的字母映射最后才考虑，需额外测映射错误和位置偏好。不能同时修改代码、顺序和集合目标后把收益归给集合监督。

协议实验仍用原单一真值，保留完整词表概率和相同监督预算约定。比较格式准确率、动作准确率、换序鲁棒性、序列计分成本及下游解析；收益不足则沿用语义动作名。受限解码若新增也单列变量。

### 6.2 S2b：集合型目标

单 token 语义动作名或代码下，可接受集合 S 的目标为 `-log(sum(p(token_a|input) for a in S))`。首版明确使用完整词表概率；EOS 项若保留，沿用一致权重并说明集合分支下的定义。不能为多个可接受答案任意选一个后缀，再称其为完整集合序列目标。

如果答案仍是多 token 动作文本，使用完整答案序列概率，需要为候选序列打分；可行但计算成本不同。不同首 token 只能帮助区分代码，不足以表示任意完整文本答案。

检查 S 非空、元素全部合法、标注来源绑定当前图像配置且来自第一轮锁定记录。单元素样本应还原对应单目标；多元素样本的梯度需符合所定义的概率和。报告集合大小、事件/动作/路线分布和旧动作偏好；第二轮仅核对物理事实和源有效性，不能扩大集合。

### 6.3 S3：事件条件候选集

优先复用现有问题域，再研究更细的事件/分支规则；不能从少量 test 的“某动作没出现”推断其不可能。UE2 没有独立 RESUME 的历史测试分布只是假设来源。

候选域裁剪需分别保留：原始动作位、全局主要动作、裁剪后的候选列表、范围外真值标记、投影版本。真值不在域内时是可测的覆盖失败，不能默默改成 KEEP；排除训练题也要统计其行为类型和下游影响。

测试正确事件、预测事件、错误事件、未知/多实例输入。若 choice 接口没有拒答项，可通过外部已有验证/回退路径处理，但新增路径必须单独设计；不能说“binary 保留 INVALID”就自动解决只部署 choice 时的拒绝能力。

### 6.4 S5：动作折叠暂缓

不默认合并 STOP 与 DECELERATE，也不默认把 R-E3 RESUME 改 KEEP。若后续实验确需折叠，先确定是问答展示层、内部状态还是对外 Action token 的变化；给出谁恢复停止/减速、谁提供汇入加速信号。

即使内部仍保留细粒度证据，若 Action 只收到粗类别，仍可能丢失控制信号。必须用接口和下游实验确认，而不是依靠“原始证据还在磁盘里”。

### 6.5 S4c：两图缩短跨度单独对照

保持原四图 `[-3,-2,-1,0]` 不变，比较两图原 `[-3,0]`（0.75 秒）与候选 `[-2,0]`（0.5 秒）；更长臂只在明确开发假设下另登记 offsets，不在首版随意增加。固定共同锚点、原动作目标与模板其他内容，重新绑定图像 SHA、输入合同、风险包络和人工有限输入判断。KEEP/RESUME/减速等动作切片与静止→运动连续片段优先报告，同时报不可判定率和新旧可用覆盖。

短跨度不是去噪的既定结论：运动位移会减少，遮挡与源异常的影响也可能改变。既有两图/四图路线 bootstrap 区间跨 0 不证明两者等价，也未验证 `[-2,0]`；统一依据见总方案 §9。先用开发验证集决定是否改善，不能直接替换默认输入。

两种两图臂分别都是原四图子集，各自可用“两图锁定→四图锁定”流程；但同一审核者不能先后看两种两图再称双方都只基于其有限输入。按总方案 §9 分配独立审核者/不同实例；更长两图若不属于原四图，也不能套原顺序。

## 7. Phase3 计算优化落点

优先级按总方案 §8.1/§8.8/§8.9：先确认四卡真实 FLA/causal-conv1d/普通注意力内核，再测同步读图/processor/H2D 与 rank0 生成验证占整轮时间的比例，决定 E5/E6 是否先于 b 选档。本地缺快速核会 warning 后回退，包已安装不是实际命中的证据。E5 保持 `_load_images`/`_build_inputs` 的输入与消费顺序，用 CPU 有界预取后由主进程搬运；不把 CUDA 模型交给 worker。

E6 只改尚未分片的 `evaluate_generation_probe`（含 periodic/final）：全局先运行原验证选题及 `unique_cases`，再分四卡逐题生成，汇总原逐题统计后保留 action guards、best/final 规则。`evaluate_loss` 已有 rank 分片与全局汇总，保持该路径；不能笼统说全部 Phase3 验证都在 rank0。训练模式/RNG、空分片和恢复后的下一步必须验收，四卡生成不直接平均各卡比例。

E6 排期按总方案 §8.9 的实际验证占比：历史 binary/choice 生成清单分别为 384/320 题，另核实际生成长度与每轮触发次数，不能只按题数推断耗时。本地 `DDP_TIMEOUT_SECONDS` 默认 3600；并行验证可减少其余卡等 rank0 的时间，但首轮保持 timeout，验证最慢分片、汇总和保存的等待仍受控。

E5 预转视觉 BF16 的数值门见总方案 §8.8.1：本地视觉入口已有 dtype 转换，但须确认实际 visual/patch 权重均为 BF16，在 processor 完成之后只转 `pixel_values`，逐值比对 CPU/GPU 转换，再比特征/loss/梯度。四图 FP32 40.5 MiB→BF16 20.25 MiB 仅适用于指定 grid，不能当作总显存减半。身份校验缓存另见 §8.8.2，默认关闭；不得在预取优化里静默用文件元数据替代内容核验。

E1 使用本地现有 `logits_to_keep`，无需升级；共同位置对齐及数值门见总方案 §8.2/§8.5。当前 [train.py](train.py) `_loss_one` 每次前向一个样本，`active=shift_weights.gt(0)`：将 active 对应的 target 前一位置传入模型，按原 target 顺序收集 logits，保留加权 CE 的权重和分母 `sum(weights).clamp_min(1.0)`。保持当前 autocast/CE 精度行为及各 component，不顺便改成 Phase4 的样本内普通均值。binary 多行 span、格式 token 与 EOS 按原 mask 全部保留。

E4 启用后按总方案 §8.2 处理逐行监督：现有 `logits_to_keep` 是共用一维位置列表，选择各行位置并集再逐行筛选，或最终隐藏状态按 `(row,position)` gather 后投影；binary 的多 span/component/格式统计也要按行映射。每行先算原 weighted loss，再按旧更新系数累积，不能把所有行 token 合并平均。

现路径先生成完整 logits，再 shift/contiguous，并对全位置 argmax 后抽取统计；E1 必须同步将 token_acc、value/format/component 统计移到有监督位置，保留原统计分母及零样本处理。B=1 下 contiguous 不保证发生复制，所以显存回收量以 profiler 为准；检查避免调试输出或指标再触发完整 LM head。

E2 先按总方案 §8.1/§8.3 测量当前实际题序的步内/轮内/跨轮复用，再选有界缓存层级；逐样本前向不保证同一步有收益。不统一 prompt 或历史间隔，不为提高命中跨更新重排题目。记录冻结范围是否包含 merger、视觉 LoRA 是否开启以及像素处理身份；批布局/内核误差仍过共同数值门。

E4 的详细合同集中于总方案 §8.6–§8.7：E4a 合并原 rank 同一次更新已有的题，E4b 可在同一次全局更新内重新均分四卡、平衡计算量，但保留原全局损失系数和题集。如果该 run 每卡 `grad_accum=1`，原四卡更新仅 N=4，不能在四卡都处理真实题的同时得到每卡 B>1；扩大 N 属于 P5。保留当前 `loss/grad_accum`、尾部更新、超长跳过和 DDP 补齐语义，按长度分桶限于原更新。先验证标准 masked batch，再试训练专用右 padding；全序列含答案构造完才在尾端补齐，不修改生成默认。局部补丁下左 padding 有 mask 可正确，省线性 mask 的快路径须另证明有效位置/M-RoPE/因果注意力正确且末态永不续用。

E0 分别测 E4 利用率和 E2 视觉去重；四个连续锚点的 16/7 是 E2 理想编码量比，不是仅拼 batch 就有的收益。语言层每题仍处理四图。E4 首先 dropout=0 对齐逐行 logits/loss、梯度和更新，恢复默认 dropout 时按总方案处理随机掩码差异；同 seed 不等于同随机实现。

若 mask 含 padding，本地 24 层 DeltaNet 会逐行执行，标准 E4 不能预设有明显加速。按总方案 §8.6.1 单列 E4c：FLA/卷积/普通注意力全通路显式隔离，并独立生成每题 M-RoPE、映射 binary 各答案 span 和 E1 位置。当前 vendor 未接语言分段参数，需源码适配与数值证明；先对照等长批及右 padding 候选，不把新主分支能力当成本地已经支持。

E4c 锁定版本还须验物理 B=1 展平、FLA 累计长度 dtype、卷积 seq_idx/channel-last stride，以及 head_dim=256 的 GQA 变长反向。全 1 mask 的 B=1 基线只在上层做一次 mask 判断，不承担 ragged 的逐层同步。硬门和后端不支持时的隔离回退统一以总方案 §8.6.1 为准。

若为复用而额外选择邻锚点，则按总方案 §12 的 P2a/P2b 做采样实验；用户指定可配置连续段为 P2c，K 候选及题数展开规则以总方案为准。原配额主锚点可带少量邻帧或按配额分配段内题，整更新保持多路线；先单测邻帧，再与 P3 桶归一化组合，不能把二者一起改成“工程优化”。

Phase3 choice 每锚点通常一题，前缀树是否有收益取决于实际选中问题，不根据 Phase4 平均题数推断。binary 当前多行本来就在一次答案序列里；把每行拆成独立分支会改变训练条件，不归入 E 系列。

R0 首轮不把 Phase3/Phase4 两个 LoRA 强并。跨任务共享语言前缀要求相同参数及完全相同的前缀；若采用联合模型，另外建立多任务实验，测负迁移、任务权重和上下文混淆。

### 7.1 四张 H20 的 Phase3 实施决策

硬件单位、显存组成及选档标准统一见总方案 §8.7。本 Phase 也固定四个 DDP rank、每卡一个进程；每卡 b 指一次前向的独立题数。主性能候选 b=4、全局 microbatch=16，正确性/容量从 b=2 起，b=3 作对照；最终以四卡共同可容纳且有效题/秒最高的档位为准，不以显存填满为目标。

本地 [train.sh](train.sh) 默认 `GRAD_ACCUM=1`，当前一次只前向一题；因此采用主候选时，先单列 P5：原 N=4 对候选 N=16。固定候选 N=16 后，b=2/3/4 的每卡波次分别为 2+2、3+1、4，按每题原目标加权，不能简单平均两个大小不同的 microbatch。N=32 作为后续实验；每次扩大 N 均重新登记更新数与 scheduler 口径，不把减少更新次数解释成纯吞吐收益。

sequence 是取数段：首个调度探针 K=32、s=1，每题仍保持原两图/四图；段可跨多次更新，不同时保留整段语言计算图。P2c 另测 K 的影响，首轮保持已选 N。choice 通常每锚点一题，binary 的多个答案 span 仍在同一题；不要为了凑四卡题数拆 binary 的答案行。经过过滤后的 Q 才是分配依据，短段不复制题目补齐。

候选 N=16 的多路线示例为四条路线各四题；K=32 只是各路线待消费队列长度，不让单一路线段占满更新。E4b 只重排原全局更新，保存确定性题→rank→波次映射；续训重放原分配，不按新的缓存/负载估计重排。新增连续题仍属于 P2c，不能混入纯工程对照。

Phase3 默认 gradient checkpointing 关闭，容量不能照搬 Phase4。分别测 binary/choice × 两图/四图的真实 token 长度、padding、最长输入与首个 Adam 更新峰值；若需要开启 checkpointing，另验性能/数值，再测 b 档位。全局 batch=8 已经表示每卡 2 题，不能再乘一个未定义的“每卡 batch 数”。每波四卡前向/反向次数一致，最后一波同步；读图/解码和缓存未命中也进入负载估计。当前没有目标 H20 实测，此处不是已经调好的运行参数。

`34 L b h` 激活情景与 FLOPs 推算的适用限制见总方案 §8.7.3/§8.1.1；前者不是本混合模型的峰值预测，后者不能用假定 MFU 推导“应在多久训完”。checkpoint off/on 是容量候选，LR 比较时固定它。

P5a 先在原 LR=1e-5 下比较 N；P5b 再按总方案 §12 做 N×LR 小网格（1e-5/2e-5/4e-5），binary/choice 分别选优，同等搜索预算保留旧 N 对照。本地默认 warmup_steps=2000，`make_scheduler` 使用计划 optimizer 更新数；扩大 N 后必须重算总步数，并按预登记进度映射 warmup，不能直接保留 2000 步。与 E4 同题集重排不同，P5 更新次数、LR 曲线和调参成本都须报告。

历史三轮 9216/7680 步的具体表集中在总方案 §12：N=16 时 choice 仅 1920 次更新，固定 2000 已经走不完 warmup。默认按各自基线比例映射，该例 N=16 用 500、N=32 用 250；binary 的 21.70% 与 choice 的 26.04% 分别保留。这里只是按历史曝光量换算的设计数，新 run 仍以实际 G0 计划、跳过和尾步重算。

## 8. 评估、时序与 Action

| 维度 | 指标与分母 |
| --- | --- |
| 严格行为 | 完整固定题集的 exact、各动作 precision/recall、格式错误；范围外真值不消失 |
| 集合行为 | 人工集合命中率、集合覆盖率/大小；严格指标同报 |
| 候选裁剪 | 真值不在候选集的比例，以及正确事件/错误事件条件下的差异 |
| UNKNOWN/INVALID | 人工不可判定率与系统拒绝/错误动作；两者语义分开 |
| 时间 | 已审核连续转换片段的提前、偏晚、漏响应和持续旧动作；预测边界与物理执行时刻分开 |
| 下游 | action_prior 词表、KEEP/NONE/UNCOND 含义、纵横投影、制动与恢复信息、所用上下文来源 |

不要仅靠离散采样 test 题推导完整响应延迟。时序指标需要连续已审核窗口和固定转换定义；窗口不完整记删失。Phase3 的“过早预测”不是 Phase4 的“过早放行”，各自计算。

历史审计集用于已知问题回归；模型及语义选优用开发验证集；最终效果用未参与设计的物理路线。比较以同路线配对为主，报告不同训练 seed 和路线聚类区间，不能将相邻帧当独立伯努利试验。

Action 前置验收按总方案 §13.1：先核对 [action_token.py](../action_prior/action_token.py) 的原始候选/full map oracle 来源及该 run 是否启用，再比较 token 差异，使用固定 Action checkpoint 做相同输入/参考的离线 ADE/FDE。S0 loss 排除、S2b 保留原单一标签时不会自动改变 oracle token；不变则只作负控制，改善要由后续预测 token 路径验证。规则/投影改变时新建映射合同，不隐式改稳定 release；语义不兼容旧 Action 时另做明确的等预算迁移实验。最后才是 CARLA 真实闭环。

“鼓励早预测”的触发顺序见总方案 §9.1：先确认连续片段系统性偏晚，S0 经训练分布和语义诊断后才考虑；集合需首轮可接受证据和已验收协议，可保留语义动作名。Phase4 catchup 权重只解决后继状态追赶，不能当作 Phase3 已经具备的补问接口。
