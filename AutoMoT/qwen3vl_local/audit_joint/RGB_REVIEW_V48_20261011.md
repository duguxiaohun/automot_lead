## 分阶段记录，不回填早期判断

新增 [rgb_review.py](rgb_review.py)。读取已绑定的input_evidence清单，检查两模式语义配对，只接受显式训练题ID。首屏保存精确系统/用户文字及原始RGB文件/解码像素身份，不展示参考答案、老师事实或模型预测。联系表是缩小预览，原文件路径和SHA保留，不声称执行了tokenizer/processor。

必须先为所有题提交带视觉理由的YES/NO/UNKNOWN，才可展开下一阶段；判断文件独占创建、不覆盖。下一阶段回执绑定前阶段判断SHA，源清单、请求、预览或判断漂移拒绝继续；展开及锁定时重新检查外部图像。完整来源阶段递归核对RGB/meta/bbox；它只是已登记因果包络，不保证连续完整路线，更不保证最小必要历史。人工题缺原生老师来源保留为空。

这是流程分隔，不是文件访问控制、防作弊系统或独立盲审凭证；即使阶段执行顺序正确，所有输出仍保留 `independent_approval=false`、`G2=not_run`。本轮两/四图均1 YES、4 UNKNOWN；揭示来源并重算后1 YES、2 NO、2 UNKNOWN。仅五道刻意选取的开发题，不能计算学生不可观察率或模型能力上限。完整证据NO不得倒填前面RGB-only阶段。

## 使用方法

在AutoMoT应用目录中，复用现有来源盘点；不要为该工具先重建数据。下面ID和输出目录须替换为实际新复核目标：

```bash
python -m qwen3vl_local.audit_joint.rgb_review prepare \
  --inventory checkpoints/input_evidence_v48_20261011_release \
  --data-root /实际数据根目录 \
  --ids 实际训练题ID \
  --output checkpoints/新的复核目录 \
  --reviewer 审核者名称 --prior-exposure known
```

查看`rgb2/cases.json`和对应图片后，把判断写到单独JSON文件（列表，每项含`id`、`answer`、`reason`），再执行：

```bash
python -m qwen3vl_local.audit_joint.rgb_review lock \
  --output checkpoints/新的复核目录 --stage rgb2 --judgments /实际判断文件.json
python -m qwen3vl_local.audit_joint.rgb_review reveal \
  --output checkpoints/新的复核目录 --stage rgb4
```

四图判断同样锁定后才能`reveal --stage history`。历史阶段仍可单独锁定判断。已存在阶段或失败阶段不覆盖，应保留并使用新复核目录；不得删除旧判断后补写来伪造先后顺序。输出禁止放进原数据或来源清单目录。
