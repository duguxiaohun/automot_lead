# ABC 新初始化与重放失败修复（2026-10-25）

## 结论与原因

旧 `run_20261024_232204` 退出于训练前的 a 重放，未开始正式训练。旧 adapter 在同一基座上分别用原/新提示词推理，触发 `tradeoff_review_required`，子进程以 2 退出，外层转成 `CalledProcessError`。日志开头的 flash-linear-attention/causal-conv1d 安装提示不是此次退出原因。

原正式训练本身已经新建 LoRA；设计错误在于强制依赖旧 adapter，并让“旧 adapter 换提示词后是否退步”决定能否从基座重新训练。现在取消这条错误门控，并拒绝旧 adapter/decoder 初始化。结果保护移到本轮训练完成后的完整测试对照，不保证新训练一定改善。

## 收到证据的独立复算

`replay_a_review.zip` 与 `diagnostic.zip` 的 CRC、全部 manifest SHA、pipeline 一致性均验证；从原/新 cases 重算的回归字段与收到报告全部一致。739 条 val，2,928 个有效端点，28 个物理组。

| 指标 | 原提示词＋旧 adapter | 新提示词＋同一旧 adapter |
|---|---:|---:|
| 端点正确率 | 82.79% | 78.59% |
| 物理组宏平均正确率 | 78.01% | 76.69% |
| 四端点全部正确（724 条完整样本） | 493 | 448 |
| 当前速度 ≤0.2 m/s 样本的错误 FAR | 33 | 6 |

损失 232 个旧正确端点，新增正确 109 个，净减少 123 个（−4.20 个百分点）；130 条记录发生旧正确损失。0.5/1/1.5/2 秒的损失分别为 43/50/53/86。损失集中于绕障后回归、路权冲突、无信号路口、对向侵入等。低速错误 FAR 改善并没有抵消总体下降，也不能把当前低速理解为未来必须静止。

原 diagnostic.zip 只有 pipeline，没有逐例重放证据。其 `core_complete:true` 仅说明当时指定的一个核心文件齐全，不代表审计充分或训练成功。本轮失败打包补入已有阶段报告和日志末 64KB；若存在旧重放 JSON，回归为核心、案例按容量收录，清楚记录可选省略。

## 改动与保留

- Phase3：每组原始 Qwen3.5＋新 LoRA，旧 test JSON 只用于成员核验和训练后的回归。禁用旧 replay 和 `--replay-root`。训练/probe 拒绝 checkpoint 初始化；自身探针重载和本轮第三轮评测保留。
- Action：保留 BEV 感知预训练，Qwen 分支使用原始 Qwen3.5；区域嵌入与 decoder 新建。显式拒绝旧任务权重、resume、训练/probe checkpoint。模型目录混有 PEFT adapter 文件时拒绝。
- 交付：正式包增加完整旧 test 紧凑预测；质量复核状态写入包内 pipeline。三组均完成后，保护通过退出 0，需复核仍完整交包后退出 2。实际异常保留底层错误，诊断打包失败不掩盖原异常。
- 标定、提示词、划分、原生训练核心、Phase3 三轮与 Action 七轮预算不改。原文件/权重/结果不迁移、不覆盖。旧失败 run、旧 processor/probe 不升级复用。

使用 [README.md](README.md) 中 `checkpoints/abc_refine_fresh_v2` 新目录命令。`--baseline-cases-root` 指向旧 a/b/c test JSON 的根；不读那里任何旧权重。Action 命令见 [两路线运行说明](../ABC_TWO_TRACK_RUN_20261024.md)。本轮不改 base/single 选择或训练。
