# 完整一轮后：先查已采训练题拟合，不续七轮

本轮把本机逐帧报告提出的首要检查做成可重复运行的独立工具：`python -m qwen3vl_local.audit_joint.train_fit`。原学生源码合同、生产合同和模型加载器均不修改，**现有一轮 adapter、data4 与 student_view 继续复用，不再生成新视图或重训**。本工具属于开发诊断，不授予G0/G2批准、不修改标签/采样/选优。

## 已复核的事实

对接收的1264文件一轮交接包重新核验，逐rank执行题目及更新次数和冻结有序采样一致。两组均有112/239道val题缺精确“事件×边×阶段×答案”训练支持；U-E1 complete/readiness有87道YES、94道NO，呈现次数也是87/94，四图5道val NO全答YES。这仍不能证明训练题未学会，必须实际加载adapter补测。

已有离线覆盖工具区分三类：`missing_pool_support`、`pool_present_not_sampled`、`sampled_fit_unknown`。完整池汇总不全、缺执行日志、题序或更新次数不一致都拒绝得出通过结论。包内SHA通过只证明内容一致，不是标签正确。

## 1. 本机离线复核（无模型）

从 `AutoMoT/` 执行，输出目录必须未存在：

```bash
python -m qwen3vl_local.audit_joint.train_fit support \
  --package checkpoints/phase4_full_epoch1_handoff_20261009.audit \
  --epoch 0 --output checkpoints/phase4_support_review_20261010
```

输入为解压目录；先完整verify-package，再核对每个学生实验的source/view、val全量ID并复算指标、采样顺序SHA、实际四rank逐步记录及更新次数。同一已采ID不能改答案/来源，所有已采类别必须存在于完整池，包括未出现在val的类别。`support_report.json`只使用粗类别支持，不冒充同状态或同实例证据；`fit_report.json`记录工具及依赖SHA。此步骤不运行模型，也不修改接收包。

## 2. 服务器：两组各推理181道已采训练题

更新到含本工具的代码后，从服务器 `AutoMoT/` 在原automot环境执行：

```bash
set -e
for mode in 2 4; do
  if [ "$mode" = 2 ]; then
    FIT_RUN=checkpoints/phase4_full_epoch1_rgb2_20261009/run_20261009_235753_477334207_rgb2
  else
    FIT_RUN=checkpoints/phase4_full_epoch1_rgb4_20261009/run_20261010_020535_587421198_rgb4
  fi
  bash qwen3vl_local/audit_joint/run_guarded.sh \
    --space-path checkpoints --min-free-gib 20 -- \
    python -m qwen3vl_local.audit_joint.train_fit fit \
    --run "$FIT_RUN" --epoch 0 \
    --dataset checkpoints/phase4_short_observed_20261009/view \
    --data-root lead_data --model-dir checkpoints/Qwen3.5-4B \
    --event U-E1 --edge complete --phase readiness \
    --output "checkpoints/phase4_train_fit_20261010_rgb${mode}"
  python -m qwen3vl_local.audit_joint.train_fit verify-fit \
    "checkpoints/phase4_train_fit_20261010_rgb${mode}"
done
```

这里使用交接包中登记的实际run，避免latest指向后续实验。路径若已迁移，应先核对，不能改旧回执SHA。默认自动选择一张GPU；固定卡用命令前 `GPU_IDS=0`，两组串行。源数据验证可能需读完整题库，但模型仅推理所选的181道不同题；选择结束后释放整池行对象再加载模型。无需优化器恢复、无需新增梯度更新；实际GPU耗时尚未测量。

只想先查选择与状态支持，可在同一命令追加 `--prepare-only` 并使用不同输出目录。它不加载模型，`training_fit=not_run`，不能拿来当拟合通过。准备后实际推理仍需新输出目录。

可扩展为 `--event U-E1 --edge proceed --phase readiness`，或U-E7 proceed并用`--phase all`；每个查询使用独立输出目录、保留完整已采样集合。U-E7 release无已采题会写`no_sampled_support`并退出2，不自动假设PROCEED/HOLD或补造标签。

## 3. 交回什么

每组输出：

- `fit_report.json`：请求、源码与输入SHA、逻辑引用解析目标、运行阶段、选择/已完成数量、状态支持及结果文件SHA；失败时保留错误与阶段。字段`training_fit=measured`只代表本次拟合推理完成。
- `fit_selection.jsonl`：完整所选训练ID、原标签来源、原输入身份、呈现次数。按已采ID确定性排序，不按预测对错筛题。
- `cases.jsonl`：实际自由生成的逐题预测与身份，逐题写盘，失败时可保留部分结果；部分结果不生成完整拟合通过状态。
- `fit_metrics.json`：不同题与曝光加权结果分别统计；按事件/边/阶段/答案、主状态、纵向状态、分支、运动和原始标签来源分报，物理组另计。运动分层沿用原生0.5m/s阈值，表示运动状态，不是可观察性批准。

状态支持使用对应题库的完整训练池、实际采样和开发val按同一分层对照。即使同格有样本，也不证明是同参与者、同实例、同像素或同可观察性；训练拟合高、val低提示需进一步查分布或标签，不能直接归因。

`verify-fit`无需模型，独立核对选择全集、逐题身份、呈现次数和结果SHA，并从cases重算指标；收到包后也能对`results/rgb2_train_fit`等目录执行。它拒绝`prepare-only`、部分结果和失败报告，不把字节核验当作本机重载权重或GPU执行证明。推理过程中会再次检查运行证据、checkpoint回执/资产及视图的内容和解析目标；中断退出130，其它失败退出2，原输出拒绝覆盖，失败报告仍可交回诊断。

```bash
python -m qwen3vl_local.audit_joint pack \
  --capture checkpoints/joint_missing_assets_20261009_layoutfix/capture \
  --result-dir rgb2_train_fit=checkpoints/phase4_train_fit_20261010_rgb2 \
  --result-dir rgb4_train_fit=checkpoints/phase4_train_fit_20261010_rgb4 \
  --output checkpoints/phase4_train_fit_handoff_20261010.audit.zip
python -m qwen3vl_local.audit_joint verify-package \
  checkpoints/phase4_train_fit_handoff_20261010.audit.zip
```

复制ZIP到本机checkpoints交回即可。拟合报告通过源码/数据/采样/检查点SHA绑定原一轮运行，本机已经保存原一轮交接，不必重复上传权重。失败报告也可打包；30MB硬限与完整核心结果不截断保持。历史G0继续保留缺失状态。

## 本轮没有放宽的规则

负尺寸51帧的绝对值诊断包络不等于可靠几何，仍须确认导出语义和影响范围；夜间一个可见反例不足以改亮度门；假设PROCEED/HOLD的release条件不证明真实可达状态或补问可批准。11路线/301帧探索性目视不转成G2盲审或独立批准。Phase3缺少正式全池时也不把本机374条候选直接用于训练。后续监督补齐、源异常局部隔离和G2锁答分别需要专门证据，本工具不会修改这些门。
