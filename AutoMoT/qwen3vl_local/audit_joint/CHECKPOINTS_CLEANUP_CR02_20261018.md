# cr02 指定旧 checkpoints 清理

用户明确要求先永久清理旧产物，保留本次 Phase3 训练以供恢复。适用机器
`szh-gpu-cr02`，项目 `/home/cruser1/lda/AutoMoT`；不是 cee 的清理方案。

`checkpoints_cleanup.py` 是独立标准库工具。默认预览，`--apply` 才永久删除。
仅处理脚本中逐项列出的 44 个旧输出/旧 batch 测试/readiness/配套日志，
不按前缀、日期或“最新目录”猜测。其余顶层资产默认保留，包括：

- 本次 `sft_new_loop_phase3_pipeline` 下三个运行及 `sft_new_loop_phase3_runs`。
- `phase3_four_data_20261017_223254_120427458` 与全部基础模型。
- `phase4_teacher_v24_20261018_121758_779650998` 与后续新恢复产物；
  已有原始回放可能是新库的永久依赖。
- 未纳入名单的其它任务、基线、原始数据与代码。

工具扫描 checkpoints 内保留产物中的路径引用（含 gzip、ZIP、PyTorch pickle
元数据、safetensors 头部），沿引用保留候选及其依赖。仅搜索字节，不执行 pickle。
日志里提及旧目录也会保留它，宁可留下待复核项。图像/视频、TensorBoard 日志、
PyTorch tensor storage 和 safetensors tensor 数据不作路径元数据读取。
这是 checkpoints 内的保守引用检查，不是项目外部任意程序的依赖证明。

同用户项目进程仍在运行、嵌套挂载、扫描读取失败、目录/文件发生变化，均阻止开始
删除。检查有 600 秒/128 GiB 解压读取上限；达到限制不凭部分结果删除。
目录 flock 只协调同工具，不锁住其它训练入口；清理期间不要启动训练/建库/同步。
删除阶段发生 I/O 错误可能部分完成，报告 `deleted` 和 `error`，不自动重试。
不停止其它任务，不创建备份，不清空整棵 checkpoints。

服务器仅从已发布固定提交下载本脚本，不做整仓库源码同步，
避免影响 Phase3 旧 checkpoint 的源码合同。用户要求反馈就地保存：在当前项目根或
checkpoints 下创建 `automot_cleanup.XXXXXX`，内含本脚本、`launch.log` 和新
`cleanup_report.json`。只排除本次三个工具文件的引用扫描；目录必须没有其它文件、
不含链接，目录成员变化仍阻止删除。不使用 `/tmp`。项目外的新输出路径仍受支持。
报告包含实际删除清单、因引用保留的项目、预计文件块数及前后磁盘可用空间；
块数可能受硬链接影响，实际释放量以现场结果为准。反馈 `cleanup_report.json`
和 `launch.log`；此步骤不恢复训练，也不重建数据。

本地验证：22 个清理测试及 11 个原恢复诊断测试通过。涵盖真实临时目录永久删除、
传递引用/链接/压缩元数据、损坏文件、扫描限额、活跃进程门禁、目录成员增加及
文件变化拒绝。未连接 cr02 执行删除，不能提前声称服务器已释放空间。
