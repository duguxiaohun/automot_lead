# Phase4重复协议校验修复与短时验证

服务器120秒采样：30/60秒位于JSONL解析，90秒已到逐题check_evaluation_protocol→producer_check_reservations→file_sha。代码每题读取同一协议并校验55个冻结文件（约1.34MB），仅298787训练题约1643万次文件SHA操作；这是调用次数，不是物理磁盘读取量或整个训练耗时。v63解决四rank重复准备，v64消除准备进程内这项重复；JSON解析及其它完整校验仍存在，不能承诺整库两分钟内通过。

## 修复范围和合同

新增audit_joint.phase4_load：只在独立、单Python线程的CPU读取进程中临时复用原producer_check_reservations返回的已验证表；每次返回副本，防止调用方改变快照。原函数在开始与结束真实执行，协议文件SHA前后复核；文件／归属变化硬失败，异常或中断恢复原函数，不跨调用持久缓存。逐题标签、来源、物理split、输入去重和其余准入校验完整保留。原生dataset.py／identity.py及冻结producer/teacher均字节不变，不改旧合同来伪装兼容。

benchmark CPU准备已接该读取适配层；未改正式训练器和旧实验重载路径，因此不宣称这些入口全部获得相同加速。当前先完成准备和GPU单trial验证。

服务器旧view的4个SHA明确对应v61。迁移入口只允许这4项已知运行差异：sequence_batch、evaluate、reload_check、run.sh。所有数据转换、标签、原生producer、曝光和输入合同必须完全相同，否则在耗时工作前拒绝。旧库原生完整校验、两模式转换后的成员／排除项／配额逐项核对后，才在新目录写当前合同，记录old_descriptor_sha256和changed_sources。旧view/checkpoint不覆盖；不能用新view续训旧checkpoint。RGB身份sidecar在复制前后核验其冻结SHA，因图像转换代码完全相同复用其原有绑定，不重扫RGB；不宣称新的人审／RGB内容认证或修改标签。

## 服务器命令：先迁移，再单trial

先沿原sync_automot.sh同步已发布v64；在AutoMoT目录、venv下执行。`P4_NEXT`请保留在当前shell中，后续失败重试用新目录，不能覆盖已生成产物。

```bash
export P4_NEXT="checkpoints/p4_v64_check_$(date +%Y%m%d_%H%M%S_%N)"
(
set -euo pipefail
python - <<'PY'
from pathlib import Path

PY

  --view checkpoints/p4_batch_measure_20261016_093447_958074352/student/view \
```

退出0且显示view_migrated后，再执行下面唯一一个GPU trial。准备最多180秒、GPU阶段最多300秒，失败不继续排队；进程启动和清理另有少量开销。CPU准备会重新校验，未通过绝不启动GPU，不使用过期准备快照。默认GC开启，四卡B1，每更新32样本；十事件各32计时呈现，另有等量预热。

这不是正式训练质量验收。若180秒仍超时，日志每30秒栈及每5万协议调用进度用于定位剩余热点，不把上限延到数小时。仅想检查原生加载而不迁移时，可改用`phase4_load --native checkpoints/phase4_v57_20261014_232157_762998141/data4 --output <新目录> --timeout 120`。
