# Phase3 自车位置 token 设计与本机全量轨迹审计

日期：2026-10-21。结论：适合把 single_frame 的规则动作监督改成 **固定当前自车坐标系内、带时间索引的自车参考点位置分类**。首选比较 35 格与 63 格的非均匀网格，主方案候选为前向 9×7＝63 格、0.5 秒间隔、2 秒未来。核心显示范围前方 32 米、左右各 14 米；超出边界的正常远轨迹仍归入相应边缘格。历史也要求同一套几何 token 时，将纵向向后镜像，词表共 17×7＝119 个位置 token，未来主要使用其中前向 63 个。119 是共享位置字典大小，不是 119 种整段驾驶模式。

本轮新增独立只读审计脚本和本地统计、图表、设计报告；未改变 single_frame、action expert、标签、prompt、采样或训练入口，未训练、SSH、commit 或 push。这里选择的是值得实验的表示，尚不是已证明优于旧 action 的模型。

## 数据范围与统计口径

扫描本机 `AutoMoT/lead_data` 实际解析到的 `lead/cache_ln/data`。覆盖 44 种场景、11 个 Town、9,582 个带 metas 目录的路线目录。其中 853 个 metas 目录为空；实际读取 8,729 条路线的 1,112,087 个文件，8,725 个非空物理路线组。2 个文件不能解码，成功读取 1,112,085 帧。不能把空目录计作已有轨迹，也不能把本机库存冒充远端或公开数据集的全部发行内容。

1,042,285 个锚点具备完整 2 秒未来；69,800 帧未来不足 2 秒，独立记录，不末点补齐。382 帧当前 speed < −0.1 m/s，其中 381 帧有完整未来：作为反向速度诊断层单列，不宣称全是错误、不写入生产隔离规则。主统计使用剩余 **1,041,904 个完整锚点**。这些窗口大量重叠，不能称作 104 万个独立场景。全库统计包括既有训练流程可能排除的路线，因此它是几何盘点，不是训练准入。

事件层读取现有 `phase3_common_v1/native/candidate_frames.jsonl` 的 189,950 条上下文记录，并应用该库 manifest 的物理路线 split 调整及 additional development 标记；没有用场景名直接猜 U-E/R-E。训练候选去重后 185,681 个有效锚点、4,587 条路线。十事件统计仅描述已有候选索引覆盖的帧，不声称给其余全库帧重新标了事件。候选索引是已存在的快照，不代表本轮重新认证它的全部标签。

全部 meta 内容经逐文件 SHA256 汇入路线级摘要；两次全库坐标核算的所有路线摘要一致。原始数据只读，完整数组、路径、图源与统计留在 checkpoints。网格解码代表点仅用训练候选的四时刻坐标拟合中位数；全库和既有 heldout 几何统计不当作新模型独立泛化成绩。最终模型选择应按冻结训练/验证协议进行。

## 时钟与坐标核对

- 原始仿真为 20 Hz；meta 每 5 步保存一次，即 4 Hz、0.25 秒一帧。
- 每个 meta 内 `future_positions` 是 20 Hz 序列，第 0 项为当前点。
- 当前 action expert 的真实接口是未来 8 个 waypoint：下标 5、10、15、20、25、30、35、40，对应 0.25 至 2 秒。新高层 token 取 10、20、30、40，对应 0.5、1、1.5、2 秒，不能把这些下标当作保存帧号。
- 主统计采用原点为当前 ego_matrix 平移、航向为 `atan2(R[1,0], R[0,0])` 的水平自车坐标：x 向前、y 负左正右。未来所有时刻固定此坐标系，不逐点换参考系。

水平坐标公式为 `x = cos(ψ0) ΔX + sin(ψ0) ΔY`、`y = −sin(ψ0) ΔX + cos(ψ0) ΔY`。从原生 `future_positions` 先用当前旋转矩阵恢复世界位移，再按该航向旋转。与后续保存帧的实际 ego_matrix 位置独立对照，共 8,582,439 个可比点，最大差异 0.000826 米。

**实际发现 24 帧 `theta` 与位姿矩阵航向相差超过 90°，全部也超过 5°；`privileged_yaw` 与矩阵航向一致。** 例如 ConstructionObstacleTwoWays/Town12_Rep0_2778_0_route0_01_10_18_51_34 第 112 帧：theta≈4.71239，矩阵航向≈1.57055；原生 2 秒点为前方约 21.885 米，若直接按 theta 转换会被翻到后方。不能用饱和格掩盖坐标故障。

原生 expert 使用包含俯仰/横滚的完整车体系 XY，水平 BEV 与它不是逐位相同：每锚点八点最大坐标差的 P98 为 0.03949 米、P99 为 0.06126 米、最大 0.72330 米。正式实现必须明确合同：高层可用本报告的水平网格，连续 expert 保留原生车体系，但交接时依据当前姿态显式换算；或全部采用原生车体系并重新核算边界指标，不能把两者默认为完全一致。

历史输入应来自截止 t=0 的定位/里程计或因果状态估计。`privileged_past_positions` 仅可作理想历史对照；部署输入应对齐 `past_positions` 或实际可用的因果定位。两者点距离 P50≈0.025 米、P98≈0.226 米、极端约 41.14 米，说明历史也需要质量标记。禁止再使用向未来看的旧 upcoming-action 历史标签，也不允许用 t>0 的坐标补历史缺失。

32×28 米是本次适中的核心区域，不是所有未来轨迹的物理上界。直行 v=16 m/s 时两秒约 32 米；v=20 m/s 时约 40 米，可以落最远 token，不需要为此扩展核心范围。匀速圆弧近似 `x=v sin(ωT)/ω`、`|y|=v(1−cos(ωT))/|ω|`：v=8 m/s、2 秒转 90° 时，x 和 |y| 都约 10.2 米。这解释了为何路口不能只留左右一个车道宽。

全局覆盖不等于每事件覆盖。32 米前界在 RAMP_MERGE_EXIT 训练候选中只覆盖约 86.39%；约 13.61% 进入外圈，属于此事件内显著比例。按照“远处可模糊”的目标可以保留这个设计，但须让最远格表示“至少很远”，不能将它当成固定 29 米目标强迫连续 expert 减速。若未来高速精度确实成为瓶颈，再比较远端残差/速度条件，不必现在增大整张图。

## 网格如何切分

主候选前向纵向 9 档，单位米：

`[−0.25,0.25), [0.25,1), [1,2.5), [2.5,5), [5,8), [8,12), [12,18), [18,26), [26,+∞)`

横向 7 档，单位米：

`(−∞,−7), [−7,−3), [−3,−0.5), [−0.5,0.5), [0.5,3), [3,7), [7,+∞)`

纵向 32 米和横向 ±14 米是用于报告覆盖及画图的名义边界；最外格实际开口，不额外新增 far token。32 米与 45 米都可归入最远纵向格，但原始连续坐标必须完整保留，不能把原始 expert 回归目标也截成 32 米。负方向超出近原点容差时不能冒充静止；使用下面的双向共享词表可自然表示，反向速度样本则另做准入审计。

近原点横向中心宽 1 米、纵向中心宽 0.5 米，减少静止数值抖动导致的左右变化。不能把这个中心格命名为 STOP：它只表示小位移，不证明车辆完全停住。全库中 2 秒总路径 <0.2 米约占 24.89%；0.2–2 米的慢行样本共 60,859 个。非均匀方案约 8.47% 的这些慢行样本四点都落原点格；所测均匀 63 格方案则将全部此类慢行样本并入原点格。0.2 米只是本次比较用阈值，不是新交通语义标定。

对每个真实 waypoint 直接计算唯一格号。不要沿用旧方案把两个 native-action origin 做 50/50 混合的规则。若想减小边界敏感性，可以另做相邻格距离加权的 soft-target 对照；保留硬格真值和原始坐标，不能先声称平滑标签没有误差。对训练候选做 ±0.1 米四个轴向扰动，63 格方案平均约 2.94% 的点换格，说明分箱边界仍带有不连续性。

### 15 格 35 格 63 格 99 格的实测比较

这里没有运行模型。表中使用真实位置选中正确 token，再解码到训练候选拟合的格内中位代表点，测量**表示本身的量化重建误差**。代表点是坐标中位数，未声称为 L2 理论最优；不同重建器会改变数值。ADE 是四个 0.5 秒点的平均欧氏误差，FDE 为 2 秒点误差。外圈样本也纳入，未通过截断真实坐标美化结果。


| 前向格数 | 训练候选 ADE m | 训练候选 FDE m | 全库 ADE m | 全库 FDE m |
|---|---|---|---|---|
| 15_5x3 | 1.131 | 1.841 | 1.277 | 1.969 |
| 35_7x5 | 0.792 | 1.231 | 0.860 | 1.271 |
| 63_9x7 | 0.614 | 0.922 | 0.664 | 1.013 |
| 99_11x9 | 0.471 | 0.698 | 0.497 | 0.723 |
| 63_uniform | 0.816 | 0.876 | 0.908 | 0.846 |


15 格可作为便宜而直观的消融，但不是推荐的唯一主线。35 格适合极简高层提示；63 格的近处/横向表达更充分，同时仍然很小；99 格进一步降低量化误差，但尚未证明增加类别能改善模型可学习性和闭环结果。均匀 63 格的最终点误差在本次比较中反而略好，不能隐去这一点；但它的平均四点误差更大、近处静止/慢行混合严重。因此推荐非均匀格的依据是整段近远兼顾，而不是所有单项指标都赢。

63 格四点序列理论上有 63⁴ 种组合，绝大多数并不是可行轨迹。“位置 token 个数”与“整条轨迹模式个数”是两回事。不应给 63 个格直接冠以 63 种驾驶行为的名字。

## 0.5 秒与 1 秒间隔

用真实点、不加网格误差，分别保留 0.5 秒或 1 秒节点，再线性插值到 action expert 原来的 0.25 秒点。全库结果：0.5 秒节点平均 ADE 0.0369 米、每条轨迹 ADE 的 P95 0.1002 米；1 秒节点平均 ADE 0.1358 米、P95 0.4106 米。0.5 秒更能保留短时制动和弯曲形状，因此作为主候选；低层仍输出原有 8 个点。

间隔缩短不必让整张图同比变密。对固定 t=0 累计位置分箱，仍可以共享同一张网格，只是早期点更集中在原点附近，因而优先细化近处。若将量化点差用于估速度，误差会大致按 `位置误差/Δt` 放大；若要求每段 token 直接控制车辆，则另需要更细的几何精度。这里保留连续 expert，目标是提供粗位置先验。

这不是 0.5 秒在任何量化器下必胜的证明：所测均匀 63 格反例中，1 秒节点重建平均误差更低。时间抽样损失、分箱误差和模型预测误差要分别报告，不能把 3.7 厘米当成最终模型误差。

## 历史两秒与共享 token

推荐历史时刻 `−2, −1.5, −1, −0.5` 秒，t=0 原点隐含已知；未来时刻 `+0.5, +1, +1.5, +2` 秒。全部投影到当前 t=0 的同一个车体参考系。过去位置大多在负 x，不能硬塞进只有正 x 的未来网格，也不能每个历史点都在自己的坐标系里被编码成零。

若要求历史和输出使用同一单 token 字典，把 9 档纵向网格向后镜像、共享中央档，得到 17×7＝119 个位置 token。原点的纵向索引为 8；前向九档的索引为 8–16；历史常用 0–8。覆盖报告仍只把未来前方区域称作 63 格，不能隐瞒共享词表总数。另设 UNKNOWN 输入符号与有效性 mask，历史缺失不补成静止；预测有效未来点的 loss mask 与历史缺失 mask 分开。

一个更省词表的备选是把纵横轴拆为 17+7＝24 种轴 token，但每个点需输出两个 token，且独立的纵横分类会破坏联合分布，需要条件化或联合评分。为保留当前“四个查询位置”的结构，优先联合格号。

`<WP_11_2>` 等只是本报告的名称约定，当前 tokenizer 尚无这些新单 token。正式实现可增加 119 个专用 token，并让新增输入 embedding/输出行在 LoRA 训练中真正可训练、可保存和重载；或使用独立分类头和共享历史 embedding。仅写这样的字符串并不会自动变成一个 token。继续复用既有词表 ID 也可以，但要逐个检查完整 processor 模板中的单 token 身份和历史/输出一致性。

## 路口和直道应保持同一种几何语义

左侧格表示未来参考点位于当前车头方向的左侧，它既可能来自左变道，也可能来自路口左转、弯道或绕障。不要让同一个 ID 在直道意为 LANE_CHANGE_LEFT、到路口又改成 TURN_LEFT。保留图像、当前速度、导航和事件作为条件，让四个点的轨迹形状表达差异。新位置目标不再按旧事件“只允许 A/B/C/F”屏蔽横向格，否则会误删正常路口横向位置。

2 秒内有些变道/转弯只刚开始，单帧加短轨迹不保证完整意图可辨；这是时域限制，不应靠放大网格解决。若后续验证发现方向仍不够，可单独对照 3–4 秒终点或末端 heading，而不是现在把所有因素一次加入。

```text
+2.0 s: [POSITION_QUERY_3]
```

四个监督值分别为 `<WP_11_2>、<WP_13_1>、<WP_13_0>、<WP_14_0>`，只进入 loss。词表边界需固定在 tokenizer/配置及其摘要中，不能只靠模型猜名称。导航占位是报告省略，正式数据必须使用原有合法 builder。

另一个实测 HardBreakRoute 第 37 帧例子，当前速度 3.321 m/s，未来四个位置都在前方约 0.68 米；四个格号相同表示“到达前方这一区域并停留”，与从 t=0 就停在原点的四个中央格不同。但仅靠这四个粗格不能确定半秒内精确刹车时刻，仍由连续 expert 处理。

## 与当前 single_frame 和 action expert 的衔接

保持当前单图、场景、速度、导航的输入骨架，替换历史标签构建、未来监督、候选词表和四个查询的输出分类。未来真值只作标签；历史严格因果。最小实验可以保留一次前向的四个并行查询，但四个位置分布不是整条轨迹的联合分布，独立 argmax 可能得到不连贯的组合。

将四个查询的分布、位置 embedding 和时间 embedding 作为连续 action expert 的条件；连续 expert 仍输出 8 个 0.25 秒点并保留真实连续目标。不要把格中心连线直接当控制轨迹，更不要把左右两个模式的平均坐标当安全路径。需要检查预测序列速度/曲率一致性和下游碰撞、出界；必要时比较小规模连贯路径候选或四 token 自回归解码。

新 expert 的训练应覆盖实际预测 token 的错误分布，例如训练集内分组交叉预测、冻结高层后的预测缓存或明确的噪声对照；只用完美 GT token 训练、推理换成预测 token 会产生条件分布落差。GT token 条件只能作为表示上限实验单独标注。当前事件若部署来自 Phase1/2 预测，也要保留相应误差路径，不能在上线时假设 GT 事件。

已有旧 action adapter/decoder 不能因为输出数看起来类似就直接当作已兼容。若新增词表，验证 token ID、输入/输出 embedding、adapter 保存重载和历史有效性；若换坐标合同，给新方法独立配置与数据签名，保留全部旧实验。

## 外部方法对本设计的启发

- [MotionLM](https://arxiv.org/html/2309.16534v1)：将运动量离散成 token，使用 Verlet 包装后的 13×13＝169 词表。它的 delta/动力学表示与本方案的固定原点绝对位置格不同，169 不能直接拿来作为这里最优大小。
- [SMART](https://arxiv.org/html/2405.15677v3)：以 0.5 秒运动段建立离散运动词表，并讨论滚动匹配的误差累积及扰动训练。它支持研究 0.5 秒尺度和训练/推理误差分布，但不是证明 15 个位置格足够。
- [AutoVLA](https://arxiv.org/html/2506.13757v1)：使用 2048 个 0.5 秒运动段 token，包含位移与航向变化，且为仿真另建码本。它直接解码连续运动，所需精度与这里“粗先验 + 连续 expert”不同，因此不必照搬几千类。

本设计沿用可解释的轴向非均匀网格。数据驱动聚类可以作后续对照，尤其整段轨迹码本能保留时序关联；但它不自动解决类别不均衡、尾部支持、边界误差和状态分布变化。

## 下一步可比较的最小实验

先冻结坐标、时域、格边界及 split，再在同样训练样本、总更新次数和图像预算下比较：旧 action 基线、35 格位置先验、63 格位置先验。保留无历史/因果历史对照，但不要为了组合矩阵无界增加训练量。本轮没有启动这些训练，也没有新的 GPU 时间估算。

除每时刻分类准确率，还应报告原始米制 ADE/FDE、格到真值最近距离、外圈比例、置信度和校准、同轨迹一致性、静止/慢行混淆，以及连续 expert 的闭环安全与成功率。事件、Town、物理路线宏平均都需要；不能用整体 98% 空间覆盖替代行驶安全或最难事件的效果。

本次可以确定的是：真实分布支持约 32 米前向和 ±14 米横向的粗网格；0.5 秒更好保留原始时序；非均匀细分明显改善近处表达。不能仅凭量化审计确定 63 类学习后必优于 35 类，也不能把离散 waypoint 称为“肯定没有噪声”。
