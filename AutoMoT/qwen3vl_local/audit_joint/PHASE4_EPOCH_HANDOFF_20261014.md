## 确认并修复的交接缺陷

此前验收手册的内联打包脚本直接解析 JSON/JSONL。训练中断后，只要 runtime JSON 或某一行步日志截断，就会在创建 ZIP 前抛出 JSONDecodeError，无法兑现“失败也交回诊断”的要求。本机保留旧脚本 SHA，用相同损坏样例复现退出1、无包。

新增独立 `phase4_epoch_handoff.py`：

- 固定读取本次 first_epoch 两模式的采样、步日志、val/reload/test 输出、检查点元数据、准入和日志尾部，不遍历权重目录。
- 缺失、损坏、非对象记录均进入诊断；JSONL 可读行继续保存，但不把部分来源当作完整证据。大量坏行保留总数和前100条详情。
- 每个读取文件登记解析路径、大小、SHA，结束时重新核对逻辑路径解析及 SHA，发现仍在写入或软链接改指就保留不完整状态。
- 核对四 rank 所有完成步的 ID、位置、顺序、epoch、有限 loss 与采样顺序摘要；必须是10240次及计划十事件各1024。重复题曝光允许，重复或遗漏步位置不允许。
- **事件计数继承已绑定采样计划**：现有 samples 没有事件字段，本工具不冒称重新从题库证明事件归属，也不验证真实 GPU 执行、优化器更新或梯度效果。
- 仅大元数据列表投影为数量和SHA。步记录和逐题输出不投影；预算不足的成员显式登记为遗漏，包标记 incomplete，不静默截断后宣布成功。
- 包SHA/CRC、消费记录匹配、模型质量验收是三个不同结论。`training_accepted` 始终为 false，收到真实包后仍需独立检查两模式、原始输出、固定val/test、重载及能力局限。

同一损坏样例使用新 CLI 退出2，生成 **1643字节**的完整诊断 ZIP，成员SHA/CRC通过；记录两处解析错误及其余缺文件。是合成失败测试，不是GPU结果。
