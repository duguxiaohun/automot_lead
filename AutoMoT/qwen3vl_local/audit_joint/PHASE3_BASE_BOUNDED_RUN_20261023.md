## 数据与采样合同

完整原生 train 候选池由 `phase3_base_pool.py` 生成。v3 复用该已校验索引及原始依赖证明，另写准入与计划；四图、六动作标签、风险隔离、val/test 物理组和固定评估成员均不变。不是恢复 sequence，也不是放开动作无效样本。

十事件各 1,280 次呈现／轮，总计 12,800；四卡 B1、累积1，每轮 3,200 更新，三轮 9,600，warmup 2,500。seed、学习率／余弦、每轮验证与最终第三轮模型 test 保留。

1. 先按物理帧计算每事件真实有效容量，不以候选行数或提示词变化增加容量。
2. 为稀缺事件保留全部有效不同帧；剩余配额通过共享容量的整数最小费用流联合分配，先最小化物理帧额外呈现次数，再优先累计曝光较少的帧。不能把各事件独立计数相加当成全池物理容量。
3. 同一事件内，只有不同帧数少于1,280时允许单帧第二次呈现；充足事件内仍最多一次。跨不同事件的同一物理帧也统一计数，全局单轮最多两次。单事件不同帧少于640或联合容量仍不足时拒绝，不升到三次。
4. 稀缺事件三轮同一事件帧上限为 `ceil(3840 / 有效不同帧数)`，其他事件内仍最多3；同时为后续轮次保留必需容量。跨事件共享物理帧全局最多6，单事件物理帧保留其更紧上限。路线、时间段及温和动作偏好用于相同容量／曝光条件下的选择。三轮均需提前投影通过。
5. 计划曝光与实际消费分开。只有完整优化与逐 rank 消费核验成功后推进历史；失败不能把计划重复次数当成已经训练。无隐式续训。

本机已知容量对应的重复需求：

| 事件 | 有效不同帧 | 每轮呈现 | 每轮事件内额外重复 | 单轮同事件帧上限 | 三轮同事件帧上限 |
|---|---:|---:|---:|---:|---:|
| DYNAMIC_CUTIN | 925 | 1,280 | 355 | 2 | 5 |
| SIGNAL_FAILURE | 1,255 | 1,280 | 25 | 2 | 4 |
| 其余八事件 | 各不少于1,280 | 各1,280 | 0 | 1 | 3 |

此外，SIGNAL_FAILURE 与 JUNCTION_RULE_CONFLICT 共享447个物理帧，二者并集只有2,430帧，对应每轮2,560次呈现。联合分配还需要105次跨事件共享帧呈现；只有25次信号灯故障事件内重复不足以解决它。POST_BYPASS_RETURN 与 UNSIGNALIZED_PRIORITY 的4个共享帧则有足够替代容量，不需要额外重复。

因此，实际每轮物理帧额外呈现为 **380＋105＝485／12,800＝3.7890625%**，每轮使用12,315个不同物理帧。最初2.97%的估算仅覆盖事件内重复，未覆盖跨事件共享缺口；正式报告使用3.79%。重复不增加独立场景数量，也不增加验证／测试支持。single v3 和 abc v2 的现有一次／轮采样不改，五类仍统一更新预算，base 的稀缺重复是明确记录的差异。

## CPU 与 GPU 分开验收

本机新版正式全池 CPU 已通过，`checkpoints/phase3_base_bounded_v3/ready_1280.json` 为 **ready**。旧严格版本的 rejected 指针保留，不能代替这个新版本的 ready。

- CPU 不加载模型，不用 GPU；复核原始来源、完整索引和三轮计划。阶段等待每30秒输出进度。
- `check base` 核验当前 CPU ready、源码／数据／计划绑定、输出碰撞、模型资产和四张 GPU。
- `probe base` 在前台完成全部计划输入准备，以及真实模型四卡前向／反向和显存检查，然后退出；不训练正式三轮，不写 latest。
- `train base` 仍执行原生前置检查和 probe，然后训练、验证、最终 test、打包。失败直接打印底层日志尾部。

此次代码尚未 push。只有这些文件发布后，才在服务器已有 AutoMoT 根目录同步：

```bash

```

先在前台依次完成以下检查；首错停止，不提交隔夜训练：

```bash
bash qwen3vl_local/audit_joint/phase3_compare.sh cpu base &&
GPU_IDS=0,1,2,3 bash qwen3vl_local/audit_joint/phase3_compare.sh check base &&
GPU_IDS=0,1,2,3 bash qwen3vl_local/audit_joint/phase3_compare.sh probe base
```

上面全部成功后，再提交正式训练：

```bash
(
  set -o noclobber
  nohup env GPU_IDS=0,1,2,3 \
    bash qwen3vl_local/audit_joint/phase3_compare.sh train base \
    > phase3_base_bounded_v3.log 2>&1 < /dev/null &
)
```

CPU ready 在 `checkpoints/phase3_base_bounded_v3/`，正式运行在 `checkpoints/phase3_compare_base/run_base_bounded_v3/`，前台探针单独在同目录的 `run_base_bounded_v3_probe/`。启动日志是 `phase3_base_bounded_v3.log`；训练日志是正式运行目录的 `train.log`。同名输出保留并拒绝覆盖，旧失败的 `phase3_base_coverage_v2` 目录不影响此新版本。
