# Phase3 dense v4：查询时间起点与窗口显存探针

> 最新独立实验与探针为 [v5](PHASE3_DENSE_V5_20261019.md)：新增逐帧语言KV融合，正式探针改为八个源帧编码。本页保留v4历史行为。

本页补充并取代 v3 的提示词、资源准入合同。新合同为 `phase3_dense_query_origins_v4`。独立 base 的选样、提示词、标签规则、B1/累积1和三轮7680更新保持不变。本轮仅修改独立密集实验模块、测试和发布绑定，没有修改原生 Phase3/Phase4 或共享视觉缓存实现。

## 逐查询时间语义

每个查询显式定义 `T = 该查询可见的最新图像时间 + offset`。速度比较以 T 时刻的速度为参照；首次越线从 T 开始寻找；忽略返回只针对该查询窗口中第一次越线之后的返回。原生规则的 immediate / speed / lateral 窗口目前分别为 1.5 / 2 / 3 秒，提示词从同一规则常量生成。

因此，观察结束后第1秒左变道、第4秒右返回，query0可以标左，query+3s可以标右；后者不会再被“忽略后续返回”文字否定。模型仍只看到已观察的图像、速度与前提；T在未来时，其速度和位置需要模型预测，不向输入填入真实未来状态。动作仍是各查询时刻的原生未来窗口标签，不是具有固定执行时长的连续控制 token。

single/all 使用相同的新提示词。stream/windows 的每个查询 offset 为0，原点就是各自读出前的最新图像。旧全局“after the newest frame / relative to current speed”在密集提示词中改为明确的 T 引用；独立 base 原提示词不动。

## 窗口探针为何改变

CPU形状扫描现在计算与实际打包相同的 query token 位置，并把 `batch_size × distinct_query_positions` 纳入探针的非支配成本集合。五个窗口各一个 query，模型中间 logits 仍可能是 `5×1×V` 或 `5×5×V`；后者不能再被相同 token 数的前者替代。GPU探针重新核对实际打包的长度和所有 query 位置，窗口前向也检查模型输出形状。

图片内容去重使相同尺寸的八帧可能只编码1张，也可能编码8张。仅用图片路径/尺寸无法知道 GPU 实际去重结果。本版没有为所有样本增加完整图片预处理，而是为每个选中窗口同时运行：

1. 正式训练使用的冻结视觉复用路径，记录实际编码数。
2. 关闭去重的保守工作量探针，让20次图片呈现全部进入视觉塔，不依赖这些图片是否相同。相应上界 patch 数和20张图片记录在形状报告中。

训练探针对两条路径各做两次 backward/AdamW step，包含优化器状态分配；评测探针两条路径都只前向，不做 loss/backward/更新。探针模型不会保存，正式训练重新加载初始 adapter，仍使用视觉复用，训练更新预算没有改变。

20图探针是额外的保守资源准入，**不是正式窗口训练改用20张不同历史图，也不是任意内核/分配器下显存绝对上界的证明**。它可能在正常8图复用运行仍可容纳时拒绝准入。若失败，应反馈 probe.log 与反馈包分析，不能直接视为正式训练已经OOM，也不能删除门禁后声称已验收。仍须实际四张H20通过后才能判断服务器显存余量。

## 方案二的实现边界

`stream` 是4/5/6/7/8图增长前缀，共享一次语言前向；`windows` 是五个严格四图语言上下文，只共享冻结视觉编码。严格滑窗同时共享语言状态仍未实现。

本地 Qwen3.5 实现既有 attention KV，也有卷积和递归状态（`qwen35/vendor/modeling_qwen3_5.py`）。裁掉旧KV或仅改attention mask并不能撤销这些状态已经吸收的旧图信息。本轮没有引入未经等价性验证的状态减除，也没有把增长前缀改称严格滑窗。若继续研究联合方案，需要单独验证窗口外图像变化不影响窗口预测、完整前向与复用前向的logits/梯度等价，再测真实资源收益。

## 启动与反馈

继续采用 [v3 执行步骤](PHASE3_DENSE_V3_20261019.md) 的参数，使用新的 `phase3_future_v4_prepare`、`phase3_future_v4_single`、`phase3_future_v4_all` 输出目录；stream/windows同样换成各自新的v4目录。先CPU prepare，再同初值single/all quick，最后同版本接续complete。旧v3训练断点必须在原版源码中恢复，不能改SHA迁入v4；已完成的独立base仍可作为初始化。已通过的新base不用为了本次提示词修复重训。

提示词变长后，CPU扫描会重新检查全部训练及固定评测输入的token预算；不截断、不自动放宽8192单序列和总补齐token限制。日志和反馈仍在显式输出目录及当前实验目录的launch.log。

交付 `result/handoff/phase3_base_report.zip` 与 `phase3_base_package.json`；前置失败交launch.log。必须先验收新base的同口径动作准确率，再比较single/all；本轮不宣称恢复历史70%以上分数、密集监督收益或闭环驾驶成功率。
