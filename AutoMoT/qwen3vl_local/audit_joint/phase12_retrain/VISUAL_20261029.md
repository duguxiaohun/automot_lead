### 确认的标定问题及保护对照

Phase1 原生表按 `(scenario, rs, event)` 提供 VULNERABLE 默认值，无法保证逐帧覆盖附带出现的骑行者。
训练路线 `VehicleTurningRoute/Town01_Rep0_Town01_Scenario4_10_route0_01_10_19_26_35`
的26–31帧可见路口右侧骑行者，原值为NO；仅这6帧写入新修正，不全场景传播。
同一路线26–38的其余7帧原为YES，保持原样。
完整清单为 `phase1_vulnerable_review_20261029.json`：6修正、12保留、2存疑不改，均绑定原始帧SHA。
叠加旧版5条训练修正；本机两层共11条，远程实际应用数以其回执为准。

特别保护 `VehicleTurningRoute/Town01_Rep0_Town01_Scenario4_11_route0_01_10_10_56_37` 的80帧：
缩略图容易漏看，原始78/79帧中骑行者被30路牌部分遮挡，不能把原YES改成NO。
审图第二意见最初也漏看，放大原始输入后撤回；最终以可见RGB为依据。
两图模式只保留77/80，恰好丢掉较清楚的78/79；该对照提示真实的输入可见性上限。
保留共用标定不代表两图也一定足以识别，需在两图/四图结果里单列，不能靠提示词补造中间帧。

**曝光限制：本机40320步三轮投影中，上述6条新增修正的曝光均为0。**
仍遵守原采样方法，不强插、不换种子挑结果。修正进入了数据池，但本机这份计划不能凭它学习；
新提示词会应用于所有入选样本。远程成员可能不同，应从原生包内 verified_training/exposure/rank_*.json
核对实际曝光，不能把“修正了数据”描述为“模型已经学到了这些修正”。

Phase2 高速8个错误窗口来自同一路线，不能当8条独立场景：
f101/104/107 有明显边界跨越，属于真实漏判；f98弱证据、f115已稳定跟车存在时间边界争议。
本轮只对UE3加局部边界说明，不扩大改动至UE1/UE5/UE6。UE1/UE6还存在距离、遮挡与时间窗疑点，
证据不足时保持标签，不能称全部错误都已修复。原始测试评分不改。

## 独立远程一行命令

在服务器自己的 AutoMoT 根目录，先激活包含训练依赖的环境。模型路径默认
`checkpoints/Qwen3.5-4B`，数据默认 `lead_data`；两台服务器路径不同由当前目录解析。
自动选4张空闲卡，需要指定时在 run.sh 前设置 `GPU_IDS=0,1,2,3`（须实际空闲）。
不会操作其他任务或修改GPU计算模式。

Phase1服务器：

```bash
bash -c 'set -Eeuo pipefail; trap "echo [FAILED]-Phase1-see-error-above >&2" ERR; bash ./sync_automot.sh; bash qwen3vl_local/audit_joint/phase12_retrain/run.sh all 1 --revision visual_20261029 --budget-profile phase1_40k; echo "[DONE] Phase1 training/evaluation/packaging finished; quality pending audit"'
```

Phase2服务器：

```bash
bash -c 'set -Eeuo pipefail; trap "echo [FAILED]-Phase2-see-error-above >&2" ERR; bash ./sync_automot.sh; bash qwen3vl_local/audit_joint/phase12_retrain/run.sh all 2 --revision visual_20261029 --budget-profile bounded; echo "[DONE] Phase2 training/evaluation/packaging finished; quality pending audit"'
```

`all`先模型资产检查，再独立CPU建库/复用与准入，再新训练、评测、打包。
已有父数据可直接复用，不覆盖旧run；数据缺失时CPU建库有心跳和超时。没有报错只能说明暂未检出错误，
持续查看心跳、训练进度和最终退出码。不要用旧run的train/resume或recover_eval执行本次新训练。
需要先只做远程CPU准入时把`all`改为`cpu`；后续`train`必须给相同revision/profile及精确`--run-dir`。

交回全部 `[BUNDLE]`：Phase1两模式primary/balanced共4包＋training_revision_audit.tar.gz；
Phase2两模式各1包＋自己的training_revision_audit.tar.gz。原生包保留完整case、实际曝光与来源证据。

## 新旧公平比较及尚未完成项

P1现在每题八问，历史包含subset/层次问法；整题联合准确率不能直接与旧总分当成同协议比较。
报告须分开：新八问全量成绩、共同RGB/标签/问题交集逐问成绩、两边均为全八问的同题子集、
历史不同协议参考。逐问列分母、precision/recall/F1及原正确→错误；测试标签争议另列，不改主分。
P2仍核对成员、域、标签、输入帧、prompt和adapter身份后比较；高速8窗口单列路线相关性。
时延、token与显存必须附硬件/图数/提示词长度，40k与9k、多问题与少问题的差异不能都算基座收益。

已完成：局部RGB与正确对照复核、P1预算及直接八问、有限train修正、P2局部提示词、CPU准入/回归。
尚未完成：远程新训练、新权重逐题回归、真正的旧正确损失验收与性能提升证明。
不保证任何神经网络更新后零回退；只有新权重原始输出能回答这一点。
