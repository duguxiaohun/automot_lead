# 六动作与 geometry a／b／c 的共同样本实验

2026-10-22 复核修订，当前表示合同 `current_reference_matched_study_v2`。实现用户附件中已经确认的选择；独立入口 `geometry_study`，原 `geometry_v1` 和 `phase3_single_frame` 生产代码、历史库与权重保留。目标是把表示、采样、预算和诊断变成可执行对照；本轮没有新模型精度结果。

## 表示与信息合同

| variant | 标定 | 历史 |
|---|---|---|
| `six` | A–F 原生动作；A/B/C/F 保留各原点的速度与后续证据，只转换已确认 D/E 的方向参考 | 原生过去起点意图；允许使用之后的离线证据，沿用 `nearest_short` 两帧短缺口填补 |
| `a` | 原速度自适应几何规则，横向 ±2 m、原 delta 和边界不变 | 过去位置减当前位置；当前速度与当前车道参考 |
| `b` | 当前 R3：20／24 m；当前 R1/R2/R4/R5：3／13 m | 和未来共用当前道路类别、当前参考及同一组米数 |
| `c` | 全道路 3／13 m | 和未来共用同一组米数 |

b／c 是横向三个区域与径向三个区域的组合，径向使用水平端点直线距离；不是等面积矩形网格，也不按时距缩放。两条径向边界均归 MIDDLE，最远区域不封顶。MIDDLE 不表示匀速；弯道上的几何 LEFT/RIGHT 不表示变道。道路类别未知时不能猜成非高速，记录排除原因。阈值来自上一轮训练候选审计，当前实现冻结它们，只报告新准入池支持量，不拿 test 再拟合。

六动作先执行原生动作及问题域判定。推理与提示词也使用原生事件 `action_keys + KEEP`；例如 LEAD_BRAKE 只允许 A/B/C/F。a/b/c 仍允许全部九类。只有原生已确认的左右变道，才把其局部车道侧向单位向量投影到当前车道右向量；投影负号翻转左右，绝对值 <0.1 标缺失。纵向动作不改成相对当前速度。填补标签使用实际被选中的原生端点参考，方向不确定不会再被填回。保存逐起点原动作、转换后动作、投影、缺失原因和填补来源，便于定位真实改变。

四组共用当前 RGB、速度、导航、事件和道路信息，但六动作历史含离线后续证据，geometry 历史是因果位置。**这不是完全等信息的表示消融**。需要更严格的信息消融时应在相同成员上使用历史清空对照，不能把两种历史混称因果观测。

## 共同池、采样与预算

从原生校验通过的 geometry 库派生。原始六动作规则从同路线 metadata 重放，要求原生当前动作有效，再取六动作与 geometry 未来查询有效性的交集；任一方法无效的查询在四组都屏蔽，没有有效查询的锚点剔除。保留父库划分，重新验证物理路线隔离与开发名单。不是旧 single_frame 锚点列表的逐字复刻，也没有重新划分旧 test。

四组读取同一份派生数据和 `sampling_mass`，共同计划不依赖当前选择的 variant：

- 事件等额。优先未曝光帧，再按实际路线组／4 秒时间段覆盖、实际帧曝光排序。
- 温和类别偏好来自四组全部有效未来目标质量，在事件／时距／表示内混合一半自然分布、一半平方根分布；相对权重上限 4，只作相同新颖性层级的加权随机排序，不保证类别等额或精确目标比例。
- 物理帧身份跨事件共享，每轮最多一次，整个最多三轮的 run 最多三次。共享容量冲突使用增广路径重分配；不足明确拒绝，不放宽重复次数或偷偷减预算。
- CPU 先检查过滤后的 train/val/test 十事件覆盖和四组固定验证指标支持，通过后才投影所有轮次。正式训练仅成功 optimizer 更新后记曝光，各 rank 汇总；下一轮按实际曝光重算并核对共同计划。中断不冒充完成，也不支持 CLI 自动续训。

| 预算 | 每事件／轮 | 四卡 B1、累积 1 每轮更新 | 三轮总更新 | warmup |
|---|---:|---:|---:|---:|
| 新候选默认 | 1280 | 3200 | 9600 | 2500 |
| 同采样政策控制 | 1024 | 2560 | 7680 | 2000 |

warmup 维持 2000/7680 比例；四种表示的模型、优化器、学习率和日程一致。限制仍为每轮 ≤4096、总计 ≤12288 更新、独立启动预算 1h、每轮 10h，100 更新后按实测速率检查 ETA。按旧 geometry 约 2.12 秒/更新，9600 步约 5.7 小时纯训练；六动作须单独实测，不含验证、保存、准备，也不是硬实时保证。

## 训练与评估

用原生小 Qwen3.5 结构相同的四查询读取方式，历史和输出共用现有 A–F／A–I token，不增加词表。六动作保留混合软目标和横向 1.5 权重；几何为单标签。损失仍按全部词表归一化，缺失查询不计算损失，每个锚点按有效查询平均。六动作仅解码施加事件候选限制，保留全部词表原始 token、未限制的六/九类选择及概率；`format_valid` 表示原始输出是否为本事件允许的字母，`letter_format_valid` 仅判断是否为本表示字母。全部词表准确率使用原始输出，不能把受约束选择的正确率算进去。

CPU 准入就固定每事件按 ID 排序前 16 个共同有效验证成员；不足时取已有成员并明确支持量。四种表示分别报告纯/混合/缺失查询、纯类支持、物理路线组与事件查询支持；任一组没有纯类支持、宏平均召回率不可定义时立即拒绝。不得为了通过检查而改挑后面的纯标签成员。训练加载已验证数据时重新计算同一份准入报告，绑定其 SHA 和固定成员到 checkpoint；恢复与评测再次核验。按纯标签的“有支持类别宏平均召回率”选模型，同分取较早轮。完成全部训练预算才写 `training_complete.json`，此后 test 只接受其中选定的 checkpoint；不默认使用第三轮。不同表示的宏平均或总体分类准确率不能直接排优劣。

评估包含事件／时距／类别交叉支持、物理路线组、运动／静止、混淆矩阵、未知历史、历史一致／冲突与拷贝数、历史到未来及相邻未来转换检出／误报率。六动作混合标签单列支持、允许答案命中和原始质量得分，不强行 argmax 后冒充纯类别或确定转换。转换检出并不要求两端都预测正确，另报两端正确数。

`evaluate --split val --ablations` 在相同 checkpoint 和成员顺序上增加历史清空、历史顺序反转、同尺寸黑图三组对照，报告获益／受损与实际发生历史扰动的案例数。这是输入敏感性诊断，黑图不代表自然图像分布，不能仅据此断言错误都由历史导致。扰动预测标为 `diagnostic_predicted`，不能作为普通 expert 预测静默消费。

`diagnose-legacy` 接受**原 geometry_v1 dataset、原模型目录及原 checkpoint**，只在 val 上执行同样的对照，保留原 prompt 与权重，严格核验原合同。没有通过改旧 SHA 让旧模型使用新 prompt。该入口已实现；本机没有运行 4B 旧模型或新模型推理。

`expert.py` 提供模型与 checkpoint 均绑定 representation 的 predicted／oracle／none 条件、原生 FM loss、同噪声配对预测和四组共同 ADE/FDE 聚合。连续 10 个 route 点及 8 个 waypoint 真值不离散化、不截断。纯四查询 oracle 才能进入 hard-token 条件，六动作混合 oracle 明确拒绝，不私自取 argmax；做四组 oracle 对照需预先冻结共同纯标签子集，并报告因此损失的覆盖。新建 expert 时必须先用 `RepresentationExpert(decoder, variant='a')`（或对应组）绑定，再开始训练。`training_loss`、`compare_conditions` 及 wrapper 的直接 forward 都核验模型合同；未绑定原生 expert 拒绝。表示合同写入 PyTorch `state_dict` 的 `_extra_state`，普通 state_dict 加载（包括 `strict=False`）也拒绝缺失或错表示合同。`save_checkpoint(path, model, expected_variant='a')` 保存权重和带 SHA 的回执；`load_checkpoint` 在复制权重前校验表示与文件 SHA。该接口仅保存权重，不声称 optimizer/RNG 续训；不得给未知来源的旧权重套 wrapper 冒充已按该表示训练。旧无合同 expert 不自动迁移。

此处是适配器和指标入口，未自动接入在线 agent，也没有本轮 expert GPU 训练结果。

## 本机准备与服务器入口

数据准备按父库完整 SHA、地图、执行依赖文件清单及表示合同寻址，通过既有 `versioned_data` 锁与完成回执管理。已验证数据复用；依赖变化进入新内容目录；失败目录保留，损坏完成回执拒绝。原生 geometry 库仍由已有版本缓存入口准备；新阶段只生成共同池与标签，不重写原库。当前派生缓存是整体级，尚未把六动作派生细分成逐路线增量缓存。

共同池建库成功不等于正式就绪。CPU 准入报告写入 `admissions/<SHA>.json`，容量计划写入 `plans/<SHA>.json`；两门均通过后 `ready_<quota>.json` 才标为 `ready`。准备开始时该指针标 `preparing`，准入或容量失败标 `rejected` 并保留报告/错误；旧数据、计划、报告、权重仍保留。远程训练启动前核验当前数据 JSON 与源码、准入报告、固定成员、请求预算和完整计划，拒绝旧格式就绪文件；完整原始源在训练 rank 0 加载模型前核验，shell 不重复扫描。

**已知旧 test 的共同池可能缺 LEAD_BRAKE、RAMP_MERGE_EXIT；本次修复让这种情况提前拒绝，不会补出不存在的数据。** 保留原 split，不降低十事件要求，不自动搬动旧测试路线。需要补齐时必须另建明确的新共同实验划分，保留旧划分；本轮没有实施重新划分，不能宣称当前全池已可正式开训。v1 数据/权重不能修改 SHA 后套用 v2；新派生进入 `current_reference_v2` 内容目录。

在服务器**已有 AutoMoT 应用根**执行，发布后同步仍统一用 `bash ./sync_automot.sh`。本轮尚未 push，不能在服务器尚未获得新源码时假设命令可用。

```bash
bash ./sync_automot.sh
bash qwen3vl_local/audit_joint/geometry_study/remote.sh cpu
```

入口自动使用项目 Python／当前 Python、`lead_data`、`checkpoints/Qwen3.5-4B` 和既有 CARLA 地图视图；不指定必须哪台服务器。CPU 阶段通过三 split 覆盖、四组固定验证指标和共同容量检查后，四组可分别运行：

```bash
bash qwen3vl_local/audit_joint/geometry_study/remote.sh train six
bash qwen3vl_local/audit_joint/geometry_study/remote.sh train a
bash qwen3vl_local/audit_joint/geometry_study/remote.sh train b
bash qwen3vl_local/audit_joint/geometry_study/remote.sh train c
```

每条先完成该组训练，再用验证选定模型测试。默认自动选四张空闲 GPU；显式选卡仅用 `GPU_IDS=0,1,2,3`。同政策 7680 步对照在 cpu 与 train 两处都加 `STUDY_PER_EVENT=1024`。输出在 `checkpoints/geometry_study_v1/runs/表示_预算`，碰撞拒绝；重复实验可显式给语义化 `STUDY_RUN_NAME`，不猜最新目录、不覆盖旧权重。

复核修复的当前证据见 `REVIEW_FIXES_20261022.md` 与 `review_verification_20261022.json`。下面的首版验证保留为历史记录；其中 train-only 小池的旧 ready 不能用于正式训练，也不能证明 val/test 或 1280 配额。

CPU 验证包含原生小 Qwen3.5 单图各表示 backward／所有历史字母／保存重载，真实两 Gloo rank 曝光，原生 FM 梯度和同噪声三条件预测，完整共享容量小图枚举，原生原始数据建库、缺失 mask、源变更拒绝及缓存复用。旧 shell 测试夹具同步到当前 profiler 模块入口，昂贵远程准备仍是替身。
