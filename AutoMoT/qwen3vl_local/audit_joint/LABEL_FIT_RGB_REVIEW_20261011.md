# 拟合结果驱动的逐帧 RGB 标定审计（2026-10-11）

当前最明确的标定问题是 **U-E1 用自车坐标的横向速度判断弯道跟车稳定性**；另发现人工参考与弱老师对“完成”的操作定义不一致。两者均应先于继续七轮训练处理。本轮完成诊断和候选清单，**没有修改生产规则、已有标签或生成新训练库**，不能据此宣称标定完成或模型收益。

## 1. 本轮实际完成的范围

- 用已恢复的旧运行源码复算 U-E1 的 181 道已采训练题及 U-E7 的 56 道历史 val：237 道题、104 条路线、218 个不同查询锚点、934 个不同因果历史帧。逐题核验收到的 RGB2/RGB4 图像身份，并重算同锚点 Phase3 原始轨迹动作。这是点查询诊断，不是全路线生产回放。
- 实际目视 19 张联系表和 4 张原图，共 **175 个不同 RGB 帧、10 条路线的局部连续窗口**；原图已包含在 175 帧内。RGB/meta/bbox 共 525 份源文件 SHA 绑定在 `visual_review.json`。选窗已知标签和预测，包含正确例及错误例，**不是 G2 盲标或独立批准**。
- 主诊断在 tmux 中低优先级、单进程运行，限制线程及地址空间；28.77 秒，峰值 RSS 165132 KiB（约 161 MiB），退出 0。未使用 GPU。
- U-E1 的 177 道弱参考的稳定性目标全部复现。当前 v47 的 `facts` 与 `following_stable` 函数 AST 与旧运行版本一致，因此下述坐标问题也影响当前规则。其它模块的版本变化不能据此视为等价。

收到的拟合包边界仍见 [接收复核](TRAIN_FIT_RECEIVED_20261011.md)：本机未加载权重，缺原完整视图，未独立证明已采题全集完整性；原 ZIP 也未收到。诊断使用冻结核心规则和原始本地数据；缺失的基础依赖从当前应用导入，没有绕过准入门。

## 2. U-E1：弯道的正常跟车被当作横向不稳定

[teacher_rules.py](../sft_new_loop_phase4/teacher_rules.py) 的 `following_stable` 要求五帧参与者横向速度绝对值小于 0.25 m/s。`facts` 只给 `cyclist_follow` 分支做 `route_motion` 投影，U-E1 仍使用自车朝向下的速度、朝向及包围盒纵向距离。前车位于弯道更前方时，沿自身车道正常行驶也会在自车坐标产生明显横向分量。

**实帧证据：** `DynamicObjectCrossing/Town04_Rep0_Town04_Scenario3_4_route0_01_10_10_49_29`，看了 f26–67。决定性对象是前方蓝车 actor191；旁侧黑车的运动应另作为并发冲突检查，不能混作同一前车。

f35 的五帧原横向速度约为 `[-1.409,-1.477,-1.594,-1.726,-1.850] m/s`；投影到参与者所在路线段后约为 `[0.102,0.077,-0.002,0.044,-0.035] m/s`。RGB 中前车随弯道行驶，原稳定性失败来自坐标方向，并非它横切车道。该帧间距约 9.22→10.97 m。不是通过放松 0.25 阈值获得的变化。

对全部 94 道 NO 做同一诊断投影，19 道的稳定性由 false 变 true：上述路线 18 道，`HardBreakRoute/Town12_Rep0_2452_0_route0_01_11_03_14_24` 的 f82 一道。19 道里 RGB4 原预测有 15 个 YES、4 个 NO，候选并非只从模型错题挑选。**这不是 19 道已批准改为 YES，也不是模型能挽回 15 题的收益估计。** 原始完整条件还包括其它冲突、优先权、可见性及实例状态；提前完成还会改变后续实例和问题生成。

已输出 `relabel_candidates.json`，19 道均保留 `proposed_target: null`。修复方向：U-E1 的速度、间距、朝向门及前车检索使用一致的因果路线参考系；先验证已有 `route_motion` 对车辆及规划车道的适用性，歧义投影保持 UNKNOWN。保留闭合速度、间距损失和其它冲突门；不只删横向约束，不按场景名特判。落地必须整实例回放，分别统计事实变化、实例提前结束、问题消失及实际准入变化。

## 3. U-E1：其余 NO 主要来自速度门，不能一并翻标

| 失败条件 | 题数 |
| --- | ---: |
| 五帧持续运动 | 3 |
| 最小间距 | 0 |
| 横向速度 | 39 |
| 最大闭合速度 | 51 |
| 最大相对速度 | 7 |
| 相对速度波动范围 | 58 |
| 单步间距损失 | 0 |
| 总间距损失 | 3 |

人工训练题 `HardBreakRoute/Town12_Rep0_3452_0_route0_01_09_04_20_19` f83 标完成 YES；对当帧最近前车作诊断，弱稳定规则会因相对速度范围 **2.005 > 1.5 m/s** 判 false。RGB 窗口 f67–88 显示起步后继续跟车，人工“跟车已建立”与严格速度波动门之间有定义差异。人工题没有相同的参与者 ID 绑定，所以这是待裁决的定义差异，不能直接认定人工错标。该路线 f73–75 的 NO 包含尚未满足持续运动等原因，不能因后续跟车正常全部前移 YES。

另看了 `HardBreakRoute/Town12_Rep0_4432_0_route0_01_09_07_47_19` 的 f74–86 窗口：f80 NO 与 f86 YES 的关键区别为速度波动门；从有限 RGB 判断精确数值阈值存在可观察性风险，需要 G2 有限输入审核，不能仅凭画面相似宣称不可学。

`AccidentTwoWays/Town01_Rep0_route_001544_route0_01_10_16_18_34` 的 f248–263 有真实相对速度波动，不能用弯道解释全部 NO。相反，`AccidentTwoWays/Town15_Rep0_route_001504_route0_01_10_23_59_40` f66 原 YES、RGB4 答 NO：跟车间距约 12.42→12.71 m，相对速度约 0.24–0.29 m/s，RGB 与稳定规则相容，没有找到应改 NO 的证据。**标签问题与模型错误并存。**

## 4. U-E7：人工“驶出路口”与弱老师速度稳定门不一致

56 道历史 val 两模式全 NO，12 道 YES 全错。其中 8 道 complete 已有类别训练支持；另 20 道缺类别支持的 val 中有 16 道 NO 本来答对。因此不能用“没有 release 训练题”解释全部退化，也不能在没有 U-E7 训练拟合的情况下判断模型是否记住其训练例。

已看这 8 道 complete YES 所在三段 RGB：Town05/002062 f28–42、Town05/002066 f48–56、Town15/002097 f44–52。人工证据强调出口边界在后方、车道及路缘对齐、横穿冲突离开；弱老师另要求最近三帧速度均大于 0.5 m/s 且范围小于 1 m/s。

| 路线／锚点 | 三帧速度范围 m/s | 单独速度门 |
| --- | ---: | --- |
| Town05/002062 f41、f42 | 0.736、1.926 | 通过、不通过 |
| Town05/002066 f54、f55、f56 | 2.277、0.999、3.542 | 不通过、通过、不通过 |
| Town15/002097 f50、f51、f52 | 2.366、1.132、3.060 | 均不通过 |

**8 道人工 YES 中 6 道不满足弱老师这一个必要条件。** 这支持“完成判据需要统一”的诊断，不能当作六道完整回放 NO：其中五道所在历史仍有已知负尺寸几何问题；f54 的地图 `is_junction` 仍为 true，也不能仅凭 RGB 直接改地图标志。

待明确的定义是：“路口事件已结束”是否应与“纵向速度已足够稳定”分开表达。建议在双轴状态中保留后续纵向约束，分别审核几何完成、可通行与速度稳定；不能通过把全部人工 YES 改 NO 或删掉全部稳定门来消除分歧。精确阈值应在开发证据与 G2 中确定，这批历史 val 已参与设计，不能再充当独立效果验收。

## 5. Phase3 与 Phase4 的相互照应

本轮按同路线、同锚点重算 Phase3 原始轨迹证据，没有借用训练索引抽样交集。237 道查询中 68 道原始动作返回缺失，保留 null，未补成 KEEP。尚未完成两个阶段的参与者／事件实例关联，不能将这些点查询称为完整 G1 匹配。

例如 Town12/3452 f73 的 Phase3 为 RESUME，随后 f74/f75 为 DECELERATE；Phase4 仍可因五帧稳定跟车条件未满足而答 NO。前者使用未来轨迹定义实际动作，后者判断当前条件，这种差异不自动进入错标队列。统一的是证据、实例身份与操作定义，不要求两个任务同帧输出同义标签。

本次有限题集的精确提示词／RGB 身份检查没有发现完全相同输入对应相反标签的例子；这不排除近似画面下的不可观察性，也不证明全池没有冲突。

## 6. 下一次本机落地的验收边界

1. 优先做 U-E1 路线参考系修复的独立版本；用上述两条路线及正常直线、弯道、真实横切、歧义路线作回归，整实例重放后审核改标，不在旧数据上重写合同。
2. 单列“完成”定义裁决：人工／弱老师、跟车／路口分别核对；保留原人工参考和逐条件证据，不把历史 val 答案当阈值搜索目标。
3. 对速度波动与输入可观察性做 G2 第一轮有限输入审核，再看完整视频／元数据；不能用本轮有预测提示的目视结果冒充盲标。
4. 修复后再扩大正式 Phase3 池和 Phase4 生产覆盖，完成跨任务隔离与六事件开发评估。事件呈现等额不代表 YES/NO 为 1∶1，也不代表缺分支已经补齐。
