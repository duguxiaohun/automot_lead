## RE5 的具体变化

此前相同 RGB、不同目标出口的 `proceed` 文本完全相同，`complete` 又允许把普通跟随理解为整个环岛任务结束。现在保留 `YIELD → PROCEED → DONE`，遇新冲突使用已有 `re_yield` 回到 YIELD；不增加状态数。

- `target_corridor` 与方向进入当前/候选下一状态描述；模型仍只回答 YES/NO。
- 环岛必须由导航/跟踪上游提供 `route_context`，包含 `kind=roundabout`、`completion_boundary`、`navigation_evidence_id`。目标出口和实例结束边界进入状态文字；证据 ID 不进入模型。
- 导航目标应是当前可定位的出口/走廊描述。仅给内部道路 ID 或需要长历史才能数出的“第几个出口”不足以解决可观察性。代码校验字段完整性，不能自动证明自然语言与地图/RGB 对齐。
- 环岛 `complete` 同时要求 `event_resolved`、`route_exit_reached`，后者指已经到达**指定出口边界且清空环行冲突**。环岛内稳定跟随、经过非目标出口均不够。
- 完成环岛几何阶段不要求解除独立纵向限制：`complete=YES + hold=YES` 可进入 DONE/HOLD 并保留 STOP。只有纵向恢复稳定才退出实例。
- `catchup` 也必须审核出口条件；缺失/不确定不补 YES，明确不成立为 NO；未来证据拒绝。没有固定 ±0.5 秒扩窗。
- 环岛执行回执和回放真值绑定 `route_context_id`。错目标回执使整帧事务回滚；更换出口或实例边界须建立新实例，不能通过原实例复核接续旧许可。
- 三条已知环岛来源缺导航上下文时，构建/条件流编译/加载拒绝。该登记仅是已知来源的准入保护，不是所有环岛的自动检测器；其它来源仍依赖上游正确声明。

实际入口为 `route_prompts.py` / `route_calibration.py` / `route_context.py`，构建、训练编码、评估、实时预测、序列回放和 demo 已统一接入。旧 `prompts.py`、`calibration.py`、taxonomy 和 observation 是原冻结评估规则，未改 SHA；不使用路线扩展的题目委托原实现。冻结 holdout 协议拒绝用旧协议声明新环岛语义已验收，需要另行前瞻冻结独立评估。

训练覆盖新增三 split × `proceed/re_yield/complete` 共九个环岛支持格，要求 readiness YES/NO，普通路口和 catchup 不能填充。九格目前全缺。

## 接口示例

```python
from qwen3vl_local.sft_new_loop_phase4.controller import Episode
from qwen3vl_local.sft_new_loop_phase4.route_context import route_identity
from qwen3vl_local.sft_new_loop_phase4.route_prompts import prompt

ep = Episode(
    'R-E5', 'roundabout/entry-1', longitudinal='HOLD',
    target_corridor='exit beside the red building',
    route_context={
        'kind': 'roundabout',
        'completion_boundary': 'past the exit mouth and circulation conflict',
        'navigation_evidence_id': 'upstream-current-route-receipt',
    },
)
# 以上文本必须由真实当前导航落地；不是这批审计路线的标签。
question = prompt(ep, 'proceed', {
    'frame_id': 20, 'history_frames': [16, 20], 'speed_mps': 0.,
})
# executor/causal_tracker 的真实执行回执还须包含原有实例、边集和因果帧字段。
route_context_id = route_identity(ep)
```
