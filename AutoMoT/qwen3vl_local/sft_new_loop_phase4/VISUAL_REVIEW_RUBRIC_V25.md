# v25 方案 B 的可复核视觉审核口径

本口径是保守的开发标注准入，不是交通法规、已认证驾驶阈值或教师准确率。条件无法确认时标 UNKNOWN，不能由“未达到 YES 门槛”推导 NO。模型仍只看状态对与因果 RGB；内部证据不进入提示词。

1. 分别审核实际 2 图 `[f-4,f]` 和 4 图 `[f-6,f-4,f-2,f]`。审核卡输出两份面板，不能借用中间帧/未来帧替某种输入证明后继状态。每种模式须绑定这些帧的文件 SHA、当前可见区域坐标及观察。可允许4图支持、2图未知；构建按模式隔离，加载再次检查。
2. 补问 YES：自车已恢复行进须指出同一相机内、同一静态地标从 f-4 到 f 的图像坐标，位移至少6像素，并解释相机旋转、震动及透视影响；地标不能是旁边正在移动的车。已经进入目标车道/完成事件须在当前图定位车道边界和本车相对位置，明确可见几何。`successor_confirmed=True`、速度非零或专家动作不能单独作为证据。数值与勾选只能提高可复核性，仍需独立审核核实真实性。
3. UE1 readiness YES：当前图有明确近处可用跟车走廊；f-4→f 能定位同一前车可见特征/轮廓变化，至少6像素，且经来源可核的几何辅助证据确认车头间距增长至少1米。二者都要满足；只在 bbox 有微小位移、画面无法判断、刹车灯不清时弃答。米制差值只作辅助，不替代RGB证据。原稳定跟车条件未改变。
4. UE4 proceed YES：可见完整参与者轮廓已经离开当前自车规划走廊，轮廓近侧到走廊边界的**保守下界**至少1米，且因果图像显示继续远离；或已完全上到与车行走廊分隔的人行区域。须指出当前图的边界、轮廓及距离估计依据，不能用参与者中心距代替外轮廓余量。透视/车道边界/路缘不清，不能填伪精确距离，记 UNKNOWN。仍在走廊上的明确冲突为 NO。无需等参与者横穿整条道路；仍须排查后续近处参与者。
5. UE7：实例要求上游已建立的、可用于当前输入解释的信号失效证据，适用灯头和车道须匹配，并排除普通有效红灯等待。源场景名字、逻辑 Red、逻辑 Off/Unknown、RGB与逻辑不一致都只能检索身份待审卡，不能单独建立实例。可见相邻方向绿灯也不能作为本方向通行权。故障无法区分时不把其通过帧强行补为首个 UE7 YES。
6. 横向进入只判断已知目标的可见范围，必须复核当前旁侧车辆；不对后方不可见范围作结论。机动执行仍须独立安全许可。未改导航几何和目标走廊由当帧已知输入/审核明确，不能从未来专家绕行倒推。
7. 审核者先看隐藏规则建议的输入卡、写事实，再给答案。队列不携带逐卡建议答案/排序分数；统计表按层汇总建议分布，不能用其替代审核。这降低确认偏差，但本轮Codex已接触旧规则建议，不能称真正盲审或独立认证。
8. 训练数值下限按每个事件转移/答案的不同物理路线计数：readiness YES和NO各20路线；val/test各事件各5路线。重复帧、重复训练、补问不填此缺口。独立40路线审核另报；不能由测试通过或数值下限满足推断准确率。

v25只对新增/复审的半自动证据强制本合同。旧冻结人工标注未被自动宣称重新满足此口径，原独立评估只代表旧审核协议及其四事件范围。若扩展评估协议，须独立复核，不能由规则编写者自行补造独立标签。
