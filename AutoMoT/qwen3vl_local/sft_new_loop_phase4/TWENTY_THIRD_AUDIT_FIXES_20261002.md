# Phase4 v23：静态冲突、跟车语义、可见异常与自动上下文

结论：用户对 v22 的主要判断成立。本轮修正了直接影响几何候选的缺陷，接入部分自动上下文；**仍未获得可批准的自动监督，也未达到正式训练条件**。全量采样应覆盖冻结路线池，但不要求把每个原始帧强制变成 YES/NO；应记录 UNKNOWN/排除及其原因，只在有可靠条件证据的帧构题。

## 修复与证据

- **静态障碍不再因语义计数为零而消失。** `privileged_geometry.visible` 对静态物体使用现有投影 RGB 质量筛查，不依赖 `visible_pixels`；`maneuver_facts` 中任何占据走廊但未能判定可见性的物体都使间隙未知，不能跳过后变成 YES。ConstructionObstacle 002000 第35帧已用原图复核；真实数据的静态走廊组件检查不再给出空走廊。图像质量通过只是候选证据，不能认证遮挡、物体识别或整体可见性。交通灯停车线代理框不再被当成物理障碍，通行权仍由独立条件约束。
- **UE1/UE3 的正常跟车不再自动否定 proceed。** 在身份、通行权、可见空间已绑定的场景上下文中，连续观测支持安全间距/相对运动的同一前车可保留在走廊内；其它参与者仍阻挡或使其未知。测试覆盖仍有前车时 YES，以及加入行人后 NO。停车候选由车速下反应及制动距离计算，并覆盖15m内走廊行人，修复“只有距车头2m才需要等待”；此阈值尚待真实逐帧标定，不是经认证的安全规则。
- **画面风险与清单风险分开。** 缺失/跳变仅在物体整个水平包围圆确定处于所有相机外时标为 `inventory_only`；暗图、零像素、边缘露出、未知标定均不能据此断言画面外。跳变前后任一端可能入镜仍是 RGB 风险。RGB 条件不再被仅画面外删除否决，回放安全许可仍检查全部清单异常。1150_0 第127→128帧在45m检测范围内有13个缺失，全属清单风险；这不等同于用户报告96m清单内20个删除的逐一认证。
- **UE5 候选使用当前规划路线的分段走廊。** 取消有导航时的同 road/lane 硬条件，带0.5m侧向余量召回近中心线对向车。1150_0 第127–151帧25帧均有候选；676_0 第57–87帧仍为零。余量只产生待审假设，不把相邻车道贴近行驶直接定为真实侵入。
- **修复整帧诊断丢失。** Town05 的 `static_prop_car` 有负 extent，旧投影会拒绝整帧。现在保留原始负值及异常，绝对值包络仅用于诊断；任何含该异常的因果历史都不生成条件许可，安全适配同样拒绝。两个路口样本全部114帧均有这类问题，不能因候选恢复就称几何已合格。

## 自动化已接入什么，仍缺什么

新增 `automatic_context.py`，默认生产不再完全没有上下文：

1. 从当帧 `route_original`，或明确 `changed_route=False` 的 `route` 取得规划路线，逐段计算走廊。LEAD `expert.py:save_meta` 的这两个字段是当前规划器的剩余路线，以当前自车坐标保存；未读取未来执行轨迹、专家控制或未来车道。缺少未改路线时不使用专家已偏移的绕行轨迹倒推许可。
2. 输出明确作用于自车的交通灯/停车标志诊断、停车义务候选。红灯不能证明信号故障，绿灯不能证明全部横穿冲突已解决；traffic_light 框可能是停车线代理，不能用其投影认证灯头 RGB。`priority_satisfied` 保留未知。
3. 用连续身份和相对位置给出“已到身后”的局部事实；不以 ID 消失当完成，不从假设 RECOVER 声称有真实恢复历史。
4. UE6/UE7/RE5 接入路口候选假设。UE7 的故障身份、RE5 的无灯身份均须确认；灯列表为空不是无灯路口证据。源场景名称仍不充当事件真值。
5. 当帧规划走廊内的可见阻挡进入默认条件提议，可给出部分否定事实；空清单、未解决空间与未建立实例状态不产生正许可。完整横向导航目标/机动历史，可靠优先权、可见性及事件边界，以及安全适配的三个外部证据来源仍未齐备。

实跑17条训练路线、1615帧：1465帧可取得未修改的当前导航，150帧缺失；产生6066个待审状态对、覆盖8类候选，RE2/RE3 自动实例仍缺。133个异常候选中64个可能影响 RGB、69个仅清单风险，未逐一人工确认。两个路口来源现在有UE6/UE7/RE5假设，但不代表三类实例标注已完成。**6066个训练目标全部 UNKNOWN，新增监督为0。**
