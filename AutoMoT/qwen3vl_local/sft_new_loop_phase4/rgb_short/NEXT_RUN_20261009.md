# 短跑后：完整预算一轮、保存重载、交接

本轮交接目录 `phase4_short_smoke_handoff_20261009.audit` 的1244文件、两组输入/基座/配置及239道val逐题记录核验通过。RGB2参考一致率52.30%、YES召回11.32%；RGB4全部回答NO，一致率55.65%、YES召回0%。每组只有40次呈现、按配置2次更新，不能比较最终效果。现在先各跑完整预算1轮，再看是否延长到7轮。Phase3/Action恢复不阻塞这轮单任务开发实验；旧G0状态不自动升级。

以下命令均在服务器 `AutoMoT/`、原 automot 环境执行。先更新到含本次改动的代码。四卡训练和随后单卡重载串行；只复用现有四图库，不再全量回放或复制production。

## 1. 只生成新版小视图

本次新增诊断/运行记录改变学生源码合同，旧视图与短跑权重继续保留。新目录须未存在：

这里只扫描/核验已完成data4并写一个小JSON，不再编译题库。若源码合同不匹配，先保留报错，不删库、不改旧SHA。此前旧版view不可直接交给新版训练器。

## 2. 两组各完整训练1轮并自动重载

直接从同一基座启动新实验，不传短跑adapter、不传 `--epoch-samples 40`。

```bash
set -e
for mode in 2 4; do
  DATASET=checkpoints/phase4_short_observed_20261009/view \
  OUTPUT_DIR="checkpoints/phase4_full_epoch1_rgb${mode}_20261009" \
  RGB_MODE="$mode" \
  bash qwen3vl_local/sft_new_loop_phase4/rgb_short/run.sh --epochs 1
done
```

默认每事件1024次、全局10240次；四卡各2560次前向、accum8各320次更新。每轮不是遍历330902题。默认自动选四卡，需要固定时在 `DATASET=...` 前加 `GPU_IDS=0,1,2,3`。

每组训练结束后，入口释放DDP进程，在所选四卡的第一张上启动**新进程**重新加载已保存的最后一轮adapter，完整生成同一val，并和保存前逐题预测比较。权重/处理器等资产及优化器字节均核验，预测不一致返回2，保留诊断结果；只有训练和重载都成功才更新base目录的 `latest`。重载是额外一次完整val，耗时单列，不能算进训练吞吐。它不实际恢复优化器训练，也不保证后续优化器resume已经实测。

失败后不要重复完整训练：若仅重载失败，可检查原run的日志/JSON，再显式执行 `python -m qwen3vl_local.sft_new_loop_phase4.rgb_short.reload_check --help`，传原run与新 `--output` 路径复查；既有失败报告不覆盖。

重载开始前即创建 `reload_check/checkpoint_reload.json`，每个阶段先写 `in_progress`。资产校验、模型加载、验证中途或结果比较异常会留下 `failed`、失败阶段、错误类型/信息及截至失败时的身份核验结果，退出码为2；Ctrl-C为130。报告随交接包保留。验证中断不会把内存中的部分结果当作完整val，完整指标只在验证和比对完成后保存。进程被强制终止时可能只留下最后的 `in_progress`，不能当作通过；输出目录无法创建或磁盘不可写时也无法保证报告落盘。

新增结果：

- `epoch_000_samples.jsonl`：全局有序题目ID、rank分配、目标及原始标签来源；sampling清单绑定全局/各rank题序SHA。
- `epoch_000_rank{0..3}_steps.jsonl`：各rank实际完成题目、loss、token数、更新次数及同步后的每步墙钟耗时。不是预估题序，也不是GPU kernel耗时。
- `epoch_000_runtime.json`：四rank训练耗时/平均loss/训练阶段峰值显存、rank0验证及保存耗时；不存在的CPU显存填null。
- `epoch_000_validation.json`：原选优一致率保持；另列答案分布、YES/NO召回、平衡参考一致率、常量回答/不优于多数类参考警告，逐事件也报告。
- `data_admission.json`：保留短输入转移参考分类，同时补充原始弱监督数量，避免把RGB2的`weak_supervision_rows=0`读成全部人工题。
- `epoch_000_checkpoint.json` 与 `reload_check/checkpoint_reload.json`：保存资产SHA、优化器身份、实际重载和完整val比对。权重/optimizer本体不入包。

诊断警告不伪造审核批准，也不自动改变选优策略。若仍全NO/全YES，或YES召回近0，先交回结果定位，不机械续跑7轮。源码/采样策略/标签不应在两组中途改变。

## 4. 审核完整一轮后，再续到总计7轮

只有新版**完整预算一轮**的checkpoint可以按以下配置续训；不得拿40次短跑来续，不能换源码/视图/预算或world size。原epoch1 run和其中best依赖必须保留。

RGB2示例（RGB4同样替换为4，串行运行）：

```bash
P4_RESUME2="$(readlink -f checkpoints/phase4_full_epoch1_rgb2_20261009/latest)/epoch_000"
DATASET=checkpoints/phase4_short_observed_20261009/view \
OUTPUT_DIR=checkpoints/phase4_full_epoch7_rgb2_20261009 RGB_MODE=2 \
bash qwen3vl_local/sft_new_loop_phase4/rgb_short/run.sh \
  --epochs 7 --resume "$P4_RESUME2"
```

`--epochs 7`表示总计7轮，只追加第2至7轮。后续交接同时包含原epoch1目录和续训目录，不能漏掉继承的best来源。常量回答消失也不代表十事件独立准确率验收通过，当前val仍仅4类事件。
