# Phase4：按逐帧RGB确定成立范围与旧状态补问范围

本轮修正的是上一版把“前后0.5秒”的例子直接写成固定扩窗规则的错误。**现在没有全局或按事件写死的前后帧数，靠近记录转移点本身不会产生YES。** `reviewed_state_pairs_v2.json`仅保留历史，不再作为默认输入；新构建器拒绝`transition_point_window`。

本轮实际顺序查看了45个连续窗、720次帧呈现、701张不同RGB，覆盖十事件、10个Town、36个物理组。36窗是原审阅片段复查，9窗继续向后查看；125张是此前未审的新图，累计不同RGB从1416变成1541，不能把701全部称为新增。录像较短的三个续窗包含重叠帧，已去重计数。新增图均属于既有曝光路线，仍是train-only。

证据保存在`rgb_boundary_review_v3.json`：逐帧RGB/meta SHA、原路径、审阅范围、每条路线观察。模型只接收原始因果RGB；面板上的速度、road/lane编号用于审计定位，不能独立证明条件成立或完成，也不进入模型文字。

## 标定判断

1. 先找当前所问边的实际条件：允许起步、允许借道、已经进入借道车道、已经超过最后参与者、允许回切、已经回切完成，是不同问题。起步帧不能替代横移帧。
2. 每帧记录`readiness`、`catchup`、`uncertain`或`excluded`。readiness必须有本帧条件证据；catchup必须观察到后继状态，并复查当前没有新冲突。两者都使用同一个旧状态对，仅输出YES/NO。
3. “快完成了”不能提前标成“已完成”。完成类边最早YES不得早于本轮明确观察到完成的帧。机会类边可以早于示范执行，因为条件已经成立而示范仍在等。
4. 下一阶段、新冲突、普通行进已占主导时，停止采这个旧问题；这不表示截止后的正确答案自动变成NO。看不清的边界进入待审，不用未来运动反证当前许可。
5. 窗口结束仍未见终点时标`review_end`，即右删失。表中此类“后几帧”只是已经看过的可用范围，不是最晚合法补问范围，更不能推广为该事件的固定阈值。

参考帧分为`successor_observed`（首次明确看到开始执行/后继阶段）、`condition_onset`（只确认条件开放）、`milestone_observed`（已经完成）、`not_observed`。偏移量由逐帧结果汇总，不反过来生成标签。4Hz下1帧约0.25秒；表中的“前2、后2”包含参考帧共5帧，但不同路线无需相同或对称。

## 数据与验证

新默认含46条逐帧转移审核记录，以及11条未被本轮路线复核替换的既有审核区间；不继承被复核路线上的旧冲突标签。两种RGB模式均构建429道二元开发题：323 readiness、106 catchup；另外121条证据不足题进入待审队列。所有题仍是train-only。catchup不能补齐readiness覆盖缺额。

`calibration.py`验证逐帧完整性、本帧证据、完成类不得提前、旧问题截止及当前阻挡优先。`dataset.py`按逐帧标签构题并验证RGB哈希，不再调用时间膨胀；缺失/不确定帧不转NO。提示词强调“条件已经成立或后继刚达成”，并禁止把“快要完成”当作“已完成”。评估分别统计readiness与catchup召回。

源码/默认标注/审阅证据绑定v3合同，须新索引、新run；v2 adapter和旧索引不可直接复用。训练、生成评估、预测状态回放、动作先验及路线分支功能保留；Phase3稳定版与Action默认未改。

本轮专项107项通过，含真实小型Qwen3.5多模态答案mask/LoRA反向。2/4图开发数据全量历史RGB哈希核验、各7轮×world1/4采样回放通过。无独立val/test及完整分支标注，且本地缺完整4B权重，ready=false；未正式训练、未真实GPU/DDP/CARLA验收。
