# Phase4 连续 RGB 审阅与首版标定

历史说明：下述为首轮审阅记录。曾将用户的0.5秒例子误写为v2固定扩窗；该规则已撤销，新默认与本轮逐帧复核见[RGB_BOUNDARIES_V3_20260929.md](RGB_BOUNDARIES_V3_20260929.md)。被本轮复核路线上的旧标注由v3替换，不合并旧窗口标签。


实际检查了 92 个连续窗口、1,472 次逐帧呈现，按原始路径与 SHA256 去重均为 **1,416 张 RGB**，来自 81 个物理路线组、11 个 Town。每窗16帧，4Hz，按时间顺序逐帧观察两页拼图；原图1152×384，拼图内等比缩至798×266。没有把自动渲染、轨迹数值扫描或场景名计为目视确认。未声称逐个看完所有数据集路线，也未用图像目估得出精确米数/TTC阈值。

初次候选扫描8,614条路线、产生2,982个候选窗；按事件、Town、场景和物理路线差异选80窗，每个候选context八窗。另补UE4沿路骑行12窗，包含Town12/13、同向邻道与对向借道。已有连续窗重复部分按图像去重；同一条录制不算新的独立路线。

完整记录见 [rgb_review_20260929.json](rgb_review_20260929.json)：包含每窗场景名、Town、route ID、帧号、RGB/meta哈希、逐窗观察、证据不足标记、开发隔离组。人工书写的逐窗笔记见 [review_notes.json](review_notes.json)。图片产物在本地 `probe_output/rgb_20260929/`，不入库。

重点完整骑行过程：p4_091（HazardAtSideLaneTwoWays / Town13 / `Town13_Rep0_1227_0_route0_01_10_21_55_12`）64–67等待对向车，68–70进入借道走廊，71–76依次通过骑手，77–79返回。p4_080–082显示同向左邻蓝车先占据入口，之后才具备绕行机会。p4_083–085则被接连从左后方经过的车辆打断，不能把最初YES一直保存为有效许可。

本次看到了“短窗口内没有返回”的例子，但**没有因此认证UE2路线不要求返回**。代码已保留该分支，进入分支需要导航/路线证据；其专项训练支持仍需补充。这里严格区分“代码支持”与“已完成实证标定”。

首版[条件区间](reviewed_intervals_20260929.json)为46个已注明证据的区间，构成204道开发问答。包含连续正例、明确未满足条件的负例、证据不足的UNKNOWN和单独的catchup补问；不是完整训练集。没有把整段窗口的观察笔记自动扩展成全窗许可标签；没有用未来控制/未来变道时刻提前若干帧改YES。未确认的权限、后方间隙和低能见度不补造。

所有上述81个物理路线组连同Phase3已有开发曝光组只入train。当前开发集无val/test，UE3、UE5、RE5在这份少量区间中还缺明确YES，INVALID也尚无已发布标注。正式入口会报告不足并拒绝训练。进一步生产标注应覆盖每条转移和路线分支，尤其UE2不返回、UE4同向绕行、未执行许可失效、事件重入与中途接管；需要冻结规则后使用独立路线审核，不能把本次看过的路线挪入盲测。

以上是流程、标签与提示词的开发结论，不是新LoRA效果、闭环驾驶成功率或4B GPU验收结论。
