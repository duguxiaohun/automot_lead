## 1. 目标与保留的语义

Phase4 判断给定事件实例和当前状态下，一条适用转移边的条件是否现在成立，或后继是否刚刚实现而输入状态已经过时。readiness、catchup、几何完成和运行时执行许可分别保留。

事件轴记录 WAIT/YIELD、DEPART/CROSS/PASS/RETURN/DONE 等机动阶段；纵向轴记录限制、停车、恢复、稳定跟随等状态。横向通过或完成不能自动移除纵向限制。当前条件成立不是永远成立，新冲突可撤销 readiness。[状态与边](taxonomy.py)、[控制器](controller.py)、[运行时](runtime.py)

横向 depart/enter/return 的语言判断限定在所见相机范围；未见后方/侧方不能被模型 YES 认证。真正执行仍须当前规划器/BEV 的完整机动许可及执行回执。[实际问题范围](route_prompts.py)、[执行许可](maneuver_safety.py)、[可见范围合同](visible_scope.py)

当前老师 UNKNOWN、风险过滤、人工未知和非法模型输出不是同一种状态。模型生产输出仍是 YES/NO；数据中 UNKNOWN 不自动意味着已经训练了第三种输出。若将来新增拒答协议，必须作为显式任务变化。

## 4. P4-G0/G1：建立来源完整的逐帧账本

先在已选开发路线从必要历史起点连续回放固定版老师，保留每帧的有实例/无实例/UNKNOWN/不适用及失败原因；Phase3 同路线上逐帧重算标定器和原 context 来源。两套按配额抽样的训练索引只用于追溯入库/曝光，不能作为时间线帧集合。按总方案 §6.1 做同帧全外连接，缺历史不由未来补齐，也不按锚点重启老师状态机。

每题关联物理组、实例、参与者身份、方向、目标走廊、分支、return policy、路段、事件/纵向状态、适用边与精确输入。记录条件三态、来源和 observed_until，以及 rule target→监督准入→最终入库的变化原因。

把 `execution_observed`、`permission_granted`、`readiness_yes`、`state_synchronized` 分列。离线看到车辆已横移可以同步回放状态，但不能倒推当时已经安全，也不能生成新的人工/严格监督。

对每条边保存条件成立与撤销的连续区间，不能只留 first_yes；记录右删失、缺图、参与者消失、身份跳变、下一实例和问题停止适用。停止采旧问题不一定等于条件变 NO。

来源包括老师的连续历史，而不是仅当前入库图像。即使最终只输出两图，也要知道标签用过什么信息；否则无法审计隐含 STOP 义务、普通跟随稳定性或故障身份。

跨 Phase3/Phase4 按总方案 §6.2 的录制身份、同锚点、参与者与目标关联。执行映射以 [taxonomy.py](taxonomy.py) 的 `CONTEXT_TO_EVENT`、`template_for` 和 [route_context.py](route_context.py) 的 `episode_edges` 为准，文档表仅为快照。先独立统计 `event_presence_mismatch`，区分仅一侧检测到事件、未知/缺数据和同类不同参与者，再对可比命题按原五类原因分析；上游分歧不自动归咎任一老师。

审核执行总方案 §7.1 的两图锁定→四图锁定→第二轮完整证据流程；独立双审与顺序偏差单列。第二轮特别检查 STOP 连续停稳、信号适用身份、普通跟随稳定观察、参与者消失和相机外范围。有限输入不确定与完整事实错误分别登记，不能用第二轮补齐第一轮的可见证据。

按事件×边×分支×图像配置报告 UNKNOWN、分歧、source issue、老师正确/错误及不同物理组数。稳定状态与边界状态、静止与运动、readiness 与 catchup 各自分层。

批准优先级和预算统一见总方案 §7.3：先做 UE1/UE4 指定 proceed 分支的容量检查，再决定是否预约严格批准；六事件开发 val 单独补齐；稀缺 return/分支及不可观察类保持明确弱监督或 UNKNOWN。五路线试标不能支持通用不可判定率决策，缺路线时不批量发卡凑题数。

## 6. P4-S1：边界监督处理

S1 的前提是审核确认当前监督存在证据不足或边界不确定。当前链路已经有 UNKNOWN/review 排除，所以先统计新增被影响的题数；不能在没有实际变化时声称加入新机制带来收益。

明确 NO 保留 NO；明确 YES 保留其逐帧证据；未知保留未知理由并不进确定目标。取消监督时不能留下虚构答案 token、也不能让 EOS 单独给该题产生正样本权重。全空有效监督要按训练/DDP 合同安全处理。

严格 test 不因 S1 自动删题。报告完整固定参考、明确参考子集、coverage 和未知比例；若原参考本身被可靠证据纠正，另出数据纠正版，并将旧模型与新模型在相同新参考上重新评估。新旧指标不能混成一条无缝提升曲线。

46 条旧 band 不生成提前容忍参数；`reference_kind`、stop kind 和 source 必须保留。catchup 检查当前针对该转移的冲突；几何已完成不需要重新“撤销几何”，但仍保留独立纵向限制。

若目标是减小转移延迟，执行总方案 §9.1：先证明回答偏晚且不只是许可/执行等待；S1 仅在确有不确定监督时试。已确认后继状态的 catchup 权重另列采样实验，未确认的 v42 候选不能直接转成补问 YES。若缺静止 readiness 的可观察正例，应补证据/输入，不能用 catchup 替代，更不能扩大首次 YES 到明确 NO 区间。

## 7. P4-S4/S6：输入改善与公平对比

### 7.1 两图跨度与图数实验

| 组 | offsets | 作用 |
| --- | --- | --- |
| A，现有两图 | `[-4,0]` | 旧输入基线 |
| B，候选两图 | `[-6,0]` | 与 A 比历史跨度 |
| C，现有四图 | `[-6,-4,-2,0]` | 与 B 比同跨度下中间观察的作用 |
| D，短跨度两图候选 | `[-2,0]` | 0.5 秒；与 A/B 构成 S4d 跨度对照 |

A/B 为原 S4a，B/C 为 S4b；D/A/B 为新增 S4d，不在一组比较里同时换图数和跨度。共同锚点以最长臂历史可用性与风险包络条件选定。仅部分臂可用的早期锚点和风险题另外报告，不能让某臂在更容易的样本集合上获得表面优势。

同时给出两个视角：固定共同题集上的配对结果，以及各配置实际可观察/可监督范围。B 无法判断而 C 可判断的题是图像配置能力差异，不能强行给 B 确定答案，也不能只保留双方容易题而隐去 coverage 差异。

新输入合同需贯通构建、SHA/像素身份、风险包络、加载、prompt、checkpoint、runtime snapshot、配对训练和评估。不能只改 `observation.py` 的 offsets，继续复用原审核和旧 adapter。

重点报告静止起步、前车起步、readiness/catchup、边界前后及重新 NO 的连续片段，同时报不可判定率和风险排除量。画面变化大可能是运动证据，不能一概视为噪声；图像跨度缩短也不取消老师历史证据中的风险。D 是 C 的子集，但 A/B/D 彼此并非子集，按总方案 §9 隔离不同两图臂的首轮审核；各臂单独采用两图→四图顺序，避免互相补齐历史。

S4e（暂缓）才考虑四图改为 `[-3,-2,-1,0]`：跨度从 1.5 秒降为 0.75 秒且图像变更，现有人工视觉审核、精确 SHA、配对身份、风险范围和规则批准不能直接迁移，需要新输入审核与覆盖证据。保持原四图也能共享缓存，例如 t、t+2、t+4、t+6 四锚点共有七图；只有它们原本就在同一更新才属于 E4，额外选入仍属 P2。

### 7.2 新增可部署信息

S6 的第一个低成本候选是把 observation 已有的当前 `speed_mps` 真正渲染进提示词，先验证其部署来源与当前时刻可得性，固定单位、精度和缺失表现；其他输入不变。它与增加“历史速度序列”是两个实验，不能同时加后把收益归给当前速度。

格式优先沿用 [Phase3 prompts.py](../sft_new_loop_phase3/prompts.py) 的 `Current speed: {value:.3f} m/s.`，便于联合对照；Phase3 缺失时显示 `Current speed: unknown.`。这只是格式复用，不能据此改变 Phase4 当前数值校验或静默允许缺失；部署缺失如何拒绝/回退须单独规定。两任务的输入合同与标签语义仍分别保留。

若审核显示速度历史、STOP 状态凭据或目标信息是主要缺口，后续分别试：列出传感器/状态估计来源、时间戳、更新频率、噪声、延迟与缺失回退。精确模拟器标签或专家未来控制不能直接变成线上输入。新增字段后重新做精确输入盲审和 paired identity，旧输入的可观察性结论不自动迁移。

如果把义务判断移到可靠确定性模块，可将 VLM 问题改为有限视觉子命题，再由控制器组合。但这会改变任务职责与依赖，应单列实验，不能称为原标签单纯变得更容易。

## 8. P4-S3：问答精简而不删除双轴信息

先看一个状态下哪些边实际适用，再判断是否存在部署条件可确定的冗余命题。确定性推导必须注明输入来源、失败时 UNKNOWN/回退、与其他边的矛盾处理。

不能把 restrict 和 hold 无条件合并，也不能认为 depart/enter 自动吸收 release、settle、stable、recover_follow。绕行等待可以移动跟随或静止停车，进入后也可能继续受限；一个主要动作 token 不代表这些事实不再重要。

完整保留纵向/事件两轴、return policy、相邻路段边界、target corridor、可见范围、执行许可和回执。省问前后在同一事实输入上比较问题集合、状态轨迹、最终 prior、待确认状态和 recheck 行为。

错误事件测试应包括错误参与者、过时状态、错误目标、缺分支和多实例冲突。只给正确事件/状态的逐题准确率是条件能力，不能当作整个 Phase1/2→Phase4 链路的效果。

## 9. Phase4 E 系列：计算优化

先按总方案 §5.1 核对四卡实际快速内核，不能只看安装列表；本地缺依赖会 warning 后回退。E0 已确认应优先量的两个入口：训练循环同步 `encode`（含 SHA/解码/processor/H2D）和每轮 rank0 串行 `evaluate_rows`。后三卡在验证阶段等待，不等于整轮都闲置 75%；应分别报阶段占比与整轮墙钟，再确定 E5/E6 的收益。

E5 见总方案 §8.8：把现有 `encode` 的 CPU 工作与末端 `.to(bundle.device)` 分离，worker 只预取 CPU 张量并保留全部身份校验，主进程做 pin/异步 H2D；有界队列按原题序消费，不先改采样。E6 见 §8.9：全局冻结 val 清单后分四卡 B=1 生成，汇总 `evaluate.py` 的逐题 cases，再调用原 `metrics`；保留人工指标与老师一致率分报、observed-event macro 选优及原 best/final 规则，不能平均四卡 macro。首版无须改变 generate 协议或实施 packed 训练。

E5 可选 CPU 预转 BF16 见总方案 §8.8.1：本地视觉入口与 patch embedding 都有 cast，须确认实际 dtype 一致，在 processor/答案定位等原处理完成后仅转 `pixel_values`，再 pin/H2D；不改 IDs/grid/labels。四图指定分辨率下该张量从 40.5 MiB 减至 20.25 MiB，但 CPU/GPU 舍入、特征/loss/梯度、CPU 转换耗时和队列总内存都需验收。文件/像素校验结果缓存是 §8.8.2 的单列合同候选，默认关闭；inode/mtime 不可冒充 SHA。

当前人工 val 为 273 题、每题最多生成 8 token，E6 优先级取决于其在整轮中的实际占比；Phase3 历史生成清单为 binary 384/choice 320 题且输出/频率不同。E0 分 Phase 报验证总墙钟和各 rank 等待后再定先后，不为对称实施而预设 Phase4 验证同样是主要瓶颈。

E0 按总方案 §8.1 分别计时训练、规则老师回放/建库、完整评估和运行时问答。已核对 [model.generate](model.py) 与 [runtime](runtime.py) 都调用 `generate(max_new_tokens=8)`；拆分读图、processor、prefill、实际 decode、解析及控制器提交，记录每帧实际边数和整帧延迟。E3 的基准在此推理路径建立，不能只计训练 loss 前向；老师规则回放另列，不把规则耗时误记成解码耗时。

E1 直接使用本地 `logits_to_keep`；共同原理与精度门见总方案 §8.2/§8.5。当前 [train.py](train.py) 每次 encode/前向一个样本，通过 `model(**inputs, use_cache=False).loss` 使用内置损失，再以 `loss/accumulation_size` 反传。

实现时从 `model.encode` 的 labels 取全部非 ignored 答案及 `<|im_end|>` 位置 j，以 j-1 为投影位置；去掉传给模型的原全长 labels，显式计算已对齐交叉熵。按固定版本内置路径将选出 logits 转 FP32，以完整词表归一化、对该样本有效 token 求均值；之后沿用原样本累积大小、尾步与 DDP 行为，不能再 causal shift 一次，也不能改成跨样本 token 总数归一化。E4 的混长 batch 必须立即补齐逐行映射：`logits_to_keep` 只接受共用一维位置，按总方案 §8.2 选位置并集后逐行筛选，或 gather 最终隐藏状态后经 LM head。核对不同答案 token 数、行位置及样本分母；缩小词表或改变生成协议另列实验。

E2 的缓存选择以总方案 §8.1/§8.3 为准。虽然同锚点多边共享图片，但逐样本前向和路线分散采样不保证同一更新内命中；先测每 rank 步内/轮内/跨轮复用距离，再选 GPU/CPU/磁盘容量。冻结特征可跨步复用，语言训练前缀不可跨参数更新复用。v40 最大重复是历史七轮统计，不作 v42 收益承诺；不同锚点按帧身份求并集，缓存仍核验来源。

注意区分相邻两题和整批：Phase4 两个相邻锚点不共享，但四个连续锚点唯一图为 10 张，编码量比 16/10=1.6；间隔两帧的四锚点唯一图 7 张，才是 16/7≈2.29。线上逐帧热缓存若保留必要的两组奇偶历史，也可每次只编码新图；仅缓存上一窗口四图做不到。所有比值均依赖实际 E2 接入，批处理本身不自动视觉去重。

E4 按总方案 §8.6–§8.7：E4a 合并原每 rank 同一次更新的题；E4b 允许在同一次全局更新内重新分配四卡，保持原事件配额、每题全局权重和更新边界。batch 内先按行算 FP32 有效 token 均值，等量同权时以原 `accumulation_size` 缩放其和；一般情形按总方案的原全局损失系数还原。不能用整批 token CE 均值替代，不能把 batch 均值再除一次旧 accumulation。尾步、梯度裁剪及各 rank 同步对齐。原更新内按长度分组可以测试，跨更新凑同路线题属于 P2。

基础 E4 可用当前 masked batch；右 padding 作为训练专用布局，在完整答案后补 pad，生成入口保持原合同。左 padding 有真实 mask 时本地补丁会跳过 pad；右 pad 若仍传 mask 也会触发 ragged 逐行路径。省线性 mask 的快路径必须满足总方案的无缓存/无续写/有效位置因果约束，本地无独立公开开关，不可把整个 attention_mask 随意删除。先 dropout=0 验证行隔离、有效 logits/loss/梯度/更新，再处理默认 .05 的随机性和 GPU/FLA 性能。

ragged 路径在 24 层 DeltaNet 连投影也逐行执行，标准 E4 主要作为正确性基线，不能预设常规 batch 加速。新候选 E4c 按总方案 §8.6.1 打通 FLA `cu_seqlens`、卷积 `seq_idx`、变长因果注意力和每题 M-RoPE；YES/NO 与结束 token 的 j-1 映射必须留在各自段内。它需要本地 vendor/输入适配，当前视觉塔的分段参数不能代替语言边界；不支持边界的后端不得继续跑展平多题流。

按锁定版本进一步核对：FLA 变长物理 B=1、边界 dtype/device，卷积 channel-last 内存布局及 seq_idx 连续 int32，以及普通注意力 head_dim=256、GQA、BF16 的真实 H20 变长前反向。不能凭 Hopper 名称或仅一次前向通过放行；attention dropout 与 LoRA dropout 分开记录。全 1 mask 在上层退为 None，不把 ragged 开销计入当前无 padding 的 B=1。

E3 优先处理 `runtime` 同一时刻的多条边：共享完全相同的 system+图像 token 前缀，再分别追加状态/边文字。先复制可写缓存、得到全部答案，然后沿现有事务式状态提交处理，保持单帧原子性。不同状态或实例的答案不得流入其他分支前缀。

推理验收包括独立前向与共享前缀的有效 logits/原生成输出、分支排列不变性、不同 suffix 长度、多实例目标冲突、RoPE/mask、缓存复用后图像变化。跨帧的新输入需要新视觉/语言处理；不能把已滑出的图像仅从 KV 删掉而保留污染的循环状态。

训练前缀树单独进入总方案 R0/R1，尤其覆盖 FLA 初末态梯度、checkpointing 重算、分支复制、optimizer 更新后失效、显存峰值与 DDP。现有后缀梯度测试不是其替代品。

### 9.1 四张 H20 的 Phase4 实施决策

按总方案 §8.7 固定四个 DDP rank、每卡一个进程；主性能候选每卡 b=4、全局 microbatch=16，b=2 起验证、b=3 对照。当前默认每卡累计 8 题，四卡每更新 N=32，因此三档可直接保留原更新边界：

| 每卡 b | 每卡一次更新内的波次 | 各波 batch 均值的系数（等权完整更新） |
| --- | --- | --- |
| 2 | 2+2+2+2 | 1/4、1/4、1/4、1/4 |
| 3 | 3+3+2 | 3/8、3/8、2/8 |
| 4 | 4+4 | 1/2、1/2 |

表中先求每题的有效 token 均值，再求该波题均值，最后乘表内系数；或者直接将该波各题 loss 之和除以 8，二者等价。不能把波均值再除以旧 accumulation=8，不能把 3+3+2 当三等份。尾部不足 8 题按基线实际 `accumulation_size` 处理；跨 rank 重分配按原全局系数计算。预算 10240 题/轮、N=32 时仍为 320 次更新，不因改为 b=4 就把原 8 次逐题累积变成 8 个四题 batch。

K=32 是取数段探针，Phase4 同帧多边/多实例使 Q 可能大于 K；按真实 Q、token 长度及未缓存图像成本分配四卡，不能固定“32 帧必为 32 题”。逐帧段 s=1 保持，s=2 是另一个 P2c 采样臂，四图 offsets 都保留 `[-6,-4,-2,0]`。一个段可跨更新，完整更新仍尽量含多路线，图像缓存按 rank 本地维护；不要求模型语言状态沿段延续。

N=32 的推荐示例改为四路线各八个合格锚点小块、每锚点一题，每卡一块；各路线 K=32 的段跨多次更新排队。有多边/缺题时按 Q 和配额重算，四路线结构仅是 P2c 设计，不强改 E4 原题集。采样代码先产生绑定 world 的全局 plan/曝光历史，再按 `indices[rank::world]` 切片；E4b 新增的分配必须由冻结题集确定性产生，恢复时重放保存表或按保存成本模型重算验 hash，不按即时负载重新排。当前 epoch 边界恢复不等于已支持中途更新恢复。

本 Phase 当前 gradient checkpointing 开启，与 Phase3 分开测容量。两图/四图按原流水线分别训练，每个训练 run 都使用四卡；本方案不把两卡分给两图、另两卡分给四图，也不隐式联合两个 Phase。冷/热缓存、最长输入、首个 Adam 状态、四卡拖尾和 E1 混长索引都完成验收后才定 b；目标 H20 实测状态统一记录于总方案，不在此填写预计吞吐。

## 10. P4-P：采样与监督来源

日常 pipeline 以 `phase3_balanced` 为基准：每事件 1024，总 10240；实际策略以 run 元数据为准，不拿直接 `train.py` 推导的其他默认冒充日常配置。v42 已改为带主边权重和运动分层的内部 policy；以选定版本的全量池重新报告不同题、路线、边/答案和重复次数，不跨版本借统计。

第一轮工程实验固定原题集、权重、更新数、两图/四图配对身份，不附带额外题。之后附带题和邻近锚点分别做 P1/P2，按原入库规则过滤，不能给缺失分支生成想当然的答案。

P2 的主锚点仍由配额选择，P2a/P2b 最多带 1–3 个邻锚点作为待登记起点，用户指定的可配置连续段另做 P2c；两种方案都保持整更新多路线，邻题纳入事件曝光预算及原准入。不能断言连续锚点必然破坏事件总配额，但答案分布、每步路线数和相关性仍可能恶化。先 P2a 固定邻帧、再 P2b 边界优先，保留稳定段对照；P2c 的 K/s/Q 规则及 P5 更新预算以总方案 §12 为准。P3 全局桶归一化单测后才组合，不能用归一化声称恢复了样本独立性。报告实际权重、路线/事件数量、最大重复及 P0 开发对照。

增加标签来源维度：人工、弱老师、严格批准老师分别记录样本数和有效权重；弱题多不自动意味着应淹没人工信号。是否改变各来源权重必须作为新采样/目标实验，保持可复现。

全局按桶平均须处理 DDP 的平均系数、梯度累积、缺桶、尾部更新与全空监督。至少验证同一全局问题集合在 world=1/4 时的更新；仅比较题序一致还不证明梯度权重一致。

## 11. P4-V：人工评估、时序与真实运行

### 11.1 单题评估

人工参考与老师一致率继续分开。十事件全宏平均在有事件缺失时不报告成完整覆盖；已有四事件指标标明 observed scope。按边/分支/readiness/catchup、静止/运动、图像配置和物理路线支持分解。

报告 YES precision、NO→YES 假放行率、readiness recall、catchup recall、格式错、UNKNOWN 和覆盖。对不可判断样本，若系统采取保守等待，要单列“系统拒绝/等待”，不能把其算成视觉事实已判 NO。

严格批准门、理想样本下限及审核预算统一引用总方案 §7.3 和 [批准政策](teacher_approval.py)，本指南不另维护数字。路线聚类区间补充报告，不替换现有 Wilson 政策；开发验证、独立批准和最终 test 不混用。

### 11.2 连续状态评估

每个连续明确 YES 片段建立一个响应机会。第一次有效模型 YES、获得完整执行许可、确认动作执行分别计时；新 NO、实例更换、UNKNOWN/断档按预先冻结规则中断或删失。不能把无回执的实例算已完成。

分别报告：模型未响应、模型过早 YES、许可模块拒绝、执行迟迟未发生、相互矛盾的同轴答案、跨实例目标冲突、状态抖动和异常恢复。安全模块挡住错误不抹掉模型错误，合理安全拒绝也不算模型响应延迟。

至少覆盖：YES→NO→YES、readiness 后未执行、执行后旧状态补问、新冲突仅影响纵向、完成后同 ID 新实例、多参与者最后一人未通过、跨路段目标变化、可见删除、身份跳变、STOP 义务历史不足。

### 11.3 下游分层

先测 adapter 输入输出和 Action prior 接口，再测预测上下文驱动的离线状态序列，最后做 CARLA 真闭环。Phase3 标签/投影涉及 Action 时，先插入总方案 §13.1 的 oracle token 差异与离线 ADE/FDE 验证；它不能代替 Phase4 的状态时序和完整许可验收。固定录制图像上的自主状态更新仍是离线回放，不能称车辆在模型行动下通过了场景。

真实验收使用部署时可得的 Phase1/2 事件、目标和许可提供者；oracle 上下文只作上界对照。报告端到端延迟与截止错过，而不只测单题推理速度。

## 12. 合同、配对与发布边界

现有 [identity](identity.py) 绑定老师、控制器、训练/评估和部分 Phase3 依赖。修改依赖后按新合同构建新产物，不以复制旧 manifest 的方式兼容。input、老师、人工审核、配对语义和采样版本应分别可识别，便于定位变化来源。

既有两图/四图语义题配对不代表所有配置可观察性相同。新增 `[-6,0]` 模式需要重新核验共享图像、风险、人工标签有效性和配对分母；不把旧 rgb2 规则批准或审核结论自动迁移给新输入。

正式候选发布必须有完整目标覆盖、独立人工结果、运行时边界和 Action 行为证据。弱试训可继续保持其明确身份，不能因文档完成、全量回放或单测数量增多而将严格 registry 填为通过。
