# Phase4 v41：十事件自动弱老师

默认流水线现已接入 UE2、UE3、UE5、UE6、UE7、RE2、RE3、RE5，连同原 UE1/UE4，按通用规则扫描全部合格路线。不是把这 34 条开发路线固定成生产白名单。没有改 Phase3、人工标签或运行时 BEV 安全许可。

日常命令仍为：

```bash
bash qwen3vl_local/sft_new_loop_phase4/run.sh
```

自动新建匹配 v41 的题库，再按四图、两图顺序训练、测试、打包。默认保持 v40 的 Phase3 比例：每事件每轮 1024 次，共 10240 次；四卡累积 8 时，每卡 2560 次计算、320 次参数更新。题池扩大不会自动扩大每轮预算。

## 规则与接线

- UE2 用当前障碍物身份及规划路径建立绕行目标；保存改道前导航。当前路径可先于 changed_route 标志改变，不能逐帧覆盖原路径。原路径不足时不推断“不返回”。通过、返回和归位分别判断，原导航耗尽时删失实例。
- UE3 要求车辆确实移动，并进入固定世界坐标下的历史走廊；自车转弯、规划路径偏移和静态场景车不构成切入。
- UE5 检查对向朝向、走廊占据和连续身份，目标消失不会制造释放。
- UE6/RE5 检查局部横穿冲突及适用灯、STOP 义务；正常跟车不当作占道。自车道路/车道从 metas 读取，自车框缺少重复字段不再导致永久 UNKNOWN；字段冲突仍弃答。
- UE7 需要上游明确的故障场景身份，普通红灯不自动成为故障。解除故障灯义务仍须检查 STOP 和当前冲突。
- RE2 需要当前导航变道/路肩出发证据；RE3 需要活动汇入/驶出实例及当前目标路径。规划路径只指定目标，不证明目标间隙安全。
- 三态条件、图像质量、静态占据、因果来源 SHA 和局部不连续检查统一使用；纵向恢复、旧实例截止和离线观测状态同步接入真实 Episode。
- 离线记录中的已执行横移只同步回放状态，不产生许可或训练标签。运行时 depart/enter/return 仍须另有当帧规划器/BEV 安全许可。
- 弱注册表、横向可见范围入库和加载校验均接入新规则；新增监督只进 train。独立批准没有伪造，老师一致率仍与人工准确率分开。

1067 项专项测试通过。对 17 类场景的 34 条训练路线、3601 帧做了程序回放。新增八类主边均有真实规则 YES/NO；以下为两图原始老师提议，尚未经过风险窗口过滤，不是人工正确率。

真实两图和四图分别完成建库及加载验证：各 3071 条 train，其中 2628 条开发路线弱题、443 条原人工题；人工 val 273、test 186、待审 539 保持。3071 条训练题全部配对，没有因图数求交而丢题。world=1/4 各跑七轮采样，两模式每轮题序一致、每事件 1024 次。这里只验证开发题库，不能拿其重复率推断全量题库。

目视仅检查一张联系表中的五个当前帧，无完整序列、无独立 RGB、无新增人工标签。五个物理组均原属 train，已显式登记曝光；不能把程序读取 3601 帧称为逐帧目视。

## 尚未证明的覆盖

这次补齐的是八类事件的自动规则和入库链路，不等于每个分支都已获得足够真实监督。34 条开发路线没有 UE2 return 标签；返回规则的正例路径有合成测试，但真实返回覆盖须看全量重建结果。自动“不返回／本车道通过／骑行绕行”分支抽取仍未实现。UE5、UE7 的正例在本次探针中仍少，人工 val/test 仍只覆盖四事件，严格批准仍为空。

本机没有重新生产全量 v41 数据，也没有启动 GPU 训练、CARLA 或独立人工评测。上面的无参数命令会在实际运行环境按最终源码进行全路线生产。旧题库及 manifest 不改写；禁止把本次开发统计当作全量训练结果或准确率。
