# v42：事件身份、运动偏差和弯道跟车

这次对外部 v41 全量审计做代码复核、具名路线 RGB 筛查和程序回放。外部 7,268 条训练路线的统计未作为本机独立复现数字；本次验收范围和产量另存 `teacher_v42_verification_20261008.json`。

## 审计判断

- 确认 v41 新事件移动正例直接进入 readiness，默认采样缺少运动分层。移动正例本身并不必然错；问题是把起步后才首次成立的事实当作静止时可学到的释放证据。
- 确认 UE5 会把自车绕行路径内的正常对向车当侵入者，UE6 会把普通红灯排队中的横向通行车当优先权异常；确认普通跟车使用自车朝向及过窄闭合速度门槛。
- 对方关于 `InvadingTurn/3023_0` 的解释不完整：RGB 和 bbox 显示真实锥桶及对向车辆同时存在。锥桶 UE2 不能全部删掉，对向车也不能由 `scenario_obstacles_ids` 自动改称静态障碍。
- `CrossJunctionDefectTrafficLight/Town05_route_002071` 的连续画面显示同一路口内前移、等待和继续通过，不足以证明“两次穿过路口”。专家动作不能替代条件标签。
- 同意 return、分支完成和独立人工评估仍有缺口。目标被销毁不能直接当自然离开，未补造 UE4 complete 正例。

## 实现

1. 回放按实例、转移边保留最后一次静止二元条件及原始来源。静止 NO 后，首次在移动中满足的 proceed/depart/enter/return 记为 catchup 候选；事实 YES 保留用于状态回放，但监督为 UNKNOWN。尚未实现自动视觉后继证明，因此不把这些候选批准成 catchup YES。没有先前静止 NO 的移动条件正例不会一刀切删除；UE1 原有移动释放入库限制保持。
2. 对七个 YIELD 类事件应用“已观察停车后，连续实际前向行驶”截止旧等待实例；没有制造 YES、完成或运行时许可。横向 WAIT 不因单纯前进而结束，仍依赖实际车道进入证据。
3. UE5 使用原始／冻结的本车道几何；普通几何召回要求非路口范围、同道路同车道归属和对向足迹重叠，宁可漏掉不确定的部分压线。当前或此前已知 InvadingTurn 身份加当前场景参与者 ID、可见对向重叠，可检索侵入实例；场景目录名不是许可依据。原始道路不足时仍有召回限制。
4. UE6 需当前上游优先权异常身份和实际横穿冲突，普通红灯队列不再满足种子条件。UE3 保留局部因果切入几何，普通路口／汇入不因交叠自动成为切入；可使用当帧 cut-in actor IDs 检索。未引入控制量、保存的未来轨迹或语义未经确认的 `vehicle_cuts_in` 字段。
5. 普通前车按其位置的路线切线计算朝向、纵横向速度和间距，保留车道一致性、可见性、最小间距及闭合 TTC。新增 2 m/s 闭合上限、5 s TTC 是弱老师开发阈值，不是认证安全阈值。连续平行车辆沿当帧道路曲线预测；横移／换道证据不满足时仍检查通用冲突。
6. 默认仍每事件 1,024 次、每轮 10,240 次。部分池抽样恢复主要边权重 8、recover_follow 4、其他 1；缺 YES 或 NO 的边权重降为 1。边内按答案、readiness/catchup、静止/运动分层并按容量回流；有充足容量时可四格等额，缺格不伪造标签或无限重复。输出运动缺格、实际呈现和重复量，恢复历史绑定新策略。

## 运行和限制

合同 v42、老师 v10；同物理路线冻结划分，独立预约 v22 保留原预约，严格注册表 v17 仍空。旧 manifest 不改 hash。`run.sh` 检出新源码后自动在新目录重建全量配对题库，仍四图→两图；不要求用户填写路径或参数。

```bash
bash qwen3vl_local/sft_new_loop_phase4/run.sh
```

本次验证不等于全量 v42 产物已经验收或十事件驾驶闭环认证。人工 val/test 覆盖不足的六类事件只能报告老师一致率。冻结导航耗尽、真实 return／分支完成样本和独立人工误差仍需实测，不能靠这次测试通过声称解决。未启动 GPU 训练或 CARLA。

- 1,090 项专项测试通过。
